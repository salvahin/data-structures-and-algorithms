El patrón de dos punteros

Dos punteros

Dos índices que se acercan

  • Se usan dos variables que guardan posiciones: una empieza al principio del arreglo y la otra al final.
  • En cada vuelta se mira la pareja que forman y se decide cuál de las dos mover. Se acercan hasta encontrarse.
  • La ganancia: en lugar de probar todas las parejas, cada paso descarta varias de golpe. Hoy los dos problemas usan esta forma.

Hay otra variante, con los dos índices avanzando a distinta velocidad, que verás cuando lleguemos a listas ligadas.

Dos punteros · Cómo se mueve

Buscar dos valores que sumen 9

Dos punteros · Por qué es correcto

Por qué se puede descartar

Si la suma se pasa del objetivo, el número de la derecha es demasiado grande para cualquier pareja que quede, porque los de la izquierda son todavía menores.
  • Por eso, al mover ese índice hacia la izquierda, tiras muchas parejas de una vez sin revisarlas.
  • Esto solo vale si el arreglo está ordenado. Sin orden, que una suma se pase no dice nada de las demás.
  • Ningún índice retrocede, así que el recorrido termina y cada elemento se mira una sola vez.
Checkpoint

El arreglo llega sin ordenar y te piden dos posiciones cuyos valores sumen el objetivo. ¿Puedes usar dos índices que se acercan?

B. Todo el patrón se apoya en que a la izquierda hay números menores. Sin esa garantía, mover un índice puede tirar justo la pareja correcta. Ese caso se resuelve con otro patrón de la lista, la tabla hash, y lo veremos más adelante en el curso.

Problema 1
Pares que suman un objetivo

20 minutos · lo programas tú · LC 167

Problema 1 · Enunciado

Dos números que sumen el objetivo

  • Recibes un arreglo de enteros ordenado de menor a mayor y un valor objetivo.
  • Devuelve las posiciones de los dos elementos que suman exactamente el objetivo, con índices que empiezan en 1.
  • Se garantiza a lo más una respuesta, y no puedes usar el mismo elemento dos veces.
  • Si no hay pareja, devuelve un vector vacío.

// El contrato que van a probar los casos:
std::vector<int> dosSuma(std::vector<int> v, int objetivo);
Problema 1 · Antes de teclear

Contesta esto antes de abrir el editor

  • ¿Dónde arrancan los punteros? Uno en la primera posición y otro en la última, con un tipo que permita restar sin sorpresas.
  • ¿i < j o i <= j? Uno de los dos deja usar el mismo elemento dos veces.
  • ¿Qué haces en cada caso? Suma mayor, menor o igual al objetivo: tres ramas, y en cada una decides qué puntero mover.
  • ¿Qué devuelves? Índices basados en 1, no en 0. Es el error más común de este problema.
Problema 1 · Casos de prueba

Con estos casos verificas tu solución

  • Camino feliz. Arreglo 2, 7, 11, 15 con objetivo 9 → posiciones 1 y 2.
  • La pareja está en los extremos. Arreglo 1, 2, 3, 9 con objetivo 10 → posiciones 1 y 4. Falla si mueves un puntero antes de comparar.
  • La pareja está al centro. Arreglo 1, 3, 4, 8 con objetivo 7 → posiciones 2 y 3. Obliga a que ambos punteros se muevan.
  • Mínimo posible. Arreglo 3, 3 con objetivo 6 → posiciones 1 y 2. Dos elementos iguales y solo una vuelta de ciclo.
Problema 1 · Casos de prueba

Los que de verdad rompen soluciones

  • Negativos. Arreglo −5, −2, 0, 4 con objetivo −7 → posiciones 1 y 2. Falla si supusiste que los valores son positivos.
  • Sin respuesta. Arreglo 1, 2, 4 con objetivo 100 → vector vacío. Verifica que el ciclo termina en vez de salirse del arreglo.
  • Solo se lograría repitiendo un elemento. Arreglo 1, 5, 8 con objetivo 10 → vector vacío. El 5 sumado consigo mismo daría 10, y eso no se vale. Aquí se cae quien escribió i <= j.

Si falla uno, el nombre del caso te dice dónde mirar.

Antes del palíndromo:
strings en C++

Recordatorio · std::string

Una cadena se recorre como un arreglo


std::string s = "Anita";
s.size();            // 5 — cuántos caracteres
s[0];                // 'A' — un char, no una cadena
s.back();            // 'a' — último carácter

s == "Anita";        // compara contenido, no direcciones
s.substr(1, 3);      // "nit" — desde la posición 1, tres caracteres
s += "!";            // concatena al final
  • Las comillas dobles arman una cadena; las simples, un solo carácter. s[0] == 'A' compila, s[0] == "A" no.
Recordatorio · std::string

Mayúsculas y dígitos


#include <cctype>
std::isalnum(c);     // ¿es letra o dígito? útil para saltar espacios y signos
std::tolower(c);     // 'A' → 'a'; los dígitos y símbolos quedan igual

int n = s.size();    // cuántos caracteres tiene
int j = n - 1;       // la última posición: las posiciones van de 0 a n-1
  • Guarda el tamaño en un int antes de restarle 1. Es una costumbre que evita un error raro cuando la cadena viene vacía.
Checkpoint

Quieres comparar el primer carácter con el último. ¿Qué posición ocupa el último en una cadena de tamaño n?

B. Las posiciones van de 0 a n - 1. Leer la posición n se sale de la cadena, y ese es el error que hace que un palíndromo funcione con unas entradas y truene con otras.

Problema 2
Palíndromo válido

18 minutos · lo programas tú · LC 125

Problema 2 · Enunciado

¿La cadena se lee igual al derecho y al revés?

  • Recibes una cadena que puede traer espacios, signos y mayúsculas.
  • Considera solo letras y dígitos, tratando mayúsculas y minúsculas como iguales.
  • Devuelve verdadero si lo que queda se lee igual en ambos sentidos.
  • La cadena vacía cuenta como palíndromo.

bool esPalindromo(std::string s);
Problema 2 · Antes de teclear

El mismo patrón, con dos cuidados extra

  • Los punteros arrancan en los extremos y se acercan mientras i < j. Hasta aquí es idéntico al problema anterior.
  • Antes de comparar hay que saltar basura. Adelanta i mientras no apunte a algo alfanumérico y retrocede j igual. Esos saltos van dentro de ciclos propios.
  • Cuidado con salirte. Cada ciclo de salto necesita también la condición i < j: una cadena de puros signos los haría cruzarse.
  • Compara en minúsculas. Si difieren, ya puedes responder que no; si coinciden, mueve los dos punteros.
Problema 2 · Casos de prueba

Con estos casos verificas tu solución

  • Camino feliz con ruido. "A man, a plan, a canal: Panama" → verdadero. Mezcla comas, espacios, dos puntos y mayúsculas.
  • Negativo claro. "race a car" → falso. La diferencia aparece a media cadena.
  • Mínimos. "aa" → verdadero y "ab" → falso. Dos caracteres, una sola comparación.
  • Impar con centro. "aba" → verdadero. Verifica que el carácter de en medio no se compara consigo mismo de más.
Problema 2 · Casos de prueba

Los que de verdad rompen soluciones

  • Cadena vacía. "" → verdadero. El ciclo no debe entrar ni una vez.
  • Un solo espacio. " " → verdadero. Los saltos de basura tienen que frenarse antes de salirse del rango.
  • Pura puntuación. ".,!" → verdadero. Los dos punteros se cruzan sin comparar nada.
  • Letra contra dígito. "0P" → falso. Comprueba que estás comparando los caracteres y no haciendo cuentas con ellos.
  • Dígitos. "12321" → verdadero y "12345" → falso. Confirma que los números también cuentan como alfanuméricos.
Taller 1 · Cierre

Cuándo aplica y cuándo no

  • Aplica cuando el arreglo está ordenado, o cuando el problema compara los extremos, como el palíndromo.
  • No aplica si los datos están desordenados: ahí mover un índice puede tirar la respuesta correcta.
  • Antes de teclear, di en voz alta por qué es seguro mover cada índice. Si no puedes, todavía no es momento de programar.
