R6 · Punto de partida

El compromiso: cero cout

  • Un cout de diagnóstico obliga a recompilar cada vez que quieres ver otra variable, y hay que borrarlo después.
  • Solo muestra lo que se te ocurrió imprimir. Si el error está en una variable que no imprimiste, el ciclo empieza otra vez.
  • El depurador congela el programa en cualquier línea y te deja inspeccionar todo el estado: variables locales, parámetros, el arreglo completo y quién llamó a quién.
Vamos a encontrar el error de suma.cpp con el depurador y sin modificar el archivo.
R6 · La bandera -g

El breakpoint hueco y gris


# sin simbolos: el punto rojo se vuelve un circulo gris hueco
g++ -std=c++17 suma.cpp -o suma

# con simbolos: el punto rojo engancha
g++ -std=c++17 -Wall -Wextra -g suma.cpp -o suma

Al lanzar la sesión, VS Code descolora el breakpoint y muestra el aviso “the breakpoint address could not be obtained”. El ejecutable no contiene la tabla que asocia cada instrucción de máquina con su línea de código.

-g agrega esa tabla y los nombres de las variables. Sin ella, los símbolos de depuración no existen y el depurador no tiene dónde detenerse.

R6 · launch.json

La configuración de arranque: macOS


{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Depurar (macOS, CodeLLDB)",
      "type": "lldb",
      "request": "launch",
      "program": "${workspaceFolder}/programa",
      "cwd": "${workspaceFolder}",
      "preLaunchTask": "compilar"
    }
  ]
}

En macOS se usa la extensión CodeLLDB ("type": "lldb"), que envuelve al depurador del sistema.

R6 · launch.json

Linux, WSL y la tarea previa


{
  "name": "Depurar (Linux/WSL)",
  "type": "cppdbg",
  "request": "launch",
  "program": "${workspaceFolder}/programa",
  "MIMode": "gdb",
  "externalConsole": false,
  "preLaunchTask": "compilar"
}
          

{
  "label": "compilar",
  "type": "shell",
  "command": "g++",
  "args": ["-std=c++17", "-Wall",
           "-Wextra", "-g",
           "main.cpp", "-o", "programa"]
}

preLaunchTask ejecuta la tarea compilar antes de lanzar, así que nunca depuras un binario viejo.

Checkpoint

Pones un breakpoint, presionas F5 y el punto se vuelve un círculo gris hueco. ¿Qué revisas primero?

B. El círculo hueco significa que el depurador no pudo traducir esa línea a una dirección del ejecutable, y eso pasa cuando faltan los símbolos de -g. Guardar el archivo (A) no cambia el binario ya generado. Un breakpoint en línea en blanco (C) VS Code lo mueve solo a la siguiente línea ejecutable en vez de desactivarlo.
R6 · Los cuatro movimientos

Cuatro teclas y nada más

TeclaNombreQué hace
F5ContinuarCorre hasta el siguiente breakpoint o hasta el final
F10Step overEjecuta la línea completa; si hay una llamada, la corre entera
F11Step intoEntra al cuerpo de la función que se llama en esa línea
Shift+F11Step outTermina la función actual y regresa a quien la llamó

Con F10 recorres la lógica de una función. Con F11 bajas un nivel. Con Shift+F11 subes uno.

R6 · Los cuatro movimientos

La diferencia entre F10 y F11


#include <iostream>
const int N = 8;
int sumar(const int datos[], int n) {
    int total = 0;
    for (int i = 1; i < n; i++) total += datos[i];
    return total;
}
int main() {
    int datos[N] = {3, 1, 4, 1, 5, 9, 2, 6};
    std::cout << "Suma: " << sumar(datos, N) << '\n';
}

F10 en la línea 10 ejecuta sumar completa; F11 entra en la línea 4, con datos, n y total a la vista.

R6 · Variables y seguimiento

Ver el estado sin imprimirlo

  • El panel Variables lista los parámetros y las locales del punto donde estás detenido. Se actualizan solas en cada paso.
  • Los arreglos se despliegan elemento por elemento, así que puedes revisar datos[0] hasta datos[7] sin escribir nada.
  • El panel Watch evalúa expresiones, no solo nombres.

Watch
  i              1
  total          0
  datos[i]       1
  total + datos[i]   1
Checkpoint

Estás detenido en std::cout << sumar(datos, N); y quieres ver el valor de total en la primera vuelta del ciclo. ¿Qué tecla usas?

C. total es local de sumar, así que hay que estar dentro de esa función para verla. F10 ejecutaría la llamada completa y te perderías el ciclo. Shift+F11 sale de la función actual hacia quien la llamó, es decir, en dirección contraria.
R6 · Pila de llamadas

Una recursión para ver la pila


#include <iostream>

long long factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

int main() {
    std::cout << factorial(5) << '\n';
}

Pon el breakpoint en la línea 4 y presiona F5 cinco veces. Cada llamada suspendida se apila y el panel Call Stack crece.

R6 · Pila de llamadas

Qué dice el panel Call Stack


CALL STACK

  factorial(int)  n = 2   factorial.cpp:5
  factorial(int)  n = 3   factorial.cpp:5
  factorial(int)  n = 4   factorial.cpp:5

  • Se lee de arriba hacia abajo: el marco superior es donde estás; los de abajo son las llamadas que siguen esperando su resultado.
  • Al hacer clic en cualquier marco, el panel Variables cambia a las locales de esa llamada. Cada nivel tiene su propia n.
R6 · Breakpoints condicionales

Detenerse en la vuelta 47 de mil


int main() {
    long long acum = 0;
    for (int i = 0; i < 1000; i++) {
        acum += i * i;      // breakpoint condicional aqui
    }
}
  • Clic derecho sobre el punto rojo, Edit Breakpoint, y en Expression escribes i == 47.
  • Se detiene una sola vez, con i valiendo 47.
  • El mismo menú ofrece Hit Count, que se detiene en la enésima vez que pasa por la línea.
Checkpoint

Un ciclo de 5000 vueltas falla cerca del final. Pones un breakpoint normal y presionas F5. ¿Qué pasa?

A. Un breakpoint sin condición detiene el programa cada vez que la ejecución pasa por esa línea. No se consume (B) ni observa cambios de variables (C); esa última idea corresponde a los data breakpoints, que son otra herramienta. Para llegar a la vuelta 4900 se usa una expresión como i == 4900 o un Hit Count.
R6 · Logpoints

Imprimir sin tocar el código fuente

  • Clic derecho en el margen, Add Logpoint, y escribes un mensaje con expresiones entre llaves. Eso crea un logpoint.

Logpoint en suma.cpp:7
  vuelta i={i}  total={total}  datos[i]={datos[i]}

DEBUG CONSOLE
  vuelta i=1  total=0  datos[i]=1
  vuelta i=2  total=1  datos[i]=4
  • El programa sigue corriendo; la línea va a la consola.
  • No se recompila nada y el .cpp queda intacto.
R6 · El error del arranque

Un minuto con el depurador

  1. F11 en la línea 10 para entrar a sumar.
  2. i y total al panel Watch.
  3. Primer F10 dentro del ciclo: i vale 1, no 0. El primer elemento nunca se suma.

    int total = 0;
    for (int i = 0; i < n; i++)      // antes: i = 1
        total += datos[i];

28 más datos[0], que vale 3, da 31. El síntoma numérico y la causa quedan conectados sin haber recompilado ni una vez para investigar.

Checkpoint

Lanzas la sesión, el programa se detiene resaltando una línea en amarillo y aparece la barra de control. ¿Qué ocurrió?

B. El resaltado amarillo marca la línea que está a punto de ejecutarse, con el proceso vivo y congelado. Una falla real se anuncia con un mensaje de señal en la consola de depuración, del tipo EXC_BAD_ACCESS o SIGSEGV (A). Si el programa hubiera terminado, la barra de control desaparecería (C).
R6 · Trampas comunes

Tres formas de pelearse con el depurador

  • Depurar un binario viejo. Editas el .cpp, lanzas la sesión y el depurador salta líneas o se detiene donde ya no hay nada. Con preLaunchTask configurado esto deja de ocurrir.
  • La consola que se cierra. Con "externalConsole": true se abre una ventana aparte que desaparece al terminar el programa. La terminal integrada de VS Code conserva la salida.
  • Confundir la detención con la falla. Detenerse en un breakpoint es el comportamiento normal. Un fallo real imprime una señal en la consola de depuración y deja la pila de llamadas en el punto del accidente.

Tres funciones, un error cada una

Cópialas a tres archivos, compílalas con -g y localiza cada error solo con el depurador.


int suma(const int v[], int n) { // A
    int s = 0;
    for (int i = 0; i <= n; i++)
        s += v[i];
    return s;
}
int pares(const int v[], int n) { // B
    int c = 0;
    for (int i = 0; i < n; i++)
        if (v[i] % 2 != 0) c++;
    return c;
}
          

int maximo(const int v[], int n) { // C
    int mejor;
    for (int i = 0; i < n; i++)
        if (v[i] > mejor)
            mejor = v[i];
    return mejor;

R6 · Ejercicio

Los tres errores, uno por uno


// A: Watch sobre i y n. En la ultima vuelta i == n y se
//    lee v[n], fuera del arreglo.
for (int i = 0; i < n; i++) s += v[i];

// B: logpoint "i={i} v[i]={v[i]} c={c}". Cuenta impares.
if (v[i] % 2 == 0) c++;

// C: el panel Variables muestra 'mejor' con basura antes
//    de la primera vuelta.
int mejor = v[0];
for (int i = 1; i < n; i++)
    if (v[i] > mejor) mejor = v[i];

En A y en C el depurador enseña el valor incorrecto antes de que el programa produzca salida. En B todo se ve normal, y ahí el logpoint dentro del if es lo que delata la condición invertida.
