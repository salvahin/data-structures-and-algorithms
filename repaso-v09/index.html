R9 · Punto de partida

Un estudiante de menos cinco años


struct Estudiante {
    std::string nombre;
    int edad;
    double promedio;
};

int main() {
    Estudiante e{"Ana", 20, 92.5};
    e.edad = -5;
    e.promedio = 140.0;
    std::cout << e.nombre << ": " << e.edad
              << " anios, promedio " << e.promedio << '\n';
}
      

$ g++ -std=c++17 -Wall -Wextra estudiante.cpp -o est && ./est
Ana: -5 anios, promedio 140
R9 · Diagnóstico

Nadie está encargado de la regla

  • El compilador verifica tipos: -5 es un int perfectamente válido y 140.0 es un double válido. No hay nada que objetar.
  • Las reglas “la edad va de 15 a 99” y “el promedio va de 0 a 100” existen en la cabeza de quien escribió el struct y en ninguna línea del programa.
  • Con los campos públicos, cualquier línea de cualquier archivo puede escribirlos. Cuando aparece un promedio de 140, el sospechoso es el programa completo.
La pregunta no es cómo evitar esa línea, sino dónde debería vivir la regla para que la línea no pueda escribirse.
Checkpoint

En un programa de 2000 líneas, un Estudiante aparece con promedio 140. Los campos son públicos. ¿Dónde buscas el error?

B. Con campos públicos, escribir en promedio es legal desde cualquier punto del programa, así que el conjunto de sospechosos es toda escritura sobre ese campo. La declaración del tipo (A) solo fija que es un double. El compilador (C) no conoce el rango válido: nadie se lo dijo.
R9 · Cerrar el acceso

Reducir los sospechosos a uno


class Estudiante {
public:
    // aqui iran los metodos
private:
    std::string nombre = "sin nombre";
    int edad = 18;
    double promedio = 0.0;
};

int main() {
    Estudiante a;
    a.edad = -5;   // error: 'int Estudiante::edad' is private
}
  • Con private, el único código que puede escribir en edad son los métodos de la propia clase. El compilador rechaza lo demás.
  • La búsqueda del promedio de 140 pasa de 2000 líneas a las pocas que forman la clase.
R9 · Cerrar el acceso

La puerta con un guardia


class Estudiante {
public:
    bool asignarEdad(int e) {
        if (e < 15 || e > 99) return false;
        edad = e;
        return true;
    }
    int obtenerEdad() const { return edad; }
private:
    std::string nombre = "sin nombre";
    int edad = 18;
    double promedio = 0.0;
};
  • El método revisa el rango antes de tocar el campo y devuelve false cuando el valor no sirve. El objeto nunca queda en un estado imposible.
  • const al final de obtenerEdad promete que el método no modifica el objeto. El compilador lo verifica.
R9 · Cerrar el acceso

El estado inválido deja de ser alcanzable


Estudiante a;
std::cout << a.asignarEdad(-5) << ' '
          << a.obtenerEdad() << '\n';    // 0 18
std::cout << a.asignarEdad(20) << ' '
          << a.obtenerEdad() << '\n';    // 1 20
  • La asignación inválida se rechaza y el objeto conserva el valor que tenía. Quien llama recibe un false y decide qué hacer.
  • Los valores escritos junto a cada campo privado son inicializadores por omisión: el objeto nace válido, antes de que nadie lo toque.
  • En R10 esa inicialización pasa al constructor, que además permite exigir los datos al crear el objeto.
Checkpoint

¿Qué garantiza declarar edad como private?

A. private es una regla de acceso que el compilador aplica al código fuente: limita quién puede nombrar el miembro. Para impedir cambios después de la construcción se usa const (B). No hay ninguna protección en tiempo de ejecución: el depurador muestra los campos privados igual que los públicos (C).
R9 · struct y class

La única diferencia


struct A { int x = 1; };   // miembros publicos por omision
class  B { int x = 1; };   // miembros privados por omision

int main() {
    A a;  std::cout << a.x;   // compila
    B b;  std::cout << b.x;   // error: 'int B::x' is private
}
  • Un struct puede tener métodos, campos privados, constructores y herencia. Un class puede tener todo público. Lo único que cambia es el acceso por omisión.
  • La convención del curso: struct para agrupaciones de datos sin reglas, class cuando hay algo que proteger.
R9 · Abstracción

Decidir qué se expone


class Termostato {
public:
    void subir()      { if (grados < 30) grados++; }
    void bajar()      { if (grados > 15) grados--; }
    int  leer() const { return grados; }
private:
    int grados = 21;
};
  • La abstracción es la decisión de qué operaciones ofrece el tipo. Aquí son tres verbos del problema: subir, bajar, leer.
  • Quien usa Termostato no necesita saber que la temperatura se guarda en un int en grados enteros. Ese detalle puede cambiar a double sin tocar el código que lo usa.
  • La parte pública es el vocabulario con el que se habla del objeto. Lo que quede fuera de ella no existe para el resto del programa.
Checkpoint

¿Cuál es la diferencia entre struct y class en C++?

C. Es la única diferencia del lenguaje, junto con el acceso por omisión en la herencia. A describe el struct de C, no el de C++, donde puede tener métodos y constructores. B es falso: los dos se copian igual, según cómo se declare el parámetro o la variable.
R9 · Encapsulamiento

Proteger los invariantes

  • Un invariante es una condición sobre los datos del objeto que se cumple siempre, desde que el objeto existe hasta que se destruye.
  • Invariantes de Estudiante: la edad está entre 15 y 99; el promedio está entre 0 y 100; el nombre no está vacío.
  • Invariante de Termostato: grados está entre 15 y 30. subir y bajar lo respetan en el tope, así que llamar a subir veinte veces deja 30.
  • El encapsulamiento es cerrar el acceso directo a los datos para que toda modificación pase por código que preserva esos invariantes.
R9 · Encapsulamiento

Getters y setters para todo


class Estudiante {
public:
    void setEdad(int e)        { edad = e; }
    int  getEdad() const       { return edad; }
    void setPromedio(double p) { promedio = p; }
    double getPromedio() const { return promedio; }
private:
    int edad;
    double promedio;
};
  • Un setter sin validación deja pasar exactamente los mismos valores que el campo público. e.setEdad(-5) funciona igual que e.edad = -5.
  • Cada par de métodos que no filtra nada agrega líneas y no agrega garantías.
  • El criterio es al revés: primero se escriben los invariantes, y solo entonces se decide qué operaciones se ofrecen para modificar el objeto sin romperlos.
Checkpoint

Una clase tiene todos sus campos privados y un par de get/set sin validación para cada uno. ¿Qué protege?

B. El único beneficio que queda es de mantenimiento: si mañana edad se guarda como fecha de nacimiento, el cambio se limita al cuerpo de los métodos. Los invariantes siguen sin custodia, porque el setter acepta cualquier valor del tipo (A). Los campos privados se ven igual en el depurador (C): private es una regla de compilación.
R9 · Trampas comunes

Cuatro descuidos frecuentes

  • Escribir getters y setters para cada campo y dar por hecho que la clase ya encapsula.
  • Devolver una referencia no constante a un campo privado. int& getEdad() { return edad; } permite escribir obj.getEdad() = -5; y anula la validación.
  • Olvidar const en los métodos de consulta. Un objeto declarado const no podrá llamarlos.
  • Abrir un class y escribir los métodos antes de cualquier especificador. Quedan privados y el código que usa la clase no compila.
R9 · Ejercicio

Tres invariantes que hay que sostener


struct Reserva {
    std::string sala;   // invariante 1: no vacia
    int personas;       // invariante 2: entre 1 y 20
    int horaInicio;     // invariante 3: 0 <= inicio < fin <= 23
    int horaFin;
};

Conviértelo en clase e impide cada violación. El tercer invariante relaciona dos campos, así que no puede sostenerse con un setter por campo.


class Reserva {
public:
    bool asignarPersonas(int p) {
        if (p < 1 || p > 20) return false;
        personas = p; return true;
    }
    bool asignarHorario(int ini, int fin) {   // los dos juntos
        if (ini < 0 || fin > 23 || ini >= fin) return false;
        horaInicio = ini; horaFin = fin; return true;
    }
private:
    std::string sala = "A1";
    int personas = 1;
    int horaInicio = 8, horaFin = 9;
};

asignarSala sigue el mismo patrón: rechaza la cadena vacía con s.empty() antes de escribir. Con asignarInicio y asignarFin por separado el objeto pasaría por un estado con inicio >= fin entre las dos llamadas; un solo método que recibe el par revisa la condición completa antes de escribir cualquiera de los dos campos.
