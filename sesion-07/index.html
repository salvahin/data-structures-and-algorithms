El problema del ordenamiento

Ordenamiento · El problema

Qué pedimos exactamente

  • Entrada: una secuencia de n elementos y un criterio de comparación.
  • Salida: una permutación de la misma secuencia donde a[0] ≤ a[1] ≤ … ≤ a[n−1] según ese criterio.
  • El criterio lo define un comparador: para enteros es <, para structs lo escribes tú (por promedio, por fecha, por prioridad).
  • Todos los algoritmos de esta semana solo usan dos primitivas sobre los datos: comparar dos elementos y moverlos. Contaremos ambas por separado.
Ordenamiento · El problema

Dos propiedades para clasificar algoritmos

  • Estable: los elementos con clave igual conservan su orden relativo original. Importa al encadenar criterios: ordenar por grupo una lista ya ordenada por nombre deja cada grupo alfabético solo si el algoritmo es estable.
  • En sitio: usa O(1) memoria adicional; reordena dentro del propio arreglo.

5.1 Bubble Sort

5.1 · Bubble Sort

El algoritmo: comparar vecinos, intercambiar


void bubbleSort(std::vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {          // n-1 pasadas
        for (int j = 0; j < n - 1 - i; ++j) {  // zona no ordenada
            if (a[j] > a[j + 1])
                std::swap(a[j], a[j + 1]);
        }
    }
}
  • Cada pasada empuja el mayor elemento restante hasta el final de la zona no ordenada.
  • Por eso el límite interno es n - 1 - i: los últimos i elementos ya quedaron en su lugar.
5.1 · Bubble Sort

Una pasada, paso a paso

5.1 · Bubble Sort

La optimización: detectar que ya terminaste


void bubbleSort(std::vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {
        bool hubo = false;                  // ¿esta pasada intercambió algo?
        for (int j = 0; j < n - 1 - i; ++j) {
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
                hubo = true;
            }
        }
        if (!hubo) break;   // pasada limpia: el arreglo ya está ordenado
    }
}

Una pasada sin intercambios demuestra que cada par de vecinos está en orden — y eso implica que todo el arreglo lo está.

5.1 · Bubble Sort

Conteo exacto

CasoComparacionesIntercambios
Peor (entrada inversa)n(n−1)/2n(n−1)/2
Mejor, con bandera (ya ordenada)n−10
Mejor, sin banderan(n−1)/20
  • Cada intercambio corrige exactamente una inversión (un par fuera de orden): el total de intercambios es igual al número de inversiones de la entrada.
  • Con la bandera, el mejor caso baja a O(n); sin ella, las pasadas se ejecutan completas aunque no haya nada que hacer.
Checkpoint

Bubble Sort con bandera recibe un arreglo ya ordenado de n elementos. ¿Cuánto trabajo hace?

B. La bandera convierte el mejor caso en O(n): una sola pasada de verificación. La opción A describe la versión sin bandera. La C es imposible para cualquier algoritmo de comparación: verificar que un arreglo está ordenado ya cuesta n−1 comparaciones.

5.2 Selection Sort

5.2 · Selection Sort

El algoritmo: buscar el mínimo, colocarlo


void selectionSort(std::vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {
        int m = i;                          // índice del mínimo
        for (int j = i + 1; j < n; ++j)
            if (a[j] < a[m]) m = j;
        if (m != i) std::swap(a[i], a[m]);  // un intercambio por pasada
    }
}
  • La pasada i busca el mínimo de la zona no ordenada y lo coloca en la posición i.
  • Busca mucho, mueve poco: n−1−i comparaciones por pasada y a lo más un intercambio.

  • Las comparaciones no dependen de la entrada: el ciclo interno recorre la zona no ordenada completa siempre, haya o no algo que corregir. Por eso Θ(n²) es cota exacta, en todos los casos.
  • A cambio, hace a lo más n−1 intercambios en total — Bubble puede hacer n(n−1)/2.
5.2 · Selection Sort

Cuándo importa la asimetría

Comparar suele ser barato (leer dos claves); mover puede ser caro:

  • Registros grandes: si cada elemento pesa megabytes, cada intercambio copia megabytes.
  • Escrituras costosas o limitadas: memoria flash/EEPROM, donde cada escritura desgasta el medio.

En esos escenarios, Selection Sort con sus O(n) intercambios puede ganarle a algoritmos con menos comparaciones.

Nota: Selection Sort no es estable — el intercambio puede saltar por encima de un elemento con clave igual.

Checkpoint

Selection Sort recibe un arreglo ya ordenado. ¿Cuántas comparaciones hace?

C. Selection Sort no tiene forma de "darse cuenta" del orden: para afirmar que a[i] es el mínimo de la zona no ordenada debe compararlo contra todos los demás, siempre. Sus comparaciones son una constante de la talla n, no de la entrada — esa es su firma característica, y la verán en los contadores del experimento.

  • Repetir cada medición y quedarse con la mediana: la primera corrida paga costos de caché que las demás no.

Checkpoint

Cada elemento de tu arreglo pesa 1 MB y copiarlo es la operación cara. ¿Cuál de los dos algoritmos de hoy conviene y por qué?

A. Cuando mover domina el costo, el criterio es el número de movimientos: Selection garantiza O(n) intercambios contra los O(n²) posibles de Bubble. La opción B solo aplica si la entrada ya viene casi ordenada. La C ignora que O(n²) cuenta comparaciones — con elementos de 1 MB, las operaciones no cuestan lo mismo y la constante manda.

std::swap y la semántica de movimiento


std::vector<int> a(1'000'000), b(1'000'000);
std::swap(a, b);   // O(1): intercambia punteros, no copia elementos

// desde C++11, swap se implementa con movimiento:
// tmp = std::move(a); a = std::move(b); b = std::move(tmp);
// mover un vector transfiere su buffer; no toca los datos
  • Con la semántica de movimiento, intercambiar contenedores cuesta O(1) aunque contengan millones de elementos.
  • Para tus propios tipos: si el struct guarda sus datos en contenedores estándar, std::swap ya es barato sin trabajo extra.
STL

Comparadores personalizados con lambdas


std::sort(v.begin(), v.end(),
          [](const Alumno& a, const Alumno& b) {
              return a.promedio > b.promedio;   // descendente
          });
  • El comparador debe cumplir strict weak ordering: en particular, comp(x, x) debe ser falso.
  • Escribir >= en lugar de > lo viola — y el resultado es comportamiento indefinido: std::sort puede leer fuera de rango y tronar, no reportar un error.
  • Regla práctica: el comparador responde "¿va estrictamente antes?", nunca "¿puede ir antes o igual?".
