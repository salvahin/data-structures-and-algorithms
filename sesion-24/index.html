8.3.1 El TDA conjunto

8.3.1 · El TDA conjunto

Especificación del conjunto

Un conjunto es una colección sin elementos repetidos. Sus operaciones:

  • Sobre un conjunto: agrega(x), elimina(x), pertenece(x). La pertenencia es la más usada: casi todo uso real pregunta "¿ya vi esto?".
  • Entre conjuntos: unión \(A \cup B\), intersección \(A \cap B\), diferencia \(A - B\).
  • El invariante (sin repetidos) es el mismo en todas las implementaciones. Lo que cambia es cuánto cuesta cada operación.

Checkpoint

Quieres intersecar dos conjuntos en tablas hash, de tamaños n y m con n < m. ¿Cómo lo haces eficiente?

B. Cada consulta de pertenencia cuesta O(1) promedio sin importar el tamaño del conjunto consultado, así que el costo total lo fija el conjunto que recorres. Recorrer el chico da O(n); recorrer el grande, O(m). Con n = 100 y m = 10 millones, recorrer el chico hace cien mil veces menos consultas.

8.3.2 Técnica de hashing

8.3.2 · La idea

Calcular la casilla en lugar de buscarla

8.3.2 · Función hash

De la clave al índice

La regla que convierte una clave en un número de casilla se llama función hash. Con m casillas, devuelve un número entre 0 y \(m - 1\). Necesita tres propiedades:

  • Determinista: la misma clave produce siempre la misma casilla. Si no, lo que se guardó no se vuelve a encontrar.
  • Uniforme: reparte las claves entre las casillas, incluso cuando las claves se parecen entre sí.
  • Rápida: se calcula en cada operación. Si cuesta más que la búsqueda que evita, no sirve.

A las casillas de una tabla hash también se les llama cubetas.

8.3.2 · Función hash

Enteros: el método de la división

\[ h(k) = k \bmod m \]
  • \(k \bmod m\) es el residuo de dividir \(k\) entre \(m\). En C++ se escribe k % m.
  • Ejemplo con \(m = 7\): \(\;31 = 4 \cdot 7 + 3\), así que \(h(31) = 3\).
  • El residuo siempre queda entre 0 y \(m - 1\), así que la casilla siempre existe. Esto vale para \(k \ge 0\); en C++ el residuo de un negativo es negativo, y por eso las tablas de hoy piden claves no negativas.
8.3.2 · Función hash

Elegir m: por qué conviene un primo

Las claves reales tienen patrones. Estas cinco son múltiplos de 10:

\(k\)2030405060
\(k \bmod 10\)00000
\(k \bmod 7\)62514
  • Con \(m = 10\) el residuo es el último dígito, y las cinco claves caen en la casilla 0. Si las claves comparten un factor con \(m\), solo usan algunas casillas.
  • Un primo solo comparte factores con sus propios múltiplos, así que claves con patrones como "múltiplos de 10" o "pares" se reparten entre todas las cubetas. Por eso las tablas de hoy usan \(m = 7\) y \(m = 11\).
8.3.2 · Función hash

Cadenas: el hash polinomial

Cada carácter es un número, su código ASCII ('s' = 115), y se combinan como dígitos en base \(b\):

\[ h(s) = \left( s_0\, b^{L-1} + s_1\, b^{L-2} + \cdots + s_{L-1} \right) \bmod m \]

int hashCadena(std::string s) {
    int L = s.size();
    int h = 0;
    for (int j = 0; j < L; j++) {
        h = (h * 31 + s[j]) % M;
    }
    return h;
}
\(j\)carácterh * 31 + s[j]\(h\)
0's' = 1150 · 31 + 115 = 1153
1'o' = 1113 · 31 + 111 = 2041
2'l' = 1081 · 31 + 108 = 1396

Sacar el residuo en cada vuelta da lo mismo que sacarlo al final, y evita que h se desborde.

8.3.2 · Función hash

¿Por qué no sumar los caracteres?

CadenaSuma de códigosSuma \(\bmod 7\)Polinomial, \(b = 31\), \(\bmod 7\)
"amor"97 + 109 + 111 + 114 = 43141
"roma"114 + 111 + 109 + 97 = 43140
  • La suma no depende del orden de las letras: todos los anagramas caen en la misma casilla.
  • En el polinomial cada carácter se multiplica por una potencia distinta de \(b\) según su posición, así que cambiar el orden cambia el resultado.
Checkpoint

Una tabla de \(m = 100\) cubetas guarda precios en centavos, y casi todos terminan en 00 o en 50. ¿Qué pasa con \(h(k) = k \bmod 100\)?

B. \(k \bmod 100\) son los dos últimos dígitos de \(k\), y en estos datos solo toman dos valores. Que las claves sean distintas no basta: importa que sus residuos sean distintos. Con \(m = 101\) (primo), los residuos dependen de todos los dígitos del precio y se reparten. El tamaño de los precios no cambia nada, por eso la C es incorrecta.
8.3.2 · Colisiones

Las colisiones no se pueden evitar

  • Hay muchas más claves posibles que cubetas: solo de cadenas de 10 letras minúsculas hay \(26^{10}\), unos 141 billones, contra unas miles de cubetas. Por el principio del casillero, algunas claves comparten cubeta.
  • Una buena función hash reparte las colisiones de manera uniforme, pero no las elimina.
  • Por eso toda tabla hash trae una regla para resolverlas. Hay dos familias: encadenamiento (una lista por cubeta) y direccionamiento abierto (buscar otra casilla en el mismo arreglo).
8.3.2 · Encadenamiento

Una lista simple por cubeta


const int M = 7;              // numero de cubetas
// struct Nodo: el de la sesion 12 (dato, next)

class TablaHash {
    Nodo* tabla[M];           // tabla[i]: primer nodo de la cubeta i
public:
    TablaHash() {
        for (int i = 0; i < M; i++)
            tabla[i] = nullptr;   // 7 listas vacias
    }
    void inserta(int k);      // pre: k >= 0 y k no esta
    bool contiene(int k);     // pre: k >= 0
};

Cada tabla[i] hace el papel del head de una lista. Insertar y buscar empiezan igual: calculan k % M para saber en qué lista trabajar.

8.3.2 · Encadenamiento

Encadenamiento, línea por línea

8.3.2 · Encadenamiento

El código completo


void inserta(int k) {
    int i = k % M;
    Nodo* nuevo = new Nodo(k);
    nuevo->next = tabla[i];
    tabla[i] = nuevo;
}
        

bool contiene(int k) {
    int i = k % M;
    Nodo* p = tabla[i];
    while (p != nullptr) {
        if (p->dato == k)
            return true;
        p = p->next;
    }
    return false;
}

inserta es O(1): no recorre nada. contiene recorre una sola lista y cuesta lo que mida esa lista.

8.3.2 · Direccionamiento abierto

Todo dentro del arreglo


const int M = 7;
const int VACIA = -1;         // marca de casilla sin dato

class TablaAbierta {
    int tabla[M];             // las claves viven en el arreglo
public:
    TablaAbierta() {
        for (int i = 0; i < M; i++)
            tabla[i] = VACIA;
    }
    void inserta(int k);      // pre: k >= 0, k no esta, hay hueco
    bool contiene(int k);     // pre: k >= 0, hay hueco
};

No hay nodos ni punteros. Como cada casilla guarda una sola clave, la tabla se llena: con M casillas caben a lo más M claves.

8.3.2 · Direccionamiento abierto

Sondeo lineal, línea por línea

8.3.2 · Direccionamiento abierto

Buscar sigue la misma ruta


bool contiene(int k) {
    int i = 0;
    int pos = k % M;
    while (tabla[pos] != VACIA) {
        if (tabla[pos] == k)
            return true;
        i++;
        pos = (k % M + i) % M;
    }
    return false;
}
  • Prueba las mismas casillas que inserta, en el mismo orden.
  • Una casilla VACIA indica que la clave no está: inserta la habría guardado ahí.
  • Borrar no puede dejar VACIA: si se borra el 24, contiene(17) se detiene en la 4 y no llega a la 5. Se deja una lápida.
8.3.2 · Direccionamiento abierto

Tres reglas para la casilla del intento \(i\)

SondeoCasilla del intento \(i = 0, 1, 2, \ldots\)Desde la casilla 3, con \(m = 11\)
Lineal\(\big(h(k) + i\big) \bmod m\)3, 4, 5, 6, 7, …
Cuadrático\(\big(h(k) + i^{2}\big) \bmod m\)3, 4, 7, 1, 8, …
Doble hashing\(\big(h(k) + i \cdot h_2(k)\big) \bmod m\)con \(h_2(k) = 6\): 3, 9, 4, 10, 5, …
  • \(h(k) = k \bmod m\) es la casilla inicial. La regla solo decide qué casilla se prueba cuando hay choque.
  • En doble hashing, \(h_2(k) = R - (k \bmod R)\) con \(R\) primo menor que \(m\). Da un número entre 1 y \(R\), nunca 0; con un paso 0 la clave probaría siempre la misma casilla.
8.3.2 · Direccionamiento abierto

Las mismas claves, tres reglas

8.3.2 · Direccionamiento abierto

En el código cambia una línea


void inserta(int k) {
    int i = 0;
    int pos = k % M;
    while (tabla[pos] != VACIA) {
        i++;
        pos = (k % M + i) % M;
    }
    tabla[pos] = k;
}
        

// cuadratico: la linea 6 queda asi
pos = (k % M + i * i) % M;

// doble hashing: la linea 6 queda asi
pos = (k % M + i * h2(k)) % M;

int h2(int k) {       // con M = 11
    return 7 - k % 7; // entre 1 y 7
}

Es la misma línea en contiene: buscar tiene que repetir la ruta de la inserción.

8.3.2 · Direccionamiento abierto

Lo que cada regla necesita

  • Lineal: siempre encuentra una casilla vacía si la hay, porque prueba todas. Su problema es el cúmulo primario que se vio en la animación.
  • Cuadrático: no prueba todas las casillas. Con \(m = 7\), los valores de \(i^{2} \bmod 7\) son 0, 1, 4, 2, 2, 4, 1: solo 4 casillas distintas. Con \(m\) primo, encuentra hueco si la tabla está a lo más a la mitad.
  • Doble hashing: prueba todas las casillas si \(h_2(k)\) y \(m\) no comparten factores, lo que se garantiza con \(m\) primo. Cuesta calcular una segunda función.
Checkpoint

Con \(m = 11\) y \(h_2(k) = 7 - (k \bmod 7)\), insertas \(k = 47\) con doble hashing. \(47 \bmod 11 = 3\) y la casilla 3 está ocupada. ¿Qué casilla se prueba después?

B. \(47 = 6 \cdot 7 + 5\), así que \(47 \bmod 7 = 5\) y el paso es \(7 - 5 = 2\). En el intento \(i = 1\) se prueba \((3 + 2) \bmod 11 = 5\). La A es sondeo lineal. La C usa el 7 de la fórmula como si fuera el paso; el paso depende de la clave, y por eso dos claves que empiezan en la misma casilla siguen rutas distintas.
8.3.2 · Factor de carga

Factor de carga: qué tan llena está la tabla

\[ \alpha = \frac{n}{m} = \frac{\text{claves guardadas}}{\text{cubetas}} \]
  • En la animación de encadenamiento: 5 claves en 7 cubetas, \(\alpha = 5/7 \approx 0.71\). Es el largo promedio de una lista.
  • En la de sondeo lineal: también \(\alpha \approx 0.71\), y la casilla 0 se ocupó después de 5 pruebas.
  • En encadenamiento \(\alpha\) puede pasar de 1 (las listas crecen). En direccionamiento abierto \(\alpha \le 1\), porque cada casilla guarda una clave.
8.3.2 · Factor de carga

Cuánto cuesta buscar según \(\alpha\)

Con funciones hash uniformes, una búsqueda que no encuentra la clave revisa en promedio:

Fórmula\(\alpha = 0.5\)\(\alpha = 0.7\)\(\alpha = 0.9\)
Encadenamiento\(1 + \alpha\)1.51.71.9
Doble hashing\(\dfrac{1}{1 - \alpha}\)23.310
Sondeo lineal\(\dfrac{1}{2}\left(1 + \dfrac{1}{(1 - \alpha)^{2}}\right)\)2.56.150.5

El costo depende de \(\alpha\) y no de \(n\): con \(\alpha\) fijo, una tabla de mil claves y una de un millón cuestan lo mismo. El direccionamiento abierto se vuelve lento arriba de 0.7, sobre todo el lineal.

8.3.2 · Factor de carga

Rehashing

  • Cuando \(\alpha\) cruza un umbral (por ejemplo, 0.7 en direccionamiento abierto), se crea una tabla de aproximadamente el doble de cubetas, con \(m\) primo.
  • Todas las claves se reinsertan con la \(m\) nueva. No se pueden copiar casilla por casilla: \(k \bmod m\) cambió para casi todas.
  • El rehash cuesta O(n), pero ocurre cada vez que el número de claves se duplica. Repartido entre todas las inserciones da O(1) amortizado, como el push_back de vector.

El O(1) promedio supone dos cosas: una función hash uniforme y un \(\alpha\) acotado por el rehashing.

8.3.2 · El peor caso

Qué provoca el O(n)

  • Función hash pobre: si \(h\) manda las claves reales a pocas cubetas (por ejemplo, \(k \bmod 100\) con precios que terminan en 00), una cubeta concentra casi todo y buscar ahí es recorrer una lista.
  • Claves adversariales: si un atacante conoce \(h\), puede fabricar miles de claves que colisionan a propósito y volver lento un servicio (hash flooding). Por eso los lenguajes modernos eligen al azar una semilla del hash en cada ejecución.
  • \(\alpha\) sin control: sin rehashing, \(\alpha\) crece con los datos y \(1 + \alpha\) deja de ser pequeño.
Checkpoint

Diseñas una función hash con distribución perfecta y uniforme. ¿Qué pasa con las colisiones?

B. Por el principio del casillero, si hay más claves posibles que cubetas, existen claves que comparten cubeta, y con \(\alpha > 0\) las colisiones aparecen en la práctica. Por eso la regla de resolución es obligatoria. La C confunde las claves posibles con las cubetas: hay \(2^{64}\) enteros de 64 bits y la tabla tiene \(m\) cubetas.

8.3.3 Conjuntos disjuntos

8.3.3 · Conjuntos disjuntos

Union-find, ahora como tema formal

  • El lunes lo usamos para componentes en la Act 4.2; hoy le toca su lugar en el temario. Resuelve otro problema de conjuntos: mantener una partición. Cada elemento pertenece a exactamente un conjunto, y los conjuntos se fusionan con el tiempo.
  • Representación: un bosque. padre[x] apunta hacia la raíz; la raíz es el representante del conjunto. find sube hasta la raíz; union cuelga una raíz de la otra.
  • Sin optimizaciones, los árboles pueden degenerar en cadenas: find llega a costar O(n).
8.3.3 · Conjuntos disjuntos

Dos optimizaciones, y por qué hacen falta ambas

ConfiguraciónCosto por operación
Sin optimizacionesO(n) en el peor caso
Solo unión por rangoO(log n)
Solo compresión de caminosO(log n) amortizado
Ambasα(n) amortizado — inversa de Ackermann, ≤ 4 en la práctica
  • Unión por rango evita que los árboles crezcan de más al fusionar: la raíz baja se cuelga de la alta.
  • Compresión de caminos aplana el árbol en cada find: todos los vértices del camino quedan colgados directo de la raíz.
Checkpoint

Implementas union-find solo con compresión de caminos, sin unión por rango. ¿Qué garantía tienes?

B. Cada optimización por separado da O(log n) amortizado; la cota α(n) de Tarjan requiere la combinación. La opción C subestima la compresión: aplanar en cada find sí acota el costo amortizado aunque las uniones se hagan sin criterio. En la práctica se escriben las dos, y son tres líneas extra.

8.3.4 · STL

std::unordered_map y std::unordered_set


std::unordered_set<std::string> vistos;
vistos.insert("doc-42");
bool repetido = vistos.count("doc-42") > 0;   // O(1) promedio

std::unordered_map<std::string, int> frecuencia;
frecuencia["token"] = frecuencia["token"] + 1;
// si "token" no estaba, frecuencia["token"] lo crea con 0

frecuencia.reserve(1000000);            // pide cubetas de una vez
double alfa = frecuencia.load_factor(); // n / cubetas
  • Los dos usan encadenamiento. El rehash automático ocurre cuando load_factor() supera max_load_factor(), que vale 1.0 por omisión.
  • reserve(n) antes de una carga masiva evita los rehashes intermedios, igual que en vector.
8.3.4 · STL

Una función hash para un tipo propio


struct Punto {
    int x;
    int y;
};
bool operator==(Punto a, Punto b) {
    return a.x == b.x && a.y == b.y;
}
struct HashPunto {
    size_t operator()(Punto p) const {
        size_t h = p.x;
        h = h * 31 + p.y;       // la idea del hash polinomial
        return h;
    }
};
std::unordered_set<Punto, HashPunto> puntos;

Multiplicar por 31 antes de sumar hace que (1, 2) y (2, 1) tengan hash distinto. La tabla necesita además == para comparar dos claves de la misma cubeta.

Unión, intersección y diferencia con algoritmos


std::vector<int> a = {1, 3, 5, 7};
std::vector<int> b = {3, 7, 9};
std::vector<int> r;

std::set_intersection(a.begin(), a.end(),
                      b.begin(), b.end(),
                      std::back_inserter(r));   // r = {3, 7}

// misma familia: std::set_union, std::set_difference
// requisito: los dos rangos ordenados; costo O(n + m)
  • Recorren los dos rangos en una sola pasada, como el merge de mergesort. std::back_inserter(r) agrega cada resultado con r.push_back.
  • Con datos en tablas hash conviene el recorrido con consultas del primer checkpoint.
Checkpoint

Guardas transacciones por folio y necesitas dos cosas: buscar un folio exacto y listar los folios de un rango de fechas en orden. ¿Qué contenedor eliges?

B. Una tabla hash no ofrece recorrido por rango en orden: sus claves están repartidas entre las cubetas, y reconstruir el orden cuesta O(n log n) por consulta. std::map resuelve ambas operaciones en O(log n). La opción C existe en sistemas reales, pero duplica la memoria y complica cada actualización; se justifica solo si se mide que el O(log n) del map es un problema.
Por qué importa hoy

Hashing en la infraestructura de IA

  • Deduplicación a escala web: MinHash y LSH son funciones hash diseñadas para que documentos parecidos caigan en la misma cubeta, al revés del objetivo usual de repartir.
  • Prompt caching: el trabajo de procesar el prefijo de un prompt se guarda en una tabla indexada por ese prefijo y se reutiliza en las llamadas que empiezan igual.
  • Feature hashing: convierte un vocabulario sin límite en un vector de dimensión fija sin guardar diccionario. La cubeta de cada palabra es su posición en el vector, y las colisiones se toleran como ruido.
