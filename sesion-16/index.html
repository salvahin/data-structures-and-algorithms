8.1 Árboles:
terminología

8.1 · Terminología

Las palabras del bloque

  • Raíz: el único nodo sin padre.
  • Hoja: nodo sin hijos.
  • Grado: número de hijos de un nodo (en un árbol binario, a lo más 2).
  • Profundidad de un nodo: aristas desde la raíz hasta él.
  • Altura del árbol: profundidad máxima de sus hojas.
8.1 · Altura y número de nodos

Cuánto cabe en una altura h

  • Un árbol binario de altura h tiene a lo más 2h+1 − 1 nodos: cada nivel duplica al anterior.
  • Al revés: para guardar n nodos se necesita altura al menos ⌈log₂(n+1)⌉ − 1.
  • Con un millón de nodos: altura mínima 19 si el árbol está lleno; altura 999 999 si es una cadena.

Las operaciones de hoy cuestan O(h). Todo el bloque consiste en mantener h cerca de log n.

Checkpoint

Un árbol binario lleno (todos los niveles completos) tiene 1023 nodos. ¿Cuál es su altura?

B. Un árbol lleno de altura h tiene 2h+1 − 1 nodos; con h = 9 son exactamente 1023. La opción C describe el árbol degenerado, que existe, pero el enunciado dice que los niveles están completos. Esta cuenta es la razón de que "balanceado" signifique "operaciones en O(log n)".

8.1.1 Árbol binario
de búsqueda

8.1.1 · BST

El invariante de orden

Un BST es un árbol binario donde, para cada nodo:

Todas las claves del subárbol izquierdo < clave del nodo < todas las claves del subárbol derecho.

  • La condición abarca los descendientes completos, no solo a los dos hijos.
  • El invariante permite buscar descartando un subárbol completo por comparación: el mismo principio de la búsqueda binaria de la sesión 6.

En la sesión 17 veremos un árbol que cumple la comparación con sus hijos y aun así viola el invariante.

8.1.1.1 · Representación con nodos

El nodo y la clase


template <typename T>
struct Nodo {
    T     dato;
    Nodo* izq = nullptr;
    Nodo* der = nullptr;
};

template <typename T>
class BST {
public:
    void add(const T& x) { raiz = add(raiz, x); }
    bool search(const T& x) const;
private:
    Nodo<T>* raiz = nullptr;
};

La misma memoria dinámica de las listas encadenadas (sesión 11), con dos apuntadores por nodo en lugar de uno.

8.1.1.2 · Operaciones

add y search en código


Nodo<T>* add(Nodo<T>* n, const T& x) {
    if (!n) return new Nodo<T>{x};
    if      (x < n->dato) n->izq = add(n->izq, x);
    else if (n->dato < x) n->der = add(n->der, x);
    return n;                     // duplicado: no se inserta
}

bool search(const T& x) const {
    Nodo<T>* n = raiz;
    while (n) {
        if      (x < n->dato) n = n->izq;
        else if (n->dato < x) n = n->der;
        else return true;         // ni menor ni mayor: es x
    }
    return false;
}

Ambas siguen un solo camino raíz→hoja: a lo más h + 1 comparaciones.

Checkpoint

En un árbol binario, cada nodo es mayor que su hijo izquierdo y menor que su hijo derecho. ¿Es necesariamente un BST?

B. Comparar solo con los hijos es el "check ingenuo": un nodo puede cumplirlo y tener, por ejemplo, un 50 dentro del subárbol izquierdo de un 40. El balanceo (opción C) es independiente del invariante de orden. En la sesión 17 construiremos el contraejemplo exacto.
8.1.1.2 · Operaciones

Eliminar: los tres casos

  • Hoja. Se elimina el nodo y el padre apunta a nullptr.
  • Un hijo. El hijo toma el lugar del nodo eliminado; el invariante se conserva porque todo el subárbol ya estaba del lado correcto.
  • Dos hijos. Se copia en el nodo el sucesor inorden (el mínimo del subárbol derecho) y se elimina el sucesor de su posición original.

El sucesor no tiene hijo izquierdo (si lo tuviera, habría alguien menor), así que eliminarlo cae en los casos 1 o 2. La recursión termina.

8.1.1.2 · Operaciones

erase en código


Nodo<T>* erase(Nodo<T>* n, const T& x) {
    if (!n) return nullptr;
    if      (x < n->dato) n->izq = erase(n->izq, x);
    else if (n->dato < x) n->der = erase(n->der, x);
    else {
        if (!n->izq || !n->der) {        // hoja o un hijo
            Nodo<T>* hijo = n->izq ? n->izq : n->der;
            delete n;
            return hijo;
        }
        Nodo<T>* s = minimo(n->der);     // dos hijos:
        n->dato = s->dato;               // copiar el sucesor
        n->der  = erase(n->der, s->dato);
    }
    return n;
}
8.1.1.2 · Complejidad

Todo cuesta O(h)

OperaciónCostoPor qué
searchO(h)un camino raíz→hoja
addO(h)baja hasta un nullptr
eraseO(h)camino + búsqueda del sucesor
  • Árbol balanceado: h ≈ log₂ n → operaciones logarítmicas.
  • Árbol degenerado: h = n − 1 → operaciones lineales, como en una lista.

8.1.1.3 Recorridos

8.1.1.3 · Recorridos

Cuatro maneras de visitar todo

  • Preorden (raíz, izq, der): serializar o copiar el árbol — la raíz sale primero y al reconstruir llega primero.
  • Inorden (izq, raíz, der): en un BST produce las claves en orden ascendente.
  • Postorden (izq, der, raíz): liberar memoria — los hijos se destruyen antes que el padre.
  • Por niveles: una fila (sesión 14) en lugar de recursión; visita nivel por nivel.

void inorden(Nodo<T>* n) {
    if (!n) return;
    inorden(n->izq);   visitar(n->dato);   inorden(n->der);
}
8.1.1.3 · Recorridos

Por qué el inorden de un BST sale ordenado

  • Argumento por inducción sobre el tamaño del árbol: supongamos que el inorden de todo BST más pequeño sale ordenado.
  • El inorden imprime: subárbol izquierdo (ordenado, y todas sus claves < raíz), luego la raíz, luego el derecho (ordenado, y todas > raíz).
  • La concatenación de esos tres bloques queda ordenada. El paso usa el invariante completo — con la versión "solo hijos" el argumento se cae.

En un árbol binario sin invariante de orden, el inorden es una secuencia cualquiera.

Checkpoint

Vas a liberar con delete todos los nodos de un árbol. ¿Qué recorrido usas?

B. Si liberas la raíz primero (preorden), pierdes los apuntadores izq y der y ya no puedes llegar a los hijos: uso de memoria liberada. El postorden visita a los hijos antes que al padre, que es el orden seguro de destrucción. Los tres recorridos visitan todos los nodos; lo que cambia es el momento en que tocan cada uno.

8.1.2 Árboles AVL

8.1.2 · El problema

El BST degenerado

  • Insertar 10, 20, 30, 40… (claves ya ordenadas): cada nueva clave es la mayor y siempre va a la derecha.
  • Resultado: una cadena de altura n − 1. search cuesta O(n), igual que en una lista.
  • Es la respuesta a la pregunta de la sesión 1: 1000 valores ordenados → altura 999.
8.1.2 · Árboles AVL

Factor de balance

  • FB(nodo) = altura(subárbol izquierdo) − altura(subárbol derecho).
  • Un AVL mantiene |FB| ≤ 1 en todos los nodos, tras cada inserción y eliminación.
  • Si una inserción deja algún FB en ±2, se restaura con una o dos rotaciones locales sobre el primer nodo desbalanceado del camino.
  • Con esa regla, la altura queda acotada: h ≈ 1.44·log₂ n. Las operaciones O(h) pasan a ser O(log n) garantizado.
8.1.2 · Rotaciones

Rotación simple, paso a paso

La rotación conserva el inorden (10, 20, 30 antes y después) y reduce la altura en 1.

8.1.2 · Rotaciones

Los cuatro casos de desbalance

CasoDónde quedó el pesoArreglo
IIizquierda-izquierdarotación simple a la derecha
DDderecha-derecharotación simple a la izquierda
IDizquierda-derechadoble: izquierda sobre el hijo, luego derecha
DIderecha-izquierdadoble: derecha sobre el hijo, luego izquierda

Los casos dobles (el "zig-zag" de la demo de la sesión 1) aparecen cuando una rotación simple dejaría el peso del mismo lado: la primera rotación convierte el caso en II o DD.

Checkpoint

¿Cuánto cuesta search en un BST de n nodos, en el peor caso?

B. "Cada comparación descarta la mitad" solo vale si los subárboles tienen tamaños parecidos, y el invariante BST no lo garantiza: insertar claves ordenadas produce una cadena. La cota honesta es O(h). El AVL existe precisamente para forzar h = O(log n) y volver cierta la opción A.

Por qué importa hoy

Árboles en los sistemas que usas

  • Los árboles de decisión y los bosques aleatorios siguen siendo la referencia difícil de batir en datos tabulares (Grinsztajn et al., 2022). Tienen forma de árbol binario, pero sin invariante de orden sobre una clave: cada nodo divide por un atributo distinto aprendido de los datos.
  • Los índices de las bases de datos son B-trees: árboles de búsqueda balanceados, emparentados con el rojo-negro más que con el AVL.
  • Cuando filtras por rango en una base vectorial ("solo documentos de 2024 en adelante"), esa parte de la consulta corre sobre un árbol ordenado.

std::map y std::set: árboles balanceados

La implementación típica es un árbol rojo-negro. Contraste del curso: std::map mantiene orden; std::unordered_map es más rápido en promedio y no lo mantiene.
