Dos líneas que imprimen lo que nadie espera


#include <iostream>

int main() {
    int a = 2147483647;          // el mayor int de 32 bits
    std::cout << a + 1 << '\n';

    unsigned int u = 1;
    int i = -1;
    std::cout << (i < u) << '\n';
}
      

-2147483648
0

Sumarle uno a un número lo hizo negativo, y menos uno resultó no ser menor que uno. Ninguna de las dos líneas tiene un error de sintaxis.

R2 · Anatomía

Las cuatro piezas de un programa mínimo


#include <iostream>      // trae la declaración de std::cout

int main() {              // punto de entrada: el sistema llama aquí
    std::cout << "hola\n";
    return 0;             // 0 significa "terminó bien"
}
  • #include lo procesa el preprocesador de R0: pega el contenido de la cabecera antes de compilar.
  • Un programa tiene exactamente una función main. El sistema operativo la llama y recibe su valor de retorno.
  • main es la única función que puede omitir el return: si falta, el compilador supone return 0;. En cualquier otra función eso sería un error (R5).
R2 · Espacios de nombres

Por qué se escribe std::cout

  • La biblioteca estándar declara sus nombres dentro de un espacio de nombres llamado std. std::cout significa "el cout que vive en std".
  • Sirve para que tu programa pueda tener su propia función sort o su propia clase list sin chocar con las de la biblioteca.
  • using namespace std; hace visibles todos esos nombres sin prefijo. Es tolerable en un .cpp de práctica y nunca aceptable en una cabecera, porque se lo impone a todo archivo que la incluya.

std::cout << "sin using\n";      // preferido en este curso

Los espacios de nombres se tratan a fondo en R7.

Checkpoint

Un programa compila y ejecuta bien, pero el return de main devuelve 1. ¿Qué consecuencia tiene?

B. El valor de retorno de main es el código de salida del proceso: cero indica éxito y cualquier otro valor indica fallo. La terminal lo consulta con echo $? y los guiones de compilación lo usan para decidir si continúan. No se descarta (A) ni se imprime en pantalla (C).

R2 · Tipos

Pregúntale al compilador con sizeof


#include <iostream>

int main() {
    std::cout << sizeof(char)   << ' '
              << sizeof(short)  << ' '
              << sizeof(int)    << ' '
              << sizeof(long)   << ' '
              << sizeof(double) << '\n';
}
      

Linux 64 bits:    1 2 4 8 8
Windows 64 bits:  1 2 4 4 8      <- long mide la mitad

sizeof devuelve bytes y lo resuelve el compilador, no el programa en ejecución. Cuando un tamaño exacto importe, usa <cstdint>: int32_t, uint64_t.

Checkpoint

Tu programa guarda identificadores hasta 3 000 000 000 en un long. Funciona en tu Linux y falla en la máquina Windows de un compañero. ¿Por qué?

C. El estándar exige que long tenga al menos 32 bits y deja el resto a cada plataforma: Linux de 64 bits le da 64, Windows de 64 bits le da 32. El valor desborda. La solución es long long o int64_t. Windows sí maneja enteros de 64 bits (A) y no hay conversión automática a double (B).
R2 · Conversiones implícitas

El tipo de los operandos decide la operación


#include <iostream>

int main() {
    int a = 7, b = 2;
    std::cout << a / b   << '\n';   // 3    división entera
    std::cout << a / 2.0 << '\n';   // 3.5  a se convierte a double

    double d = 3.9;
    int t = d;                      // t vale 3: se trunca
    std::cout << t << '\n';
    std::cout << 'A' + 1 << '\n';   // 66   char promovido a int
}
  • Con dos enteros, / es división entera y descarta el residuo. Basta con que uno sea double para que la división sea real.
  • Asignar un double a un int corta la parte decimal hacia cero. Para redondear existe std::round.
R2 · Conversiones implícitas

-1 < 1u es falso

  • Al comparar int con unsigned int, el compilador convierte el int a unsigned antes de comparar.
  • -1 convertido a unsigned int de 32 bits vale 4294967295, que no es menor que 1.
  • -Wall -Wextra lo avisa: comparison of integer expressions of different signedness.

unsigned int u = 3;
std::cout << u - 5 << '\n';        // 4294967294, no -2
Esta conversión aparecerá cada vez que compares un índice int contra v.size(), que es de tipo sin signo (R18).
Checkpoint

¿Qué imprime std::cout << 5 / 2 * 2.0;?

A. / y * tienen la misma precedencia y agrupan de izquierda a derecha, así que la expresión es (5 / 2) * 2.0: primero 5 / 2, con dos int, da 2 por división entera. Después 2 * 2.0 da 4.0, que cout imprime como 4 porque no tiene decimales significativos. La opción B supone que la división se hace en double desde el principio y la C mezcla las dos ideas.
R2 · Desbordamiento

Qué ocurre al pasarse del rango


#include <iostream>

int main() {
    short s = 32767;
    s = s + 1;
    std::cout << s << '\n';                        // -32768

    unsigned char c = 250;
    c = c + 10;
    std::cout << static_cast<int>(c) << '\n';      // 4
}
  • En los tipos sin signo el resultado se define como aritmética modular: 260 % 256 da 4.
  • En los tipos con signo el desbordamiento es comportamiento indefinido. La vuelta a negativo es lo que suele pasar, no lo que el estándar promete: con optimización el compilador puede producir otra cosa.
R2 · const y auto

Fijar un valor y deducir un tipo


#include <iostream>
#include <string>

int main() {
    const double IVA = 0.16;
    // IVA = 0.20;          // error: no se puede asignar a const

    auto n = 42;            // n es int
    auto tasa = IVA * 2;    // tasa es double
    auto texto = std::string("hola");
    std::cout << n << ' ' << tasa << ' ' << texto << '\n';
}
  • const convierte un intento de modificación en un error de compilación. Marca las constantes del programa y, más adelante, los parámetros que una función promete no tocar (R8).
  • auto deja que el compilador deduzca el tipo del inicializador. El tipo existe y es fijo; lo que se ahorra es escribirlo. Úsalo cuando el tipo sea largo y evidente por el contexto, no para esconder qué se está guardando.
Checkpoint

Escribes auto promedio = suma / cantidad; donde suma y cantidad son int. ¿De qué tipo es promedio y qué guarda?

B. auto deduce del tipo de la expresión, y int / int es una división entera que produce un int. Los decimales se pierden antes de que auto intervenga; declarar double tampoco los recuperaría. La solución es forzar la división real: suma / static_cast<double>(cantidad). En C++ los tipos se fijan al compilar (C).
R2 · Trampas comunes

Cuatro supuestos que fallan

  • "int mide lo mismo en todas partes." Mide al menos 16 bits; el resto depende de la plataforma. long es el caso que más rompe programas al cambiar de máquina.
  • Comparar con signo contra sin signo. Producirá resultados invertidos y ciclos que no terminan. La advertencia de -Wextra es la única señal.
  • Esperar redondeo al convertir a int. Se trunca hacia cero: -3.9 se vuelve -3.
  • Confiar en el desbordamiento con signo. Es comportamiento indefinido: puede dar resultados distintos con y sin -O2.
R2 · Ejercicio

Predice la salida de estas seis expresiones


std::cout << 7 / 2 << '\n';                       // 1
std::cout << 7 / 2.0 << '\n';                     // 2
std::cout << 7 % 2 << '\n';                       // 3
std::cout << static_cast<int>(3.99) << '\n';      // 4
std::cout << (1 == 1.0) << '\n';                  // 5
unsigned int u = 3;
std::cout << u - 5 << '\n';                       // 6

Escríbelas en papel antes de compilar. Después verifica con g++ -std=c++17 -Wall -Wextra.


1) 3            división entera, se descarta el residuo
2) 3.5          un operando double convierte la operación
3) 1            % es el residuo de la división entera
4) 3            se trunca hacia cero, no se redondea
5) 1            el int se convierte a double; cout imprime true como 1
6) 4294967294   3 - 5 en aritmética sin signo de 32 bits

La sexta es la que más se falla. Ninguna resta de tipos sin signo puede dar un negativo.
