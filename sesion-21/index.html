8.2.1 Definición y modelado

8.2.1 · Definición

Un grafo es un conjunto de vértices y un conjunto de aristas

\(G = (V, E)\). Los vértices representan entidades; las aristas, relaciones entre pares de entidades.

Aquí \(V = \{A, B, C, D\}\) y \(E = \{AB, AC, BC, BD, CD\}\): \(|V| = 4\), \(|E| = 5\).

8.2.1 · Definición

Tres decisiones al definir el grafo

DecisiónOpcionesEjemplo
DirecciónNo dirigido: la arista {u, v} conecta en ambos sentidos. Dirigido: el arco (u, v) va de u hacia v.Amistad vs. "sigue a"
PesoPonderado: cada arista lleva un costo w(u, v). No ponderado: todas valen igual.Distancia en km vs. "hay carretera"
CiclosCon ciclos o acíclico. Los dirigidos acíclicos (DAG) se estudian más adelante en este bloque.Red vial vs. prerrequisitos

Las tres decisiones las fija el problema: un grafo de prerrequisitos con un ciclo describe una carrera imposible de cursar.

8.2.1 · Definición

Vocabulario que usaremos todo el bloque

  • Grado de un vértice: cuántas aristas lo tocan. En dirigidos se separa en grado de entrada y de salida.
  • Camino: secuencia de vértices donde cada par consecutivo está unido por una arista. Su longitud es el número de aristas.
  • Ciclo: camino que regresa al vértice inicial sin repetir aristas.
  • Conectividad: un grafo no dirigido es conexo si existe camino entre cualquier par de vértices; si no, se parte en componentes conexos.

8.2.2 Representaciones

8.2.2 · Representaciones

La pregunta previa: ¿cuántas aristas hay?

  • Con V vértices, E puede ir desde \(V - 1\) (apenas conexo) hasta \(V(V-1)/2\) (todos con todos).
  • Grafo denso: E se acerca a \(V^2\). Grafo disperso (ralo): E se acerca a V.
  • Casi todos los grafos reales son dispersos: en una red social de millones de personas, cada una tiene cientos de amigos, no millones.

La densidad decide la representación: guardar \(V^2\) casillas para un grafo con \(E \approx V\) desperdicia casi toda la memoria.

8.2.2 · Representaciones

Un grafo, tres retratos

8.2.2.1 · Matriz de adyacencias

Matriz de adyacencias

  • Una tabla de V×V: la casilla M[u][v] vale 1 si existe la arista (u, v) y 0 si no. En grafos ponderados guarda el peso.
  • En grafos no dirigidos la matriz es simétrica: M[u][v] = M[v][u].
  • Memoria: \(O(V^2)\), sin importar cuántas aristas existan.

int n = 6;   // vértices 0..5
std::vector<int> fila(n, 0);
std::vector<std::vector<int>> M(n, fila);

void agregarM(int u, int v) {
    M[u][v] = 1;
    M[v][u] = 1;   // omitir si es dirigido
}
8.2.2.2 · Lista de adyacencias

Lista de adyacencias

  • Un arreglo de V listas: la posición u guarda los vecinos de u.
  • Memoria: \(O(V + E)\). En un grafo no dirigido, la suma de los tamaños de todas las listas es 2E, porque cada arista aparece dos veces.

std::vector<std::vector<int>> ady(n);

void agregarL(int u, int v) {
    ady[u].push_back(v);
    // si el grafo es dirigido, se omite:
    ady[v].push_back(u);
}
8.2.2 · Consultas

¿Existe la arista 3–5?

8.2.2 · Consultas

Consultar una arista


bool existeM(int u, int v) {
    return M[u][v] == 1;
}
bool existeL(int u, int v) {
    for (int w : ady[u]) {
        if (w == v) return true;
    }
    return false;
}

Matriz: una lectura, \(O(1)\). Lista: revisar los vecinos de u, \(O(\text{grado}(u))\).

8.2.2 · Consultas

Recorrer los vecinos


void vecinosM(int u) {
    for (int v = 0; v < n; v++) {
        if (M[u][v] == 1) {
            visita(v);
        }
    }
}
void vecinosL(int u) {
    for (int v : ady[u]) {
        visita(v);
    }
}

Matriz: \(O(V)\). Lista: \(O(\text{grado}(u))\). visita es lo que haga el algoritmo con cada vecino.

8.2.2.1 · Matriz de adyacencias

Cuándo conviene la matriz

  • Grafo denso: si E se acerca a \(V^2\), las \(V^2\) casillas ya no son desperdicio.
  • La operación más frecuente es consultar aristas concretas: ninguna otra representación iguala el \(O(1)\) de M[u][v].
  • V es pequeño (cientos): las \(V^2\) casillas caben sin problema y el código es el más simple de los tres.
  • Algoritmos que operan sobre la matriz completa, como Floyd–Warshall.

Con V = 100 000, la matriz necesita \(10^{10}\) casillas: unos 10 GB aun con un byte por casilla. Ahí la memoria descarta la matriz.

Checkpoint

Red social: 10 millones de usuarios, 200 amistades en promedio. ¿Qué representación usas?

B. El grafo es dispersísimo: 200 vecinos de 10 millones posibles. La matriz costaría \((10^{7})^2 = 10^{14}\) casillas, decenas de terabytes casi todos en cero, mientras que la lista ocupa \(O(V+E) \approx 2 \times 10^{9}\) entradas. La opción C es cierta en lo lógico, pero ignora que las dos representaciones cuestan muy distinto.

Un arco, un registro

8.2.2.3 · Lista de arcos

Lista de arcos


struct Arco {
    int u;
    int v;
    int peso;
};
std::vector<Arco> arcos;

bool menorPeso(Arco a, Arco b) {
    return a.peso < b.peso;
}

// Kruskal empieza ordenando todos los arcos
std::sort(arcos.begin(), arcos.end(),
          menorPeso);
8.2.2.3 · Lista de arcos

Cuándo conviene la lista de arcos

  • Guarda solo la colección de aristas, sin índice por vértice. Memoria \(O(E)\).
  • Es la representación adecuada cuando el algoritmo procesa aristas completas y no vecinos: Kruskal las ordena por peso; Bellman–Ford las relaja todas en cada ronda.
  • Para "vecinos de u" es la peor de las tres: hay que barrer las E aristas.
8.2.2 · Comparativa

Las tres representaciones, frente a frente

MatrizLista de adyacenciasLista de arcos
Memoria\(O(V^2)\)\(O(V + E)\)\(O(E)\)
¿Existe (u, v)?\(O(1)\)\(O(\text{grado}(u))\)\(O(E)\)
Vecinos de u\(O(V)\)\(O(\text{grado}(u))\)\(O(E)\)
Cuándodenso, V pequeño, consulta de aristadisperso, recorridos (el caso común)algoritmos por arista (Kruskal, Bellman–Ford)

La tabla es una predicción: se puede comprobar midiendo memoria y tiempo de consulta sobre un grafo denso y uno disperso.

Checkpoint

¿En qué operación la matriz de adyacencias supera a la lista de adyacencias?

B. M[u][v] responde en \(O(1)\); la lista tiene que buscar v entre los vecinos de u, \(O(\text{grado}(u))\). En las otras dos operaciones gana la lista: recorre solo los vecinos reales (la matriz barre la fila entera, \(O(V)\)) y su memoria \(O(V+E)\) se ajusta al grafo, mientras que la matriz paga \(V^2\) casillas aunque casi todas valgan cero.

Por qué importa hoy

El grafo de conocimiento detrás de GraphRAG

  • GraphRAG recupera contexto sobre un grafo de conocimiento — entidades y las relaciones que las conectan — en lugar de sobre una lista plana de fragmentos de texto. Es una de las líneas activas para reducir alucinaciones.
  • Ese grafo necesita una representación concreta. Con millones de entidades y relaciones dispersas, la elección entre matriz y lista de adyacencias decide si el sistema escala o se queda en prototipo — el mismo cálculo del quiz de la red social.
  • Las redes neuronales de grafos (GNN) operan multiplicando por la matriz de adyacencias dispersa: la misma estructura de hoy, escrita en álgebra lineal.
STL

Lista de adyacencias con contenedores estándar


// Vértices densos y numerados 0..n-1: la forma habitual
std::vector<std::vector<int>> ady(n);

// Vértices con identificador arbitrario:
std::unordered_map<std::string, std::vector<std::string>> g;
g["CDMX"].push_back("GDL");
  • Si los vértices son enteros consecutivos, vector<vector<int>> da acceso O(1) por índice y localidad de memoria.
  • Si son cadenas o IDs dispersos, unordered_map evita renumerarlos a mano. El costo de esa comodidad se estudia con las tablas hash, más adelante en este bloque.
STL

Aristas ponderadas: std::pair y structured bindings


std::vector<std::vector<std::pair<int,int>>> ady(n);
ady[u].push_back({v, peso});

for (auto [vecino, peso] : ady[u])       // C++17
    std::cout << vecino << " cuesta " << peso << '\n';
  • Cada vecino viaja con su peso en un pair; los structured bindings desempacan los dos campos con nombre propio.
  • Sin ellos el código se llena de arista.first y arista.second, que no dicen cuál es el vértice y cuál el peso.
