R1 · La extensión de C/C++

Qué instala y qué no instala

En el panel de extensiones busca C/C++ de Microsoft (identificador ms-vscode.cpptools) e instálala.

Sí haceNo hace
Autocompletado y IntelliSenseNo trae compilador
Ir a definición, renombrarNo compila tu código
Conectar VS Code con gdb o lldbNo trae depurador

El subrayado rojo del arranque viene de IntelliSense, que analiza el texto por su cuenta y no encontró la ruta de las cabeceras del sistema. El compilador sí la encontró.

Checkpoint

Instalas la extensión de C/C++ en una máquina recién formateada y presionas el botón de compilar. VS Code responde que no encuentra g++. ¿Qué falta?

C. La extensión es un cliente: habla con un compilador y con un depurador que ya deben existir en la máquina. Reinstalarla no agrega binarios (A) y el indexado de IntelliSense es independiente de la compilación (B). En Linux o WSL se resuelve con sudo apt install build-essential gdb, en macOS con xcode-select --install.
R1 · El espacio de trabajo

Abre la carpeta, no el archivo

  • Con Archivo → Abrir carpeta VS Code adopta ese directorio como raíz del proyecto.
  • Toda la configuración vive en una subcarpeta .vscode/ dentro de esa raíz.
  • Si abres solo el .cpp con doble clic, no hay raíz y no hay dónde guardar tasks.json.

proyecto/
├── .vscode/
│   └── tasks.json      <- cómo compilar
└── main.cpp
R1 · tasks.json

Un tasks.json completo


{
  "version": "2.0.0",
  "tasks": [{
    "label": "compilar archivo activo",
    "type": "cppbuild",
    "command": "/usr/bin/g++",
    "args": ["-std=c++17", "-Wall", "-Wextra", "-g", "${file}",
             "-o", "${fileDirname}/${fileBasenameNoExtension}"],
    "options": { "cwd": "${fileDirname}" },
    "problemMatcher": ["$gcc"],
    "group": { "kind": "build", "isDefault": true }
  }]
}

En macOS, "command": "/usr/bin/clang++". En Windows con MinGW, la ruta del g++.exe instalado.

R1 · tasks.json

Qué dice cada campo

CampoQué significa
labelEl nombre que verás en la lista de tareas
command + argsEl comando exacto que se ejecuta, palabra por palabra
${file}Ruta del archivo abierto en ese momento
${fileBasenameNoExtension}main.cpp produce el ejecutable main
problemMatcherEnseña a VS Code a leer los errores de gcc
groupLa marca como tarea de compilación por omisión

Las tareas son la forma de VS Code de guardar comandos de terminal. Ese archivo es el mismo g++ -std=c++17 -Wall -Wextra -g … de R0, escrito en JSON.

R1 · Compilar con un atajo

Ctrl+Shift+B compila el archivo abierto

  • Ctrl+Shift+B en Windows y Linux, Cmd+Shift+B en macOS.
  • Ejecuta la tarea marcada con "isDefault": true, sin preguntar cuál.
  • Sin esa marca, el atajo abre una lista y hay que elegir la tarea cada vez.
  • La salida aparece en la pestaña Terminal, con el comando completo en la primera línea. Léelo: es exactamente lo que se ejecutó.
El atajo no es magia del editor. Escribe el comando de R0 en una terminal y presiona Enter por ti.
Checkpoint

Tienes main.cpp y suma.cpp. Con el tasks.json del slide 7 abres main.cpp y presionas Ctrl+Shift+B. ¿Qué pasa?

B. ${file} se sustituye por la ruta del archivo activo y nada más; el comando resultante ignora suma.cpp. Se obtiene el undefined reference de R0. Para proyectos de varios archivos se cambia ${file} por "${fileDirname}/*.cpp" o se usa un Makefile (R11).
R1 · Leer los errores

Del mensaje a la línea con un clic


main.cpp:5:22: error: expected ';' before '}' token
    5 |     std::cout << "hola\n"
      |                          ^
  • Con "problemMatcher": ["$gcc"], VS Code interpreta archivo:línea:columna y llena el panel Problemas.
  • Un clic en la entrada abre el archivo en esa línea exacta.
  • F8 salta al siguiente problema sin usar el ratón.

Sin problemMatcher el error sigue apareciendo en la terminal, pero como texto suelto que hay que localizar a mano.

R1 · Tres minutos de depurador

El programa se detiene donde tú decidas


#include <iostream>

int main() {
    int total = 0;
    for (int i = 1; i <= 5; i++) total += i;   // punto rojo aquí
    std::cout << total << '\n';
}
  1. Clic en el margen izquierdo de la línea 5: aparece un punto rojo.
  2. F5 y elige C++ (GDB/LLDB). VS Code genera un launch.json.
  3. El programa se detiene en la línea 5 y el panel de variables muestra total e i. F5 otra vez avanza a la siguiente vuelta.

Hasta aquí llega R1. Los cuatro movimientos, la pila de llamadas y los puntos de interrupción condicionales son el contenido de R6.

Checkpoint

Colocas un punto de interrupción, presionas F5 y el punto rojo se vuelve un círculo gris y hueco. El programa corre de principio a fin sin detenerse. ¿Cuál es la causa más probable?

A. Sin -g el binario no guarda la correspondencia entre líneas del .cpp y direcciones de máquina, y el depurador no puede colocar la trampa. El círculo gris es el síntoma exacto. Una línea muerta (B) daría un punto rojo que nunca se alcanza, no uno gris, y la extensión (C) no interviene en eso.
R1 · Trampas comunes

Cuatro formas de que la tarea falle sin razón aparente

  • Rutas con espacios o acentos. C:\Users\José\Mi Programación\ rompe la tarea: el comando se parte donde hay un espacio y las letras acentuadas confunden a varias herramientas. Usa C:\dev\eda\ o ~/eda/.
  • Carpetas sincronizadas. OneDrive, iCloud y Dropbox bloquean archivos mientras suben y el enlazador falla al escribir el ejecutable.
  • Abrir el archivo en vez de la carpeta. Sin raíz de proyecto, VS Code no encuentra .vscode/tasks.json.
  • Ejecutar sin recompilar. Editas, corres el binario anterior y concluyes que el cambio no sirvió.

> Ejecutando tarea: /usr/bin/g++ -std=c++17 -Wall -Wextra -g
