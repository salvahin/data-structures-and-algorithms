R18 · Punto de partida

Este programa lee fuera del vector y no se queja


std::vector<int> v{10, 20, 30};

std::cout << "v[10] = " << v[10]     << '\n';
std::cout << "size  = " << v.size()  << '\n';
      

$ g++ -std=c++17 -Wall -Wextra fuera.cpp -o fuera && ./fuera
v[10] = 0
size  = 3

Ni el compilador ni el programa avisaron nada. v[10] leyó memoria que no le pertenece; en esta ejecución salió 0, en otra puede salir basura o abortar. Ese comportamiento tiene nombre y consecuencias, y lo vemos en el slide 10.

R18 · Operaciones básicas

Construir un vector y moverle elementos


std::vector<int> a;          // vacío
std::vector<int> b(5);       // 5 ceros
std::vector<int> c(5, 7);    // 5 sietes
std::vector<int> d{1, 2, 3}; // esos 3
std::vector<int> e(d);       // copia de d
          

d.push_back(4);   // agrega al final
d.pop_back();     // quita el último
d[0] = 99;        // acceso indexado
d.front();        // primer elemento
d.back();         // último
d.size();         // cuántos hay
d.empty();        // ¿ninguno?

pop_back() no devuelve nada: para usar el último elemento se lee con back() y después se quita. push_back y pop_back trabajan solo en el final, que es donde el vector es rápido.

Checkpoint

¿Qué contiene std::vector<int> v(3); justo después de construirse?

B. El constructor con un número crea esa cantidad de elementos, inicializados por omisión (0 para int). A describe lo que hace v.reserve(3), que aparta memoria sin crear elementos. C sería std::vector<int> v{3};, con llaves: la lista de inicialización enumera valores.
R18 · Size y capacity

Dos números que se confunden

size()capacity()
Qué mideElementos que existenEspacio reservado
Lo cambiapush_back, pop_back, resizeCrecer más allá del espacio, reserve
Índices válidos0 a size()-1No define índices válidos

Un vector guarda sus elementos en un bloque contiguo de memoria dinámica. La capacidad es el tamaño de ese bloque; el tamaño es cuánto de él está ocupado.

Leer v[i] con i entre size() y capacity() toca memoria del bloque que todavía no contiene ningún elemento construido. Es tan inválido como leer más allá del bloque.

Qué ocurre cuando ya no cabe

Reservar, copiar y liberar cuesta tiempo proporcional al número de elementos. Las direcciones de todos los elementos cambian.

R18 · Size y capacity

El bloque nuevo mide el doble


capacity observada al agregar 1000 enteros (g++ 11, libstdc++):

0  1  2  4  8  16  32  64  128  256  512  1024
  • Once reasignaciones para mil elementos. Si el bloque creciera de uno en uno serían 999, cada una copiando todo lo anterior.
  • Duplicar reparte el costo: mil push_back provocaron 1023 copias de elementos en total, menos de 1.1 copias por elemento. Por eso se dice que push_back cuesta \(O(1)\) amortizado.
  • El factor de crecimiento no lo fija el estándar: libstdc++ duplica, la biblioteca de MSVC multiplica por 1.5.
Checkpoint

Guardas int* p = &v[0]; y luego haces v.push_back(x), que provoca una reasignación. ¿Qué pasa con p?

A. La reasignación copia los elementos a un bloque nuevo y libera el viejo; todas las direcciones cambian. El vector no tiene forma de conocer los punteros que guardaste, así que no puede actualizarlos (B). Y no queda ningún elemento en el bloque anterior, ni siquiera el primero (C).
R18 · Acceso seguro

at() revisa el índice; [] no


std::vector<int> v{10, 20, 30};

v[7];        // sin revisión: lee lo que haya en esa dirección

try {
    std::cout << v.at(7) << '\n';
} catch (const std::out_of_range& e) {
    std::cout << "out_of_range: " << e.what() << '\n';
}
      

out_of_range: vector::_M_range_check: __n (which is 7)
              >= this->size() (which is 3)

at() lanza una excepción que puedes capturar. Sin try/catch termina el programa con un mensaje, mejor que un número inventado.

R18 · Iteradores

Recorrer sin índices


for (auto it = v.begin(); it != v.end(); ++it) {
    std::cout << *it << ' ';
}

for (int x : v)          std::cout << x << ' ';   // copia
for (const int& x : v)   std::cout << x << ' ';   // no copia

for (int& x : v)         x *= 2;   // modifica el vector
  • Un iterador señala una posición; *it da el elemento y ++it avanza. v.end() señala una posición después del último, así que nunca se desreferencia.
  • El ciclo range-for es la forma corta de lo mismo: el compilador lo traduce a begin/end. Se usa cuando no necesitas el índice.
Checkpoint

En for (int x : v) x *= 2;, ¿qué le pasa al vector?

C. Sin &, la variable del ciclo es una copia del elemento; modificarla no toca el vector. Compila sin problema y hasta sin advertencia con -Wall -Wextra (B). Para el efecto de A hay que escribir for (int& x : v).
R18 · Qué guardar adentro

Vector de objetos y vector de punteros


std::vector<Alumno> grupo;
grupo.push_back({"Ana", 9.1});

for (const Alumno& a : grupo)
    std::cout << a.nombre;

Los objetos viven dentro del bloque. Al crecer, se copian todos.


std::vector<Figura*> figuras;
figuras.push_back(new Circulo(2));

for (Figura* f : figuras)
    std::cout << f->area();

El bloque guarda direcciones. Al crecer se copian punteros, no objetos.

El vector de punteros es lo que necesita el polimorfismo de R16: un vector<Figura> recortaría la parte derivada de cada objeto. A cambio, delete queda a tu cargo: el vector destruye los punteros, no lo apuntado.

R18 · Iteradores invalidados

Modificar el vector mientras lo recorres


for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) v.erase(it);   // it queda inválido
}                                    // y ++it lo usa

for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) it = v.erase(it);  // erase devuelve
    else              ++it;              // el iterador válido
}

erase recorre los elementos siguientes una posición hacia la izquierda, así que el iterador que le pasaste deja de ser válido. Devuelve uno que sí lo es, apuntando al elemento que ocupó ese lugar; por eso el segundo ciclo no lleva ++it en la cabecera.

Checkpoint

Compilas el primer ciclo del slide anterior con -fsanitize=address y lo ejecutas. ¿Qué esperas ver?

B. El sanitizer instrumenta el programa y detecta el acceso inválido en ejecución, con la pila de llamadas del lugar exacto. Según los datos, el reporte llega como negative-size-param dentro del memmove que hace erase, o como heap-buffer-overflow al desreferenciar un iterador que se pasó de end(). Con ciertos datos el programa incluso termina sin reporte, que es lo que hace peligroso este error. Nada de esto se ve en compilación (C). Y erase devuelve un iterador válido, pero no modifica la variable it que tú declaraste (A).
R18 · Trampas comunes

Cuatro formas de perder media hora

  • Guardar un puntero, una referencia o un iterador a un elemento y seguir usándolo después de un push_back.
  • Borrar o insertar dentro de un range-for. Ese ciclo toma begin y end al empezar y no los vuelve a pedir.
  • Usar [] con un índice calculado y depurar el resultado extraño durante una hora. Cambiarlo a at() mientras desarrollas convierte el síntoma en un mensaje con el índice culpable.
  • Comparar v.size() con un int negativo. size() devuelve un tipo sin signo y la comparación convierte el negativo en un número enorme.
R18 · Ejercicio

Mide cómo crece la capacidad

  1. Escribe un programa que agregue mil enteros a un vector vacío e imprima el tamaño y la capacidad cada vez que la capacidad cambie.
  2. Cuenta cuántas reasignaciones ocurrieron y cuántos elementos se copiaron en total.
  3. Repite con v.reserve(1000) antes del ciclo y compara.

std::vector<int> v;
std::size_t cap = v.capacity();
std::cout << "size 0 -> capacity " << cap << '\n';
for (int i = 0; i < 1000; ++i) {
    v.push_back(i);
    if (v.capacity() != cap) {
        cap = v.capacity();
        std::cout << "size " << v.size()
                  << " -> capacity " << cap << '\n';
    }
}
        

size 0 -> capacity 0      size 17  -> capacity 32
size 1 -> capacity 1      size 33  -> capacity 64
size 2 -> capacity 2      size 65  -> capacity 128
size 3 -> capacity 4      size 129 -> capacity 256
size 5 -> capacity 8      size 257 -> capacity 512
size 9 -> capacity 16     size 513 -> capacity 1024

Las doce líneas de salida, acomodadas en dos columnas para que quepan. Salida real de g++ 11.4 -std=c++17 con libstdc++: once reasignaciones y 1023 elementos copiados para mil push_back. Con reserve(1000) el bloque se aparta una vez y ningún push_back reasigna. Otra implementación de la biblioteca estándar dará otra serie de números.
