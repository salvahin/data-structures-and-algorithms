Este constructor no compila


class Sensor {
    const int id;
public:
    Sensor(int i) { id = i; }
};

int main() { Sensor s(7); }
      

sensor.cpp:4:5: error: uninitialized const member in 'const int'
sensor.cpp:4:24: error: assignment of read-only member 'Sensor::id'

El código parece razonable: recibe un valor y lo guarda. El compilador dice dos cosas distintas sobre la misma línea, y ninguna de las dos habla de sintaxis.

R10 · Constructores

El método que corre al nacer el objeto

Un constructor tiene el mismo nombre que la clase y no declara tipo de retorno. Se ejecuta una sola vez, cuando el objeto entra en existencia, y su trabajo es dejar los campos en un estado válido.


class Punto {
    int x, y;
public:
    Punto() : x(0), y(0) {}           // por omisión
    Punto(int a, int b) : x(a), y(b) {}   // parametrizado
};

Si no escribes ningún constructor, el compilador genera uno por omisión que deja los int con basura. En cuanto escribes uno cualquiera, ese regalo desaparece y Punto p; deja de compilar.

R10 · Constructores

Varios constructores en la misma clase

Se distinguen por el número y tipo de parámetros. El compilador elige el que coincide con los argumentos de la declaración.


class Punto {
    int x, y;
public:
    Punto() : x(0), y(0) { std::cout << "Punto()\n"; }
    Punto(int a) : x(a), y(a) { std::cout << "Punto(" << a << ")\n"; }
    Punto(int a, int b) : x(a), y(b) {
        std::cout << "Punto(" << a << "," << b << ")\n";
    }
};

Punto a;          // Punto()
Punto b(5);       // Punto(5)
Punto c(1, 2);    // Punto(1,2)
Checkpoint

Una clase Fecha declara solo Fecha(int d, int m, int a). ¿Qué pasa con Fecha hoy;?

C. El compilador genera el constructor por omisión únicamente cuando la clase no declara ninguno. Al escribir el de tres parámetros lo pierdes, y Fecha hoy; no encuentra a quién llamar. A confunde este caso con el de una clase sin constructores, donde tampoco hay ceros sino basura. B describe parámetros con valor por omisión, que hay que escribir explícitamente.
R10 · Lista de inicialización

Inicializar y asignar son dos operaciones

Los dos puntos antes de la llave abren la lista de inicialización. Lo que ocurre ahí sucede antes de que empiece el cuerpo del constructor.


class ConCuerpo { Registro r; public: ConCuerpo() { r = Registro(7); } };
class ConLista  { Registro r; public: ConLista() : r(7) {} };
      

ConCuerpo:
  Registro()        <- construccion por omision del miembro
  Registro(7)       <- se construye un temporal
  operator=         <- se copia encima del miembro
ConLista:
  Registro(7)       <- un solo paso
R10 · Lista de inicialización

Por qué el ejemplo del arranque fallaba

  • Al entrar al cuerpo del constructor, todos los miembros ya están construidos. El cuerpo solo puede asignarles valores nuevos.
  • Un miembro const no admite asignación después de construido, y una referencia tampoco: hay que darles su valor en el momento de nacer.
  • Para esos dos casos la lista de inicialización es la única vía que existe en el lenguaje.

class Sensor {
    const int id;
public:
    Sensor(int i) : id(i) {}     // ahora si compila
};
Checkpoint

La clase tiene miembros int a, b; declarados en ese orden, y el constructor escribe Clase() : b(1), a(b + 1) {}. ¿Qué valor recibe a?

A. El orden de la lista de inicialización se ignora: los miembros se inicializan en el orden en que están declarados en la clase. Como a se declara primero, se construye leyendo un b que aún no existe. B es el error habitual de leer la lista como si fuera código secuencial. C supone una inicialización a cero que no ocurre con tipos básicos. Con -Wall -Wextra el compilador avisa con -Wreorder.
R10 · Destructor

El método que corre al morir el objeto

Se llama igual que la clase con una virgulilla delante, no recibe parámetros y no se puede sobrecargar. Cada clase tiene exactamente uno.


~Punto() { std::cout << "~Punto(" << x << "," << y << ")\n"; }

Se invoca solo, sin que nadie lo escriba, en tres momentos:

  • Cuando una variable local sale de su ámbito, es decir al cerrarse la llave donde se declaró.
  • Cuando termina el programa, para los objetos globales.
  • Cuando se libera con delete un objeto reservado con new (R13).
R10 · Destructor

El orden exacto, ejecutado


int main() {
    Punto a;
    Punto b(5);
    { Punto c(1, 2); }
    std::cout << "fin de main\n";
}
          

Punto()
Punto(5)
Punto(1,2)
~Punto(1,2)
fin de main
~Punto(5,5)
~Punto(0,0)

c muere en la línea 4, antes del mensaje final, porque su llave cierra ahí. a y b mueren al terminar main, en orden inverso al de construcción.

Checkpoint

Una función recibe un objeto por valor y hace return; a la mitad. ¿Cuántas veces corre el destructor de esa clase durante la llamada?

B. Pasar por valor construye una copia dentro de la función, y esa copia se destruye al salir. A ignora que la copia también es un objeto. C supone que un return temprano evita la destrucción; el lenguaje garantiza lo contrario, y sobre esa garantía se apoya el RAII de R13.
R10 · El puntero this

Dentro de un método, this es la dirección del objeto


class Contador {
    int valor;
public:
    Contador(int valor) {
        this->valor = valor;      // miembro = parametro
    }
    Contador& sumar(int n) {
        valor += n;
        return *this;             // devuelve el objeto actual
    }
};
Contador c(10);
c.sumar(5).sumar(3).imprimir();   // imprime 18

Los dos usos legítimos son estos: desambiguar cuando el parámetro se llama igual que el miembro, y devolver *this para encadenar llamadas. Escribir this-> delante de cada miembro sin necesidad solo agrega ruido.

R10 · Trampa clásica

Reloj r(); declara una función


int main() {
    Reloj r();       // una funcion r que no recibe nada
    r.hora();        //  y devuelve un Reloj
}
      

reloj.cpp:8:12: warning: empty parentheses were disambiguated
                as a function declaration [-Wvexing-parse]
reloj.cpp:9:7: error: request for member 'hora' in 'r',
               which is of non-class type 'Reloj()'

La gramática de C++ resuelve la ambigüedad a favor de la declaración de función. Se conoce como most vexing parse. La forma correcta es Reloj r; o Reloj r{};. Nota que el mensaje del constructor nunca se imprime: el objeto no llegó a existir.

Checkpoint

Tu clase imprime un mensaje en el constructor, pero al correr el programa no aparece nada. La línea es Matriz m();. ¿Qué ocurre?

C. Con los paréntesis vacíos la línea es una declaración de función y el constructor jamás se ejecuta. A es imposible: si escribiste un constructor, el compilador no genera otro. B describe un problema real de búfer, pero aquí el mensaje no existe porque nunca se produjo.
R10 · Trampas comunes

Cuatro formas de perder una tarde

  • Escribir MiClase obj(); y buscar el error en el constructor, cuando el objeto ni siquiera se creó.
  • Asignar en el cuerpo lo que corresponde a la lista de inicialización: compila para tipos básicos y falla para const, referencias y clases sin constructor por omisión.
  • Escribir la lista en un orden distinto al de declaración de los miembros y suponer que se respeta.
  • Dar al destructor un tipo de retorno o parámetros. La firma es fija: ~Clase() y nada más.
R10 · Ejercicio

Predice el orden de los mensajes


Sesion global("global");

int main() {
    Sesion a("a");
    {
        Sesion b("b");
        Sesion c("c", 2);
    }
    std::cout << "--- medio ---\n";
    Sesion d;
}

La clase Sesion tiene tres constructores —sin argumentos, con nombre, con nombre y prioridad— y un destructor; los cuatro imprimen su nombre. Escribe la salida completa antes de abrir la solución.


Sesion(global)
Sesion(a)
Sesion(b)
Sesion(c, 2)
~Sesion(c)        <- la llave interna cierra aqui
~Sesion(b)
--- medio ---
Sesion(sin nombre)
~Sesion(sin nombre)
~Sesion(a)
~Sesion(global)   <- despues de que main termina

Dos reglas explican toda la salida: los objetos mueren al cerrarse su llave, y dentro de un mismo ámbito mueren en orden inverso al de construcción. El global se construye primero y se destruye al final.
