R0 · Punto de partida

Este programa no genera ejecutable


#include <iostream>

int sumar(int a, int b);   // declarado aquí, definido en otro archivo

int main() {
    std::cout << sumar(2, 3) << '\n';
}
      

$ g++ main.cpp -o programa
/usr/bin/ld: undefined reference to `sumar(int, int)'
collect2: error: ld returned 1 exit status

El compilador aceptó el archivo sin una sola queja. El error viene de ld, un programa distinto que corre después.

R0 · Las tres etapas

De texto a ejecutable

El error de undefined reference aparece en la cuarta caja: el enlazador buscó el cuerpo de sumar entre los .o que recibió y no lo encontró.

R0 · Las tres etapas

Puedes detener el proceso en cada etapa


# 1. Solo preprocesar: imprime el archivo con los #include ya pegados
g++ -E main.cpp | wc -l          # ~30 000 líneas por incluir <iostream>

# 2. Solo compilar a ensamblador
g++ -S main.cpp                  # produce main.s

# 3. Compilar a objeto, sin enlazar
g++ -c main.cpp                  # produce main.o

# 4. Enlazar los objetos en un ejecutable
g++ main.o suma.o -o programa

Correr g++ -E main.cpp | wc -l una vez explica por qué compilar tarda: un archivo de siete líneas se convierte en decenas de miles.

Checkpoint

Escribes Estudiante e; pero olvidas incluir "estudiante.h". ¿Qué etapa reporta el error?

C. El preprocesador solo pega texto y no revisa nada: si no le pides que incluya el archivo, no se queja. El compilador procesa el resultado, encuentra un nombre que nunca vio declarado y falla ahí. El enlazador ni siquiera llega a ejecutarse.
R0 · Compilar por consola

El mismo comando en las tres plataformas

PlataformaCompiladorComando
macOSclang++clang++ -std=c++17 -Wall -Wextra -g main.cpp -o programa
Linux / WSLg++g++ -std=c++17 -Wall -Wextra -g main.cpp -o programa
Windows nativoMinGW g++g++ -std=c++17 -Wall -Wextra -g main.cpp -o programa.exe

Se ejecuta con ./programa en macOS, Linux y WSL, y con programa.exe en Windows.

R0 · Compilar por consola

Si usas Windows, instala WSL

  • Con wsl --install en PowerShell como administrador obtienes Ubuntu; después, sudo apt install build-essential gdb.
  • El curso entero (compilación, depurador, sanitizers, Makefile) usa las mismas herramientas que Linux y macOS.
  • Los tres entornos de Windows —MinGW, MSVC y WSL— producen mensajes de error distintos para el mismo problema, lo que dificulta pedir ayuda y seguir el material.
Recomendación del curso: WSL como opción por omisión en Windows.
R0 · Banderas

Qué hace cada bandera

BanderaEfectoPor qué importa
-std=c++17Fija la versión del lenguajeSin ella cada compilador elige una distinta
-WallActiva las advertencias comunesVariables sin inicializar, comparaciones sospechosas
-WextraAgrega advertencias adicionalesParámetros sin usar, comparaciones con signo
-gIncluye símbolos de depuraciónSin ella los breakpoints no funcionan (R6)

Una advertencia no detiene la compilación, así que es fácil ignorarla. Buena parte de los errores en ejecución ya estaban anunciados ahí.

R0 · Banderas

Una advertencia que anticipa una falla


int main() {
    int total;              // sin inicializar
    for (int i = 0; i < 5; i++) total += i;
    return total;
}
      

$ g++ -std=c++17 riesgo.cpp -o riesgo        # compila en silencio
$ g++ -std=c++17 -Wall riesgo.cpp -o riesgo
riesgo.cpp:3:38: warning: 'total' is used uninitialized [-Wuninitialized]

El programa corre en los dos casos y devuelve un número. Con -Wall sabes que ese número es basura.

Checkpoint

Compilas con g++ main.cpp -o app y el programa se comporta raro. Un compañero te dice que agregues -Wall. ¿Qué esperas que ocurra?

B. -Wall solo agrega diagnósticos; el ejecutable se genera igual. Para que las advertencias sí detengan la compilación existe -Werror. La optimización es otra bandera (-O2).
R0 · Compilación multiarchivo

Un programa en tres archivos


#pragma once
int sumar(int a, int b);
          

#include "suma.h"
int sumar(int a, int b) {
    return a + b;
}
          

#include <iostream>
#include "suma.h"

int main() {
    std::cout << sumar(2, 3) << '\n';
}
          

g++ -std=c++17 -Wall -Wextra -g main.cpp suma.cpp -o programa
R0 · Compilación multiarchivo

El error del arranque, explicado

  • #include "suma.h" le dice al compilador cómo se llama y qué firma tiene la función. Con eso basta para compilar main.cpp.
  • El cuerpo de la función vive en suma.cpp. Si no lo pasas al comando, el enlazador no tiene de dónde tomarlo.
  • undefined reference significa: alguien prometió que esta función existía y nadie la entregó.
Declarar es prometer que algo existe. Definir es entregarlo. El enlazador cobra las promesas.
R0 · Trampas comunes

Tres formas de perder media hora

  • Compilar sin -Wall y perseguir en el depurador un error que el compilador ya había señalado.
  • Olvidar un .cpp en el comando y leer undefined reference como si fuera un error de sintaxis.
  • Editar el archivo, no recompilar, y ejecutar el binario anterior. El programa "ignora" tus cambios porque estás corriendo otro programa.
R0 · Ejercicio

Compila tres archivos desde la terminal

  1. Crea suma.h, suma.cpp y main.cpp como en el slide anterior, en una carpeta sin espacios ni acentos.
  2. Compila a objetos por separado y enlaza después, en tres comandos.
  3. Provoca a propósito el undefined reference y luego arréglalo.

# compilación separada
g++ -std=c++17 -Wall -Wextra -g -c main.cpp     # -> main.o
g++ -std=c++17 -Wall -Wextra -g -c suma.cpp     # -> suma.o
g++ main.o suma.o -o programa
./programa                                       # 5

# el error, a propósito:
g++ main.o -o programa
# undefined reference to `sumar(int, int)'

La compilación separada es la base del Makefile de R11: al cambiar un solo archivo se recompila ese .o y se vuelve a enlazar.

Checkpoint

¿Cuál de estos errores no puede detectar el compilador al procesar un solo archivo?

A. El compilador ve un archivo a la vez y confía en las declaraciones. Que el cuerpo exista o no se resuelve al enlazar, cuando ya están todos los .o sobre la mesa. B y C se detectan con la información de ese archivo solo.
