R7 · Operaciones básicas

Crear y unir cadenas


#include <iostream>
#include <string>
int main() {
    std::string curso = "Estructuras";
    std::string tema  = "Datos";
    std::string todo = curso + " de " + tema;
    todo += " y Algoritmos";
    std::string linea(5, '-');
    std::cout << todo << '\n' << linea << '\n';
}
  • + crea una cadena nueva; += evita esa copia.
  • std::string linea(5, '-') repite un carácter.
  • Hay que incluir <string>: sin él solo funciona por accidente.
R7 · Operaciones básicas

Tamaño y trozos


std::string s = "Estructuras de Datos";
std::cout << s.size() << '\n';          // 20
std::cout << s.substr(0, 11) << '\n';   // Estructuras
std::cout << s.substr(15) << '\n';      // Datos
std::cout << s.front() << s.back();     // Es
std::cout << s.empty() << '\n';         // 0
  • Las posiciones empiezan en 0 y la última válida es s.size() - 1.
  • substr(inicio, cantidad): el segundo argumento es cuántos caracteres, no la posición final. Con un solo argumento copia hasta el final.
  • length() hace exactamente lo mismo que size(); el nombre size() es el que comparten todos los contenedores de la biblioteca.
Checkpoint

Con std::string s = "algoritmos";, ¿qué imprime s.substr(2, 4)?

A. Se empieza en la posición 2, que es la g porque la a ocupa la posición 0, y se toman cuatro caracteres: g, o, r, i. La opción B sale de leer el 4 como posición final en lugar de como cantidad de caracteres. La C sale de arrancar en la posición 1.
R7 · Búsqueda

find y el valor npos


std::string s = "estructuras de datos";
std::size_t p = s.find("datos");
if (p != std::string::npos)
    std::cout << "encontrado en " << p << '\n';   // 15
if (s.find("arbol") == std::string::npos) std::cout << "no aparece\n";
  • find devuelve la posición del primer carácter de la coincidencia, y std::string::npos cuando no hay ninguna.
  • npos es un valor sin signo enorme, así que find(...) > 0 es verdadero justo cuando la búsqueda fracasa.
  • Ese mismo detalle explica el segundo if del arranque: "estructuras" está en la posición 0, y 0 > 0 es falso.
R7 · Comparar y recorrer

Comparación y recorrido carácter por carácter


std::string a = "casa", b = "Casa";
if (a == b) std::cout << "iguales\n";      // no entra
if (b < a)  std::cout << "Casa antes\n";   // 'C'=67, 'c'=99
// recorrido por indice
for (std::size_t i = 0; i < a.size(); i++)
    std::cout << a[i] << '-';              // c-a-s-a-
// recorrido por rango
for (char c : a) std::cout << c;           // casa
  • == compara contenido; < compara en orden lexicográfico usando el código de cada carácter, así que las mayúsculas van antes que las minúsculas.
  • a[i] no revisa el rango. a.at(i) sí, y lanza una excepción si te pasas.
Checkpoint

¿Cuál es la forma correcta de preguntar si "nodo" aparece dentro de texto?

C. A falla dos veces: da verdadero cuando no hay coincidencia, porque npos es un número enorme, y da falso cuando la coincidencia está en la posición 0. B da el resultado correcto, porque npos se define como size_type(-1) y el literal se convierte a ese mismo valor, pero mezcla tipos con y sin signo, dispara -Wsign-compare y oculta la intención. Comparar contra std::string::npos dice en el código lo que se está preguntando.
R7 · string frente a char*

Lo que cambia al dejar char*


const char* a = "hola";
const char* b = "hola";
a == b;              // compara direcciones
std::strcmp(a, b);   // compara contenido
std::strlen(a);      // recorre hasta el '\0'
// concatenar exige reservar espacio a mano
          

std::string x = "hola";
std::string y = "hola";
x == y;              // compara contenido
x.size();            // dato guardado
x += " mundo";       // crece sola
  • Una cadena de C es un arreglo de char terminado en '\0'; quien la usa administra su memoria.
  • std::string guarda su tamaño, ajusta su capacidad al crecer y libera su memoria al salir de ámbito. En este curso se usa siempre.
Checkpoint

Con const char* a = "hola"; y const char* b = "hola";, ¿qué compara a == b?

B. a y b son punteros, y == entre punteros compara direcciones. El resultado depende de si el compilador decidió guardar los dos literales iguales en el mismo lugar, así que a veces da verdadero y a veces falso. Para comparar contenido en C se usa std::strcmp. Con std::string el operador == sí compara los caracteres.
R7 · Espacios de nombres

Qué problema resuelven


// lista.h  (biblioteca de listas)
struct Nodo { int dato; Nodo* siguiente; };
void imprimir(const Nodo* n);
// arbol.h  (biblioteca de arboles)
struct Nodo { int dato; Nodo* izq; Nodo* der; };
void imprimir(const Nodo* n);

Incluir los dos en el mismo .cpp produce redefinition of 'struct Nodo', y ninguna biblioteca puede renombrar sus tipos.

Un espacio de nombres agrega un prefijo a cada nombre, así que lista::Nodo y arbol::Nodo conviven.

R7 · Espacios de nombres

Definir uno y usarlo


namespace geometria {
    const double PI = 3.14159265;
    double area(double r) { return PI * r * r; }
}
namespace fisica {
    double area(double b, double h) { return b * h; }
}
int main() {
    std::cout << geometria::area(2.0) << '\n';   // 12.5664
    std::cout << fisica::area(3.0, 4.0) << '\n'; // 12
}
  • El bloque namespace no lleva punto y coma final y puede reabrirse en varios archivos.
  • :: elige de qué espacio viene el nombre.
R7 · Espacios de nombres

using namespace std;: dónde sí y dónde no


#pragma once
#include <string>
using namespace std;      // viaja a todo .cpp que lo incluya
string saludo();
      

main.cpp:8:5: error: reference to 'count' is ambiguous
[...]
note: candidates are: 'template<...> std::count(...)'
note:                 'int count'
  • Quien incluya util.h recibe todos los nombres de std sin pedirlos, y su variable count deja de compilar.
  • En un .cpp el efecto termina ahí. En un header, nunca.
Checkpoint

¿Por qué using namespace std; es peor en un .h que en un .cpp?

A. El preprocesador pega el contenido del header en cada .cpp que lo incluye, de modo que la directiva viaja con él y puede provocar ambigüedades en código ajeno. B confunde una instrucción del compilador con código ejecutable: using no genera ninguna instrucción. C describe los headers precompilados, que son otro mecanismo y no evitan el problema.
R7 · Trampas comunes

Cuatro errores que aparecen siempre

  • Usar find sin comparar contra npos. El resultado es de tipo sin signo y cualquier comparación con > 0 o >= 0 da lo contrario de lo que esperas.
  • Leer el segundo argumento de substr como posición final. Es una cantidad de caracteres.
  • Comparar char* con == y creer que compara contenido.
  • Indexar con s[s.size()]. Esa posición está fuera del contenido; el último carácter es s[s.size() - 1].
R7 · Ejercicio

Contar palabras y voltear una cadena

  1. Escribe int contarPalabras(const std::string& s) que cuente grupos de caracteres separados por espacios, tolerando espacios repetidos.
  2. Escribe std::string voltear(const std::string& s) que devuelva la cadena invertida.
  3. Usa solo size, operator[] y +=. Nada de <algorithm>.

int contarPalabras(const std::string& s) {
    int n = 0; bool dentro = false;
    for (char c : s) {
        if (c == ' ') dentro = false;
        else if (!dentro) { dentro = true; n++; }
    }
    return n;
}
std::string voltear(const std::string& s) {
    std::string r;
    for (std::size_t i = s.size(); i > 0; i--)
        r += s[i - 1];
    return r;
}

El índice de voltear baja desde s.size() y se lee s[i - 1]. Escribirlo como for (std::size_t i = s.size() - 1; i >= 0; i--) produce un ciclo infinito, porque un size_t nunca es negativo.
