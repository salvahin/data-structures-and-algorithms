3.2.1 Plantear la recurrencia

3.2.1 · Plantear la recurrencia

De código a ecuación


int buscar(const vector<int>& v, int lo, int hi, int x) {
    if (lo > hi) return -1;             // caso base: costo constante
    int m = lo + (hi - lo) / 2;
    if (v[m] == x) return m;            // trabajo propio: constante
    if (v[m] < x) return buscar(v, m + 1, hi, x);   // un subproblema
    return buscar(v, lo, m - 1, x);                 //   de tamaño n/2
}
  • El costo de la llamada es el trabajo propio más el costo de las llamadas internas, sobre entradas más chicas.
  • Eso da una recurrencia: \(T(n) = T(n/2) + c\), con caso base \(T(0) = c\), que es el return de la primera línea.
3.2.1 · Plantear la recurrencia

La forma divide y vencerás

\[ T(n) = a\,T(n/b) + f(n) \]
  • \(a\) — cuántos subproblemas genera cada llamada.
  • \(b\) — entre cuánto se divide el tamaño en cada subproblema.
  • \(f(n)\) — el trabajo propio de la llamada: dividir, combinar, comparar.
  • Búsqueda binaria: \(a = 1,\; b = 2,\; f(n) = c\). Merge sort: \(a = 2,\; b = 2,\; f(n) = \Theta(n)\) — dos mitades y una fusión lineal.
  • Si \(n\) no se divide exacto, los tamaños reales son \(\lfloor n/b \rfloor\) y \(\lceil n/b \rceil\). Escribimos \(n/b\) porque ese redondeo no cambia la cota.
3.2.1 · Plantear la recurrencia

Recurrencias con resta

  • Cuando la llamada reduce el problema en 1 en lugar de dividirlo: \(T(n) = T(n-1) + f(n)\).
  • Con \(f(n) = c\) (factorial): \(T(n) = c\,n \to \Theta(n)\). Se desenrolla como una suma de \(n\) términos constantes.
  • Con \(f(n) = c\,n\) (procesar todo el arreglo antes de recursar): \(T(n) = c\bigl(n + (n-1) + \cdots + 1\bigr) \to \Theta(n^{2})\). La sumatoria aritmética de la sesión pasada.
  • Restar y dividir producen mundos distintos: \(T(n) = T(n-1) + c\) es lineal y \(T(n) = T(n/2) + c\) es logarítmica. La recurrencia registra esa diferencia desde el planteamiento.
Checkpoint

Merge sort divide el arreglo en dos mitades, ordena cada una recursivamente y las fusiona en tiempo lineal. ¿Su recurrencia?

A. Dos subproblemas (\(a = 2\)) de la mitad del tamaño (\(b = 2\)), más la fusión lineal como \(f(n)\). La opción B es búsqueda binaria (un solo subproblema, trabajo constante) y la C es el patrón de "quitar un elemento y procesar el resto", que resuelve a \(\Theta(n^{2})\).

3.2.2 Resolver la recurrencia

3.2.2 · Método de sustitución

Desenrollar hasta ver el patrón

\[ \begin{aligned} T(n) &= T(n/2) + c \\ &= T(n/4) + 2c \\ &= T(n/8) + 3c \\ &= T(n/2^{k}) + k\,c && \text{tras } k \text{ pasos} \\ &= T(1) + c \log_2 n && \text{con } k = \log_2 n \end{aligned} \]
  • Se sustituye la recurrencia dentro de sí misma, lo cual es legal porque la ecuación vale para cualquier tamaño, no solo para \(n\).
  • ¿De dónde sale \(k = \log_2 n\)? El caso base se alcanza cuando \(n/2^{k} = 1\); al despejar \(k\) queda el logaritmo.
  • Resultado: \(T(n) = \Theta(\log n)\). El término \(T(1)\) es una constante y la notación lo absorbe, igual que a \(c\).
3.2.2 · Árbol de recursión

\(T(n) = 2T(n/2) + cn\), nivel por nivel

3.2.2 · Árbol de recursión

Cuántas hojas tiene el árbol

Con \(a\) llamadas de tamaño \(n/b\), el conteo por niveles es el mismo:

NivelSubproblemasTamaño de cada uno
01\(n\)
1\(a\)\(n/b\)
\(k\)\(a^{k}\)\(n/b^{k}\)
\[ n/b^{k} = 1 \;\Longrightarrow\; k = \log_b n \;\Longrightarrow\; \text{hojas} = a^{\log_b n} = n^{\log_b a} \]

Ese \(n^{\log_b a}\) es el costo agregado de las hojas, y es contra lo que se compara \(f(n)\).

3.2.2 · Teorema Maestro

Cómo se decide, paso a paso

Toda la decisión es una comparación entre dos cantidades: el costo de las hojas, \(n^{\log_b a}\), y el trabajo propio \(f(n)\).

  • 1. Identifica \(a\), \(b\) y \(f(n)\). En \(T(n) = 8T(n/2) + n^{2}\): \(a = 8\), \(b = 2\), \(f(n) = n^{2}\).
  • 2. Calcula el costo de las hojas. \(\log_2 8 = 3\), así que las hojas cuestan \(n^{3}\).
  • 3. Compara y lee el caso. \(n^{2}\) crece menos que \(n^{3}\): mandan las hojas, es el caso 1 y da \(\Theta(n^{3})\).
3.2.2 · Teorema Maestro

Los tres casos

CasoComparaciónResultadoEjemplo
1\(f(n)\) crece menos\(\Theta(n^{\log_b a})\)\(4T(n/2)+n\): \(n\) contra \(n^{2}\) → \(\Theta(n^{2})\)
2crecen igual\(\Theta(n^{\log_b a} \log n)\)\(2T(n/2)+n\): \(n\) contra \(n\) → \(\Theta(n \log n)\)
3\(f(n)\) crece más\(\Theta(f(n))\)\(2T(n/2)+n^{3}\): \(n^{3}\) contra \(n\) → \(\Theta(n^{3})\)

En la columna del ejemplo, el primer término es \(f(n)\) y el segundo el costo de las hojas.

3.2.2 · Teorema Maestro

Dónde se concentra el costo

Cada triángulo es el árbol de recursión, con la parte sombreada aportando casi todo el costo. Saber cuál de los tres es te dice dónde optimizar.

3.2.2 · Teorema Maestro

Cuándo aplica y cuándo no

  • La comparación debe ser por un factor polinomial, alguna potencia \(n^{\varepsilon}\). Entre \(n^{2}\) y \(n\) el factor es \(n\), que sí lo es.
  • \(T(n) = 2T(n/2) + n\log n\) cae en el hueco entre los casos 2 y 3: el factor es \(\log n\), que se queda corto frente a cualquier potencia.
  • Con \(n = 10^{6}\): \(\log_2 n \approx 20\), mientras \(n^{0{,}1} = 4\) y \(n^{0{,}5} = 1000\). El teorema no decide este caso; el árbol de recursión sí.
3.2.2 · Teorema Maestro

Y si no aplica, qué usar

  • El caso 3 pide además regularidad: que al bajar un nivel el trabajo se reduzca en una fracción fija, \(a\,f(n/b) \le k\,f(n)\) con \(k < 1\). Se cumple en todo lo que verán en el curso.
  • Tampoco aplica a recurrencias con resta — \(T(n) = T(n-1) + f(n)\) se resuelve desenrollando, como hicimos.
  • Orden de herramientas en la práctica: Teorema Maestro si la forma encaja; árbol de recursión para entender o para los casos raros; inducción para formalizar.
Checkpoint

\(T(n) = 4T(n/2) + n\). ¿Qué dice el Teorema Maestro?

B. \(\log_2 4 = 2\), así que las hojas aportan \(n^{2}\), que crece polinomialmente más que \(f(n) = n\): caso 1. El error típico es mirar solo la \(f(n)\) visible en el código y olvidar que el número de hojas se multiplica por \(a\) en cada nivel — aquí hay \(4^{k}\) subproblemas en el nivel \(k\).

Ejercicios · Torres de Hanói

El problema

  • Tres postes. En el primero hay \(n\) discos de distinto tamaño, apilados del más grande abajo al más chico arriba.
  • Objetivo: dejar la torre completa en el tercer poste, en el mismo orden.
  • Regla 1: se mueve un solo disco a la vez, y siempre el de hasta arriba de un poste.
  • Regla 2: nunca puede quedar un disco sobre otro más chico.
  • El poste de en medio no es un adorno: sirve de espacio temporal, y es lo que hace posible la solución.

Ejercicios · Torres de Hanói

De los tres bloques a la ecuación

Llama \(T(n)\) al número de movimientos que hace falta para pasar una torre de \(n\) discos de un poste a otro.


void hanoi(int n, char origen, char aux, char destino) {
    if (n == 0) return;                        // T(0) = 0
    hanoi(n - 1, origen, destino, aux);        // bloque 1: T(n-1)
    mover(origen, destino);                    // el grande: 1 movimiento
    hanoi(n - 1, aux, origen, destino);        // bloque 3: T(n-1)
}
\[ T(n) = \underbrace{T(n-1)}_{\text{bloque 1}} + \underbrace{1}_{\text{el grande}} + \underbrace{T(n-1)}_{\text{bloque 3}} = 2T(n-1) + 1 \]
Ejercicios · Torres de Hanói

La ecuación reproduce lo que contamos

DiscosCuentaMovimientos
\(n = 1\)\(2 \cdot T(0) + 1 = 2 \cdot 0 + 1\)\(T(1) = 1\)
\(n = 2\)\(2 \cdot T(1) + 1 = 2 \cdot 1 + 1\)\(T(2) = 3\)
\(n = 3\)\(2 \cdot T(2) + 1 = 2 \cdot 3 + 1\)\(T(3) = 7\)
\(n = 4\)\(2 \cdot T(3) + 1 = 2 \cdot 7 + 1\)\(T(4) = 15\)

Esos 7 son exactamente los movimientos de la simulación, así que la ecuación resume el conteo que ya hiciste a mano.

Ejercicios · Torres de Hanói

Restar el tamaño, duplicar las llamadas

\[ \begin{aligned} T(n) &= 2T(n-1) + 1 \\ &= 4T(n-2) + 2 + 1 \\ &= 8T(n-3) + 4 + 2 + 1 \\ &= 2^{k}T(n-k) + 2^{k} - 1 \;\;\longrightarrow\;\; T(n) = 2^{n} - 1 \end{aligned} \]
  • El caso base llega con \(k = n\), donde \(T(0) = 0\): queda \(2^{n} \cdot 0 + 2^{n} - 1\).
  • La suma \(1 + 2 + 4 + \cdots + 2^{\,n-1}\) es la geométrica de la sesión 3. Son \(2^{n} - 1\) movimientos exactos, y además es el mínimo posible: ninguna estrategia lo hace con menos.
  • Con 64 discos y un movimiento por segundo: unos 585 mil millones de años. La cota exponencial no es pesimismo teórico; es el conteo exacto.
Ejercicios · Fibonacci ingenuo

Cuando ninguna de las tres herramientas encaja

  • \(T(n) = T(n-1) + T(n-2) + c\) no divide el tamaño, así que el Teorema Maestro queda fuera; y al desenrollarla no aparece un patrón limpio.
  • La salida es encerrarla entre dos recurrencias que sí sabemos resolver, cambiando el término chico por el grande y al revés:
    \[ \underbrace{2T(n-2)}_{\text{cota inferior}} \;\le\; T(n) \;\le\; \underbrace{2T(n-1)}_{\text{cota superior}} \;\Longrightarrow\; 2^{\,n/2} \lesssim T(n) \lesssim 2^{\,n} \]
  • Queda atrapada entre \(1.41^{\,n}\) y \(2^{\,n}\). El valor exacto es \(\varphi^{\,n}\) con \(\varphi \approx 1.618\), porque las llamadas obedecen la misma recurrencia que Fibonacci.
Ejercicios · Fibonacci ingenuo

Lo que cuesta esa base 1.618

  • El diagnóstico visual de la sesión 2 — subproblemas repetidos por todo el árbol — hoy tiene número: fib(50) ingenuo hace más de \(4 \times 10^{10}\) llamadas.
  • Y todo eso para calcular 50 valores distintos. Cada uno se recalcula miles de millones de veces.
  • Ese desperdicio es exactamente lo que elimina la técnica que sigue.
Checkpoint

¿Por qué Hanói es \(\Theta(2^{n})\) si merge sort, que también hace dos llamadas, es \(\Theta(n \log n)\)?

C. Ambos duplican las llamadas por nivel; la diferencia está en cuántos niveles hay. Dividir entre 2 da \(\log_2 n\) niveles (\(2^{\log_2 n} = n\) hojas); restar 1 da \(n\) niveles (\(2^{n}\) hojas). El trabajo propio de Hanói es constante — más chico que el de merge sort — y aun así pierde: la profundidad manda.

Memoización

Memoización · La idea

Calcular cada subproblema una sola vez

  • Memoizar es guardar el resultado de cada subproblema la primera vez que se calcula, y devolver el valor guardado en las llamadas siguientes.
  • La recursión queda idéntica; solo se le antepone una consulta a la caché. Por eso es la optimización menos invasiva que existe: se agrega, no se rediseña.
  • El costo pasa a ser número de subproblemas distintos × costo de combinar cada uno. En fib: \((n+1) \times O(1) = O(n)\).
Memoización · Implementación

fib con std::unordered_map


std::unordered_map<int, long long> cache;

long long fib(int n) {
    if (n <= 1) return n;
    auto it = cache.find(n);
    if (it != cache.end())
        return it->second;                // ya calculado: no se recalcula
    long long r = fib(n - 1) + fib(n - 2);
    cache[n] = r;                         // guardar antes de devolver
    return r;
}
  • Con claves enteras densas como aquí, un std::vector indexado por \(n\) es más simple y más rápido que el mapa.

Checkpoint

¿Qué determina la complejidad de una recursión memoizada?

A. Cada subproblema distinto se calcula una vez; el resto son consultas \(O(1)\). En fib eso da \((n+1) \times O(1) = O(n)\) — un cambio de exponente, no de constante, al contrario de la opción C. La profundidad de la pila sigue siendo \(O(n)\) en fib: la memoización reduce el número de llamadas, no la longitud de la rama más profunda.
Por qué importa hoy

El all-reduce que entrena a los LLM

Para sincronizar gradientes entre \(p\) GPUs, el all-reduce existe en dos variantes, y elegir entre ellas es análisis de recurrencias:

VariantePasosGana en
En árbol\(O(\log p)\)latencia (mensajes chicos)
En anillo\(2(p-1)\)ancho de banda (mensajes grandes)
  • El árbol es la forma de divide y vencerás: combinar por mitades en \(\log p\) rondas.
  • El anillo da más pasos, pero cada GPU transmite en total una cantidad de datos casi óptima; por eso NCCL lo usa para los tensores grandes del entrenamiento.
Cierre STL

std::stable_sort: la recurrencia depende de la memoria

  • En libstdc++, libc++ y MSVC, stable_sort es un merge sort adaptativo.
  • Si consigue el buffer auxiliar de \(O(n)\), aplica la recurrencia de hoy: \(T(n) = 2T(n/2) + \Theta(n) \to O(n \log n)\).
  • Si no hay memoria, fusiona in situ con rotaciones: la fusión pasa a \(\Theta(n \log n)\) por nivel y el total degrada a \(O(n \log^{2} n)\), donde \(\log^{2} n\) significa \((\log n)^{2}\).
  • El estándar escribe ambas con \(O\) porque promete un techo; el análisis de hoy da la cota ajustada, \(\Theta\).
Cierre STL

std::sort es introsort: la profundidad como alarma

  • Introsort arranca como quicksort y monitorea la profundidad de su propia recursión: si supera \(\approx 2\log_2 n\), cambia a heapsort; para tramos chicos remata con insertion sort.
  • La lógica es puro análisis de recurrencias: una recursión de quicksort más profunda que \(\log n\) delata que las particiones están saliendo desbalanceadas — el camino al peor caso \(O(n^{2})\).
  • Nada de esto lo exige el estándar (solo pide \(O(n \log n)\) peor caso desde C++11); es la decisión de implementación con la que las tres bibliotecas lo cumplen.
