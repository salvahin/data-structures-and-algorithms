5.5 Quick Sort

5.5 · Quick Sort

Divide y vencerás, con el trabajo antes de dividir

  • Particionar: elegir un pivote y reacomodar el arreglo: menores a la izquierda, mayores a la derecha. El pivote queda en su posición final. Costo Θ(n).
  • Recursar: ordenar las dos zonas por separado. No hay paso de combinación: al terminar las recursiones, el arreglo está ordenado.
  • Comparación con Merge Sort: allá el trabajo está en combinar después de la recursión; acá está en particionar antes. Ambos hacen Θ(n) por nivel.

Todo el análisis de hoy cuelga de una pregunta: ¿qué tan balanceadas quedan las dos zonas?

5.5 · Quick Sort

Qué es el pivote y qué significa particionar

  • Dentro de cada zona el orden da igual: cualquier acomodo así es válido.
  • El pivote queda en su lugar definitivo y las recursiones ya no lo tocan.
  • Con dos arreglos extra esto es fácil. El reto es hacerlo dentro del mismo arreglo y en una pasada: eso son Lomuto y Hoare.
5.5 · Quick Sort

Lomuto paso a paso

5.5 · Quick Sort

Partición de Lomuto


int particionLomuto(std::vector<int>& a, int lo, int hi) {
    int p = a[hi];                  // pivote: el último elemento
    int i = lo;                     // frontera de la zona de menores
    for (int j = lo; j < hi; ++j) {
        if (a[j] < p) {
            std::swap(a[i], a[j]);  // a[j] entra a la zona de menores
            ++i;
        }
    }
    std::swap(a[i], a[hi]);         // el pivote cae en su posición final
    return i;
}

Invariante del ciclo: a[lo..i−1] < p y a[i..j−1] ≥ p. Una pasada, a lo más n−1 intercambios.

5.5 · Quick Sort

El algoritmo completo


void quickSort(std::vector<int>& a, int lo, int hi) {
    if (lo >= hi) return;
    int p = particionLomuto(a, lo, hi);
    quickSort(a, lo, p - 1);    // menores que el pivote
    quickSort(a, p + 1, hi);    // mayores o iguales
}
  • El pivote no entra en ninguna recursión: ya está en su lugar. Cada llamada reduce el problema en al menos un elemento — por eso termina.
  • Ordena en sitio (O(log n) de pila en el buen caso) y no es estable: los swaps de la partición saltan por encima de elementos iguales.
5.5 · Quick Sort

Hoare paso a paso

Partición original de Hoare, Algorithm 63/64, CACM 4(7), 1961.

5.5 · Quick Sort

La partición original: Hoare


int particionHoare(std::vector<int>& a, int lo, int hi) {
    int p = a[lo + (hi - lo) / 2];      // pivote: elemento central
    int i = lo - 1, j = hi + 1;
    while (true) {
        do { ++i; } while (a[i] < p);   // avanza desde la izquierda
        do { --j; } while (a[j] > p);   // retrocede desde la derecha
        if (i >= j) return j;           // los índices se cruzaron
        std::swap(a[i], a[j]);
    }
}
  • Dos índices avanzan desde los extremos e intercambian pares mal colocados: en promedio, tres veces menos intercambios que Lomuto.
  • Devuelve una frontera j con [lo..j] y [j+1..hi] particionados; el pivote no queda en su posición final.
5.5 · Quick Sort

Lo que devuelve cada una no es lo mismo

Cambiar de partición obliga a cambiar los rangos de la recursión: con Lomuto y (lo, p) el pivote vuelve a entrar y con {1,2,3} se cicla; con Hoare y (j+1, hi) saltándose j, {2,3,1} sale como {2,1,3}.

Checkpoint

Tras ejecutar la partición de Lomuto, ¿qué es lo único que se garantiza?

B. La partición coloca un elemento (el pivote) en su lugar definitivo y separa el resto en dos zonas, cada una internamente desordenada — ordenarlas es trabajo de las recursiones (A). Y el tamaño de las zonas depende del valor del pivote (C): que quede cerca de la mediana es justo lo que las estrategias de pivote intentan conseguir, no algo garantizado.

Estrategias de pivote: qué gana y qué arriesga cada una

EstrategiaLo que ganaLo que arriesga
Último o primeroCero costo extra; es la del código de hoyO(n²) con datos ordenados o casi ordenados, que son los más comunes
Elemento centralIgual de barata y sobrevive a los ordenadosSigue siendo fácil construir la entrada que la hunde
Mediana de tresParticiones más parejas en promedio; inmune a ordenados e inversosTres comparaciones por llamada, y existe el "median-of-3 killer"
AleatorioNinguna entrada fija es mala: O(n log n) esperado, demostrableCuesta generar el número y dos corridas no se comportan igual
Vigilar profundidad (introsort)Garantiza O(n log n) también en el peor casoMás código y hay que elegir el umbral

Las primeras cuatro apuestan a que el pivote salga bueno; la última deja de apostar y pone una red por debajo. Por eso std::sort combina aleatoriedad o mediana de tres con el cambio a heapsort.

Checkpoint

Quick Sort con pivote = primer elemento recibe un arreglo ya ordenado. ¿Qué complejidad tiene?

A. Con la entrada ordenada, el primer elemento siempre es el mínimo: la partición queda totalmente desbalanceada y la recurrencia es T(n) = T(n−1) + Θ(n) = Θ(n²). La opción B confunde con Insertion o Bubble optimizado — quick sort no detecta el orden. La C confunde el caso promedio con una garantía: el peor caso existe, y ocurre justo con datos comunes.

Material extra · autoestudio

Quickselect: encontrar el k-ésimo menor sin ordenar. No se cubre en clase; lo necesitas para el reto en parejas y para la Act 1.5.

Quickselect

El k-ésimo menor, con la mitad del trabajo

Quickselect

Codificación y análisis


int quickselect(std::vector<int>& a, int lo, int hi, int k) {
    if (lo == hi) return a[lo];
    int p = particionLomuto(a, lo, hi);
    if      (k == p) return a[k];
    else if (k < p)  return quickselect(a, lo, p - 1, k);
    else             return quickselect(a, p + 1, hi, k);
}
  • Costo esperado con particiones razonables: n + n/2 + n/4 + … ≤ 2n → O(n) promedio.
  • Peor caso Θ(n²), heredado de la partición desbalanceada; con pivote aleatorio es improbable.
  • Ordenar todo cuesta O(n log n); quickselect responde en O(n).
Checkpoint

¿Por qué quickselect es O(n) promedio mientras Quick Sort es O(n log n)?

C. Ambos usan la misma partición (A); la diferencia es cuántas ramas siguen vivas. Quick Sort procesa las dos zonas (todos los niveles cuestan n en total); quickselect descarta una zona completa en cada paso y la serie geométrica converge a 2n. La opción B lo confunde con búsqueda binaria: quickselect trabaja precisamente sobre datos desordenados.

Por qué importa hoy

Top-k: la operación central de la recuperación

  • Un sistema de recuperación tiene un millón de documentos con puntaje de similitud y debe devolver los 5 mejores.
  • Ordenar el millón completo cuesta O(n log n) — y tira a la basura el orden de 999 995 elementos que nadie pidió.
  • Quickselect —el material extra del final— coloca los k mejores en tiempo O(n) promedio. Para flujos continuos, la alternativa es un heap de tamaño k (lo veremos en el bloque de árboles).
  • Cada vez que un chatbot con RAG recupera contexto, hay una selección por partición o un heap ejecutándose detrás.
STL

Selección en la biblioteca estándar


// los k mejores al frente, sin orden interno garantizado: O(n) promedio
std::nth_element(v.begin(), v.begin() + k, v.end(),
                 [](auto& a, auto& b){ return a.score > b.score; });
// v[0..k) son los k mejores; v[k] es el k-ésimo

// los k mejores, además ordenados entre sí: O(n log k)
std::partial_sort(v.begin(), v.begin() + k, v.end());
  • std::nth_element es la versión de biblioteca de ese material extra: selección por partición: introselect en la práctica, con respaldo por heapselect.
  • std::partition y std::stable_partition exponen la partición como algoritmo independiente.
  • Para los k mejores, std::sort hace trabajo de más.
