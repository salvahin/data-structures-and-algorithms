La idea: restringir una lista

La idea

La misma lista, con menos puertas


// LinkedList: se llega a cualquier nodo
insert(x, pos);
remove(x);
find(x);
print();
          

// Pila: solo se llega al de arriba
push(x);
pop();
top();
empty();
  • Por dentro, una pila es la lista de la sesión 12: nodos, next y un puntero al primero.
  • Lo que cambia es la parte public. Al quitar operaciones, la clase garantiza un orden de salida que la lista no garantiza.

7.2 Pilas (Stack)

7.2 · Pilas

Un bote de papas

7.2 · Pilas

LIFO: el último en entrar es el primero en salir

OperaciónEn el boteCosto
push(x)Meter una papa por arribaO(1)
pop()Sacar la de arriba y devolverlaO(1)
top()Ver la de arriba sin sacarlaO(1)
empty()¿Queda alguna?O(1)

No existe una operación para leer la papa 2 o sacar la del fondo. Esa ausencia es la que asegura el orden de salida.

7.2 · Pilas

La restricción, en el código


template <typename T>
class Pila {
    // struct Nodo: el mismo de LinkedList en la sesion 12
    Nodo* tope;                   // privado: nadie lo toca desde fuera
public:
    Pila() { tope = nullptr; }
    void push(T x);
    T    pop();
    T    top()   { return tope->dato; }
    bool empty() { return tope == nullptr; }
    // no hay insert(x, pos), remove(x) ni find(x)
};

Las paredes del bote son private: desde fuera de la clase no se puede escribir p.tope->next. El compilador rechaza el código que intente llegar al fondo.

7.2 · Pilas

push y pop ya los escribiste


void push(T x) {
    Nodo* nuevo = new Nodo(x);
    nuevo->next = tope;
    tope = nuevo;
}

Es insert(x, 0): el caso de la cabeza.


T pop() {
    if (empty()) return T();   // vacia
    Nodo* victima = tope;
    T x = victima->dato;
    tope = tope->next;
    delete victima;
    return x;
}

Es remove de la cabeza, más devolver el dato.

El if evita leer tope->dato de un nullptr. T() es el valor por omisión: 0 para int.

7.2 · Pilas

La pila, nodo por nodo

Checkpoint

Sobre una pila vacía: push(1); push(2); push(3); pop(); push(4); pop(); pop(); ¿En qué orden salieron los elementos?

A. Después de los tres push, arriba está el 3: sale. Entra el 4 encima del 2 y sale el 4. Queda el 2 encima del 1: sale el 2. La B es el orden de una fila. La C olvida que el 2 sigue encima del 1.
7.2 · Pilas

Dónde aparece una pila

  • Deshacer: la última acción es la primera que se revierte.
  • Balanceo de símbolos: cada ( se apila; cada ) debe cerrar la que está arriba.
  • Evaluación de expresiones: los operandos esperan en la pila hasta que llega su operador.
  • La pila de llamadas: cada llamada recursiva de la sesión 2 apila su marco y lo saca al regresar.

En todos hay tareas anidadas, y siempre se resuelve primero la más reciente.

7.3 Filas (Queue)

7.3 · Filas

La fila de las tortillas

7.3 · Filas

FIFO: el primero en llegar es el primero en salir

OperaciónEn la tortilleríaCosto
enqueue(x)Formarse al finalO(1)
dequeue()Atender al de adelanteO(1)
front()Ver a quién le tocaO(1)
empty()¿Queda alguien?O(1)

La pila usa un extremo; la fila usa dos: se entra por uno y se sale por el otro. El orden de salida es el mismo de llegada.

7.3 · Filas

Un puntero más: final


template <typename T>
class Fila {
    // struct Nodo: el mismo de la pila
    Nodo* frente;                 // por aqui se atiende
    Nodo* final;                  // aqui se forma el que llega
public:
    Fila() { frente = nullptr; final = nullptr; }
    void enqueue(T x);
    T    dequeue();
    T    front() { return frente->dato; }
    bool empty() { return frente == nullptr; }
};
  • Con solo frente, formarse al final obliga a recorrer toda la fila: O(n). Con final es O(1), a cambio de mantener un puntero más al día.
7.3 · Filas

enqueue: formarse al final


void enqueue(T x) {
    Nodo* nuevo = new Nodo(x);
    if (final == nullptr) {       // fila vacia: es el primero y el ultimo
        frente = nuevo;
    } else {
        final->next = nuevo;      // el ultimo apunta al que llega
    }
    final = nuevo;
}

Si la fila está vacía, final->next leería un nullptr. Por eso el primer elemento se trata aparte: tiene que quedar como frente y como final.

7.3 · Filas

dequeue: atender al de adelante


T dequeue() {
    if (empty()) return T();      // nadie formado
    Nodo* victima = frente;
    T x = victima->dato;
    frente = frente->next;
    if (frente == nullptr) {      // se fue el ultimo de la fila
        final = nullptr;
    }
    delete victima;
    return x;
}

Es el pop de la pila con una línea más: si la fila quedó vacía, final todavía apunta al nodo que se va a liberar.

7.3 · Filas

La fila, nodo por nodo

Checkpoint

Un equipo quitó de dequeue las líneas if (frente == nullptr) final = nullptr;. ¿Qué secuencia lo hace fallar?

B. Al sacar el 1 la fila queda vacía, pero final sigue apuntando al nodo liberado. El siguiente enqueue ve final != nullptr y escribe final->next en memoria liberada; además frente se queda en nullptr y el 2 nunca se atiende. En la A y la C la fila nunca se vacía. Es el caso límite "vaciar y volver a usar" de la sesión 13.

Otras variantes

7.3 · Fila circular

La fila sobre un arreglo

  • Sin nodos: los elementos van en un arreglo y dos índices marcan el frente y el final.
  • Si dequeue recorre a todos una casilla hacia adelante, cada salida cuesta O(n).
  • Si solo avanza el índice del frente, las casillas del principio quedan vacías y sin usar: la fila "se llena" con espacio libre.

La solución es dejar que los índices den la vuelta: al pasar de la última casilla regresan a la 0. El arreglo se usa como un anillo.

7.3 · Fila circular

Los índices giran, los datos no se mueven

7.3 · Fila circular

La vuelta es un %


T   datos[8];
int frente;                         // indice del primero
int n;                              // cuantos hay: distingue vacia de llena
void enqueue(T x) {                 // pre: n < 8
    int fin = (frente + n) % 8;     // la casilla libre, dando la vuelta
    datos[fin] = x;
    n++;
}
T dequeue() {                       // pre: n > 0
    T x = datos[frente];
    frente = (frente + 1) % 8;
    n--;
    return x;
}
7.4 · Fila priorizada

Urgencias: no pasa el que llegó primero

  • En urgencias de un hospital, alguien con un infarto pasa antes que quien llegó hace una hora con un esguince.
  • Cada elemento entra con una prioridad. insert(x, prioridad) agrega; extractMax() saca al de mayor prioridad, sin importar cuándo llegó.
  • Con empates, lo usual es atender por orden de llegada.

Riesgo nuevo: si siempre llega algo más urgente, un elemento de prioridad baja puede no salir nunca.

7.4 · Fila priorizada

Con listas, una de las dos operaciones cuesta

ImplementacióninsertextractMax
Lista sin ordenO(1): al frenteO(n): buscar el mayor
Lista ordenada por prioridadO(n): buscar su lugarO(1): está al frente
Heap binarioO(log n)O(log n)

La lista ordenada es la variante de la sesión 12: cada inserción camina hasta su lugar. El heap reparte el costo entre las dos operaciones; se implementa en la sesión 18.

Checkpoint

Implementas la fila priorizada como lista ordenada. Un compañero dice: "las dos operaciones son O(1): insertar al frente y sacar del frente". ¿Qué está mal?

C. Sacar el mayor es O(1) porque la lista está ordenada, y mantenerla ordenada obliga a buscar el lugar de cada elemento nuevo. La B confunde lista con arreglo: quitar la cabeza de una lista es cambiar un puntero.
7.5 · Deque

Deque: los dos extremos abiertos

  • pushFront, pushBack, popFront y popBack: se entra y se sale por los dos lados.
  • Con la lista simple de la fila, popBack no es O(1): para quitar el último hay que encontrar al penúltimo, y eso obliga a recorrer.
  • Con la lista doble de la sesión 12, el último conoce a su anterior por prev. Las cuatro operaciones quedan en O(1).

Un deque es la versión menos restringida: si solo se usa un extremo se comporta como pila, y si se entra por uno y se sale por el otro, como fila.

Por qué importa hoy

Un servidor de inferencia es un problema de filas

  • Las peticiones a un LLM entran a una fila y se agrupan en lotes para aprovechar la GPU.
  • Una petición de chat de 20 ms que queda detrás de un trabajo por lotes de una hora espera una hora. Por eso las interactivas van en una fila priorizada.
  • La caché KV del modelo se vacía con una política, FIFO o LRU, que es una decisión de estructura de datos con efecto directo en la latencia.
STL

stack, queue y priority_queue son adaptadores


stack<int> s;            // push, pop, top, empty
queue<int> q;            // push, pop, front, back, empty
priority_queue<int> pq;  // push, pop, top: sale el mayor

stack<int, vector<int>> s2;   // la misma pila, guardada
                              // en un vector por dentro
  • Un adaptador no guarda nada por sí mismo: envuelve a otro contenedor (por defecto deque) y solo deja visibles las operaciones de su disciplina.
  • Es la idea de hoy hecha biblioteca: la restricción va afuera y el almacenamiento de adentro se puede cambiar.
STL

std::deque sí es un contenedor

  • Guarda los datos en bloques de tamaño fijo más un índice de bloques.
  • Permite d[i] en O(1), y agregar o quitar en los dos extremos en O(1) amortizado.
  • Agregar por los extremos no mueve los elementos que ya estaban, a diferencia de vector cuando crece.

Por eso es el contenedor por defecto de stack y queue.

Checkpoint

¿Qué es std::stack en la STL?

B. std::stack envuelve un contenedor y expone solo push, pop y top, como la clase Pila de hoy. Por eso se puede montar sobre vector, deque o list sin cambiar el código que la usa.
