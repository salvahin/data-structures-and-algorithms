8.2 · De la fila priorizada al heap

La fila priorizada

  • Una fila priorizada guarda elementos y siempre atiende primero al de mayor prioridad, sin importar el orden de llegada. Tiene tres operaciones: push agrega, top consulta al de mayor prioridad y pop lo quita.
  • Con un arreglo ordenado: top O(1), pero push O(n). Con uno desordenado: push O(1), pero top O(n).
  • El heap binario da top en O(1) y push/pop en O(log n). Hoy lo implementamos.

8.2 El heap binario

8.2 · Propiedad de heap

La propiedad de heap

  • Max-heap: cada padre es mayor o igual que sus dos hijos. No se pide nada más.
  • Consecuencia: el máximo está en la raíz. Entre hermanos, y entre ramas distintas, no hay ningún orden.
  • Como se pide poco, mantener la propiedad cuesta O(log n) por operación. Mantener todo ordenado costaría O(n) por inserción.

El heap da acceso inmediato al máximo. Para conocer el segundo hay que hacer pop.

8.2 · Árbol completo

Árbol completo: la forma depende solo de n

  • Un heap es un árbol completo: todos los niveles llenos, salvo quizá el último, que se llena de izquierda a derecha.
  • Con n elementos solo hay una forma posible. Las operaciones deciden dónde va cada valor, nunca la forma.
  • La altura es \(\lfloor \log_2 n \rfloor\) siempre. No hacen falta rotaciones ni factores de balance.

Comparación con el BST de la sesión 16: allá el orden es fuerte y la forma depende del orden de inserción; acá el orden es débil y la forma es fija.

8.2 · Representación implícita

El árbol es un arreglo

8.2 · Representación implícita

Tres fórmulas sustituyen a los punteros

\[ \text{izq}(i) = 2i + 1 \qquad \text{der}(i) = 2i + 2 \qquad \text{padre}(i) = \left\lfloor \tfrac{i - 1}{2} \right\rfloor \]
  • Un índice es válido solo si es menor que n. Si \(2i + 1 \ge n\), el nodo i es hoja.
  • Sin izq ni der en cada nodo se usa menos memoria, y los datos quedan contiguos en el arreglo.
  • Las fórmulas funcionan porque el árbol es completo. Con huecos, el arreglo tendría celdas sin dato.
Checkpoint

El arreglo [90, 70, 80, 30, 50, 60] es un max-heap válido. ¿Qué garantiza eso sobre el arreglo?

B. El propio ejemplo refuta la opción A: 70 aparece antes que 80. Solo se garantiza la relación padre-hijos. La opción C también falla: 30 (posición 3, primera mitad) es menor que 60 (posición 5). Tratar el heap como estructura ordenada es el error conceptual más frecuente del tema.

8.2 · La clase

Un heap es un vector y dos funciones auxiliares


class Heap {
    std::vector<int> datos;
    void subir(int i);
    void bajar(int i, int n);
public:
    void push(int x);
    void pop();
    int top() { return datos[0]; }
    int size() { return datos.size(); }
    void construir();
    void heapSort();
};

subir y bajar reparan la propiedad de heap después de un cambio. Todas las operaciones públicas se apoyan en ellas.

8.2 · push y subir

push(85), línea por línea

8.2 · push y subir

push: entra al final y sube


void Heap::push(int x) {
    datos.push_back(x);
    int n = datos.size();
    subir(n - 1);
}
void Heap::subir(int i) {
    if (i == 0) return;
    int p = (i - 1) / 2;
    if (datos[p] >= datos[i]) return;
    std::swap(datos[p], datos[i]);
    subir(p);
}
8.2 · pop y bajar

pop(), línea por línea

pop: el último pasa a la raíz y baja


void Heap::pop() {
    datos[0] = datos.back();
    datos.pop_back();
    bajar(0, datos.size());
}
void Heap::bajar(int i, int n) {
    int mayor = i;
    int izq = 2 * i + 1;
    int der = 2 * i + 2;
    if (izq < n && datos[izq] > datos[mayor])
        mayor = izq;
    if (der < n && datos[der] > datos[mayor])
        mayor = der;
    if (mayor == i) return;
    std::swap(datos[i], datos[mayor]);
    bajar(mayor, n);
}
8.2 · subir y bajar

Lo que hay que recordar de subir y bajar

  • Cada llamada sube o baja un nivel: a lo más \(\lfloor \log_2 n \rfloor\) intercambios. push y pop cuestan O(log n).
  • mayor se compara contra los dos hijos. Si solo se mira al izquierdo, el derecho puede quedar debajo de un valor menor.
  • Recibe n como parámetro: solo las celdas 0…n − 1 forman parte del heap. construir y Heap Sort lo aprovechan.
  • pop supone que el heap no está vacío; quien lo llama debe revisar size() antes.
Checkpoint

¿Cuánto cuesta encontrar el mínimo en un max-heap de n elementos?

C. La propiedad de heap solo empuja a los grandes hacia arriba: el mínimo está en alguna hoja, pero el arreglo no dice en cuál — la última celda (opción A) es solo el último nivel por la izquierda. No hay "camino de los menores" (opción B) porque los hermanos no se comparan entre sí. Un heap resuelve extremos de un solo lado; para ambos lados se usan dos heaps (reto LC 295).
8.2 · Construcción

Construir un heap desde un arreglo

  • Opción directa: n llamadas a push → O(n log n).
  • Opción mejor: tomar el arreglo tal como está y llamar a bajar desde el último padre (celda n / 2 − 1) hasta la 0.
  • Las hojas ya son heaps de un elemento. Cada bajar junta dos heaps hijos con su padre en un heap más grande.
8.2 · Construcción

construir(), una llamada a bajar por paso

8.2 · Construcción

Por qué build-heap cuesta O(n)


void Heap::construir() {
    int n = datos.size();
    for (int i = n / 2 - 1; i >= 0; i--)
        bajar(i, n);
}
  • Un nodo a altura h hace a lo más h intercambios, y hay cerca de \(n / 2^{h+1}\) nodos a esa altura:
\[ \text{intercambios} \;\le\; \sum_{h \ge 0} \frac{n}{2^{h+1}} \cdot h \;=\; n \sum_{h \ge 0} \frac{h}{2^{h+1}} \;=\; n \]
8.2 · Heap Sort

Heap Sort: ordenar dentro del mismo arreglo

  • 1. construir() sobre el arreglo completo: O(n).
  • 2. Repetir n − 1 veces: intercambiar la raíz (el máximo) con la última celda de la zona viva, reducir la zona viva en uno y llamar a bajar(0, fin): O(log n) cada vez.
  • El arreglo queda ordenado de menor a mayor, de derecha a izquierda.
8.2 · Heap Sort

heapSort(): zona viva y zona ordenada

8.2 · Heap Sort

Heap Sort en código


void Heap::heapSort() {
    construir();
    int n = datos.size();
    for (int fin = n - 1; fin > 0; fin--) {
        std::swap(datos[0], datos[fin]);
        bajar(0, fin);
    }
}
  • O(n log n) sin memoria extra.
  • Frente al Merge Sort de la sesión 8: el mismo O(n log n) sin los O(n) de memoria auxiliar. A cambio, no es estable y salta más por el arreglo, lo que aprovecha peor la caché.

8.2 El patrón top-k

8.2 · Top-k

Los k mayores de un stream

  • Se mantiene un min-heap de tamaño k con los k mejores vistos hasta ahora. Su raíz es el menor de ellos; lo llamamos el portero.
  • Llega un elemento: si no supera al portero, se descarta con una comparación. Si lo supera, pop + push en O(log k).
  • Costo total: O(n log k) con memoria O(k). Ordenar todo costaría O(n log n) y exigiría guardar los n elementos.

Para quedarte con los k mayores, el heap es de mínimos: el que sale siempre es el peor de los candidatos.

8.2 · Top-k

Top-k en código


// portero: min-heap de a lo más k elementos;
// su raíz es el menor de los k mejores
void topK(std::vector<int>& v, int k,
          HeapMin& portero) {
    for (int x : v) {
        if (portero.size() < k) {
            portero.push(x);
        } else if (x > portero.top()) {
            portero.pop();
            portero.push(x);
        }
    }
}
Checkpoint

Quieres los 10 elementos más grandes de un stream de 10 millones. ¿Qué estructura usas?

B. El max-heap de tamaño 10 (opción C) es el error clásico: su raíz es el mejor candidato, pero para decidir si un recién llegado entra hay que compararlo con el peor de los 10 — y encontrar el mínimo en un max-heap cuesta O(k), como vimos en el quiz anterior. El min-heap pone al portero en la raíz: comparación en O(1), reemplazo en O(log k).

Por qué importa hoy

Top-k sostiene la generación de texto

  • Con top-k sampling, un modelo de lenguaje escoge el siguiente token entre los k más probables de un vocabulario de decenas de miles. Un heap de tamaño k lo resuelve en O(n log k) por token generado, sin ordenar el vocabulario.
  • Los k vecinos más cercanos de un índice vectorial se recolectan con el mismo patrón: un heap que descarta en la puerta a quien no supera al peor candidato.
  • El algoritmo de Dijkstra del bloque de grafos extrae en cada paso el nodo más cercano de una fila priorizada: la de hoy.
