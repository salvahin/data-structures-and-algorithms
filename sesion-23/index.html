8.2.4.1 Grafos sin ciclos: árboles y DAG

8.2.4.1 · Árboles y DAG

El árbol como grafo

Para un grafo no dirigido con V vértices, estas tres afirmaciones son equivalentes; cualquiera de ellas lo hace árbol:

  • Es conexo y no tiene ciclos.
  • Es conexo y tiene exactamente \(V - 1\) aristas.
  • Entre cada par de vértices existe exactamente un camino.

Verificación práctica: contar aristas y correr un recorrido. Si \(E = V - 1\) y el recorrido alcanza los V vértices, es árbol. Agregar una arista más crea exactamente un ciclo; quitar una lo desconecta.

Cinco vértices, tres grafos

Las tres figuras tienen V = 5. Un árbol necesita exactamente \(E = V - 1 = 4\) aristas y ser conexo.

8.2.4.1 · Árboles y DAG

El DAG y cómo verificarlo

  • Un DAG es un grafo dirigido sin ciclos: un conjunto de tareas con dependencias que sí se pueden completar.
  • Verificación con Kahn: si el orden topológico incluye los V vértices, es DAG; los que quedan fuera forman un ciclo o dependen de uno.
  • Verificación con DFS: si aparece una flecha hacia un vértice cuya llamada sigue abierta (arista de retroceso), hay ciclo.
  • Un DAG admite en general varios órdenes topológicos. Contarlos todos es costoso; encontrar uno cuesta \(O(V + E)\).

Checkpoint

Un grafo no dirigido es conexo y tiene V vértices y V aristas. ¿Qué puedes afirmar?

B. Un árbol conexo tiene exactamente V − 1 aristas; la arista número V cierra exactamente un ciclo (el que forma con el único camino que ya unía sus extremos). La opción C falla porque un grafo conexo sin ciclos no puede tener V aristas: la caracterización es exacta, no aproximada — y ese es el valor de conocerla.

8.2.4.2 Grafo bipartito

8.2.4.2 · Bipartito

Dos bandos, aristas solo entre bandos

  • Un grafo es bipartito si sus vértices se pueden partir en dos conjuntos de modo que toda arista cruce de un conjunto al otro.
  • Equivalencia clave: bipartito ⟺ no contiene ciclos de longitud impar. Un ciclo par se colorea alternando; uno impar obliga a repetir color.
  • Aparece cuando las entidades son de dos tipos y la relación solo cruza tipos: usuarios–películas, alumnos–cursos, tareas–máquinas.
  • Detección: BFS coloreando por niveles alternados. Una arista entre dos vértices del mismo color termina la búsqueda.

Coloreado a dos tonos en C++


bool colorear(int s) {
    color[s] = 0;
    std::queue<int> fila;
    fila.push(s);
    while (!fila.empty()) {
        int u = fila.front();
        fila.pop();
        for (int v : ady[u]) {
            if (color[v] == -1) {
                if (color[u] == 0) {
                    color[v] = 1;
                } else {
                    color[v] = 0;
                }
                fila.push(v);
            } else if (color[v] == color[u]) {
                return false;
            }
        }
    }
    return true;
}
        

bool esBipartito() {
    color.assign(n, -1);
    for (int s = 0; s < n; s++) {
        if (color[s] == -1) {
            bool ok = colorear(s);
            if (!ok) {
                return false;
            }
        }
    }
    return true;
}

color es un std::vector<int> visible para las dos funciones. Hay un coloreado por componente, así que sirve para grafos no conexos.

Checkpoint

Durante el coloreado BFS aparece una arista entre dos vértices del mismo color. ¿Qué concluyes?

B. El conflicto certifica un ciclo impar: el camino BFS entre los dos vértices del mismo color más la arista conflictiva forman un ciclo de longitud impar, y ningún ciclo impar se puede 2-colorear. La opción A es el error típico: dentro de un componente conexo, cambiar el origen solo intercambia los dos colores — el conflicto reaparece exactamente igual.

8.2.4.3 Conectividad fuerte y puntos de articulación

8.2.4.3 · Conectividad fuerte

Componentes fuertemente conectados

  • En un grafo dirigido, un SCC es un conjunto máximo de vértices donde cada uno alcanza a todos los demás siguiendo las flechas.
  • Al contraer cada SCC a un supernodo, el grafo resultante (la condensación) siempre es un DAG: los ciclos quedan encerrados dentro de los componentes.
  • Kosaraju los encuentra con dos DFS (uno sobre el grafo, otro sobre el grafo con las flechas invertidas); Tarjan lo hace en una sola pasada. Ambos cuestan \(O(V + E)\).
  • Ejemplo clásico: en la web, un SCC es un conjunto de páginas que se enlazan mutuamente por algún camino.
8.2.4.3 · Conectividad fuerte

Tres SCC y su condensación

Del 0 se llega al 6, pero del 6 no se regresa a nadie. Las flechas 1→3, 2→5 y 4→6 no están en ningún ciclo, por eso quedan entre componentes.

8.2.4.3 · Puntos de articulación

Dónde se rompe una red

  • Un punto de articulación es un vértice cuya eliminación desconecta el grafo; un puente es la arista análoga.
  • Revelan los puntos únicos de falla. Un router que es punto de articulación parte la red al caerse; una red robusta no tiene ninguno.
  • Probar quitando cada vértice y recorriendo cuesta \(O(V \cdot (V + E))\). Un solo DFS con dos números por vértice lo resuelve en \(O(V + E)\).
8.2.4.3 · Puntos de articulación

Dos números por vértice: disc y low

  • disc[u]: el turno en que DFS descubre a u (1, 2, 3, …).
  • low[u]: el turno más antiguo al que el subárbol de u puede regresar por una arista de retroceso, una que no es del árbol DFS. Es el low-link de Tarjan.
  • Regla: si un hijo v de u cumple low[v] >= disc[u], el subárbol de v solo sale por u, y u es punto de articulación. La raíz es la excepción: lo es solo si tiene dos o más hijos.

Con la desigualdad estricta, low[v] > disc[u], la misma regla encuentra los puentes: la arista u–v es la única salida.

8.2.4.3 · Puntos de articulación

Escribir dfsLow, una decisión por línea

void dfsLow(int u, int padre) {
t = t + 1;
disc[u] = t;
low[u] = t;
int hijos = 0;
for (int v : ady[u]) {
if (disc[v] == 0) {
hijos = hijos + 1;
dfsLow(v, u);
low[u] = std::min(low[u], low[v]);
if (padre != -1 && low[v] >= disc[u]) {
corte[u] = true;
}
} else if (v != padre) {
low[u] = std::min(low[u], disc[v]);
}
}
if (padre == -1 && hijos > 1) {
corte[u] = true;
}
}
Una sola función recorre el grafo y calcula disc y low a la vez. Se escribe línea por línea.
La firma. El padre viaja como parámetro porque la arista hacia él es la del árbol DFS y no cuenta como retroceso. La raíz recibe −1.
El turno. Al descubrir a u se le da el siguiente turno. low empieza igual a disc: sin ver a nadie más, lo más antiguo que u alcanza es él mismo.
Contar hijos. hijos cuenta los hijos de u en el árbol DFS. Solo se usa al final, para la raíz.
Un hijo nuevo. disc[v] == 0 quiere decir que v no se ha descubierto. v se vuelve hijo de u y la llamada baja.
Heredar lo que alcanza el hijo. Al regresar de dfsLow(v, u), todo lo que alcanza el subárbol de v también lo alcanza u, a través de la arista u–v.
La regla. Si el subárbol de v no llega a un turno anterior al de u, su única salida es u. Quitar u lo deja aislado. La raíz (padre == -1) queda fuera de esta regla.
Arista de retroceso. v ya se descubrió y no es el padre: es un atajo hacia un vértice más antiguo.

¿Por qué disc[v] y no low[v]? Con low[v] se encadenarían varios atajos, y el camino podría regresar pasando por el mismo u. disc[v] cuenta solo el salto directo.

La raíz. Es punto de articulación si tiene más de un hijo.

¿Por qué la raíz es la excepción? Nadie se descubre antes que ella, así que la regla de low la marcaría siempre. Separa el grafo solo si DFS entró desde ella a dos subárboles: si hubiera camino entre ellos, el primero habría alcanzado al segundo.

void articulaciones() {
    t = 0;
    disc.assign(n, 0);
    low.assign(n, 0);
    corte.assign(n, false);

8.2.4.4 · Euleriano vs. hamiltoniano

Ninguna propiedad implica la otra

Checkpoint

¿Cuál de los dos problemas de ciclos se decide en tiempo polinomial, y con qué criterio?

B. El teorema de Euler da una caracterización local verificable en O(V+E): conexidad y grados pares. Para el hamiltoniano no se conoce nada parecido — la condición de la opción A es necesaria pero está lejos de ser suficiente — y el problema es NP-completo. La opción C regala el euleriano al enemigo: tener caracterización eficiente es justo lo que lo salva.

Adelanto del tema 8.3.3

Union-find: componentes sin recorrer el grafo

  • Mantiene una partición en conjuntos disjuntos con dos operaciones: find(x) (¿cuál es el representante del conjunto de x?) y unir(a, b) (fusionar dos conjuntos).
  • Cada conjunto es un árbol que apunta hacia su representante, guardado en un std::vector<int> de padres. Para componentes conexos, se llama unir(u, v) por cada arista.
  • Con unión por tamaño (o por rango) y compresión de caminos juntas, cada operación cuesta α(n) amortizado, la inversa de Ackermann. Cada optimización por separado solo da \(O(\log n)\).

Union-find en C++


int find(int x) {
    if (padre[x] == x) {
        return x;
    }
    int raiz = find(padre[x]);
    padre[x] = raiz;
    return raiz;
}
void unir(int a, int b) {
    int ra = find(a);
    int rb = find(b);
    if (ra == rb) {
        return;
    }
    if (tam[ra] < tam[rb]) {
        padre[ra] = rb;
        tam[rb] = tam[rb] + tam[ra];
    } else {
        padre[rb] = ra;
        tam[ra] = tam[ra] + tam[rb];
    }
}
        

void init(int n) {
    padre.resize(n);
    tam.assign(n, 1);
    for (int i = 0; i < n; i++) {
        padre[i] = i;
    }
}
