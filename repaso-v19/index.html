R19 · Punto de partida

Contar palabras usando solo vector


std::vector<std::string> palabras{"sol","mar","sol","luz","sol"};
std::vector<std::string> claves;
std::vector<int> veces;

for (const std::string& w : palabras) {
    bool esta = false;
    for (std::size_t i = 0; i < claves.size(); ++i)
        if (claves[i] == w) { veces[i]++; esta = true; break; }
    if (!esta) { claves.push_back(w); veces.push_back(1); }
}

Funciona, pero por cada palabra recorre todas las claves ya vistas. Con cien mil palabras distintas el ciclo interno domina el tiempo de ejecución.

R19 · pair

Dos valores que viajan juntos


std::pair<std::string, int> p{"Ana", 20};
std::cout << p.first << '\n';    // Ana
std::cout << p.second << '\n';   // 20

auto q = std::make_pair(3, 4.5);
// q es std::pair<int, double>, deducido de los argumentos
  • Es una plantilla con dos parámetros de tipo y dos campos públicos, first y second. Nada más.
  • Aparece cuando una función necesita devolver dos cosas y cuando un contenedor guarda parejas. Ese segundo caso es el que sigue.
R19 · map

El mismo conteo, en dos líneas


std::map<std::string, int> conteo;
for (const std::string& w : palabras) conteo[w]++;

for (const auto& par : conteo)               // luz=1 mar=1 sol=3
    std::cout << par.first << "=" << par.second << ' ';

auto it = conteo.find("mar");
if (it != conteo.end())
    std::cout << "mar aparece " << it->second << " veces";
  • conteo[w] crea la entrada con valor 0 si la clave no existía, y devuelve una referencia al valor; por eso ++ funciona en ambos casos.
  • Al recorrerlo salen ordenados por clave, no por orden de inserción. Cada elemento es un pair<const K, V>.
Checkpoint

Tienes std::map<std::string,int> m; vacío y escribes if (m["ana"] == 0) …. ¿Qué pasa con el mapa?

C. operator[] tiene que devolver una referencia a un valor, así que si la clave no está la inserta con el valor por omisión. Es cómodo para contar y sorprende al consultar: un ciclo que revisa mil claves inexistentes deja mil entradas. Para consultar sin insertar están find y count.
R19 · set

Un conjunto: sin repetidos y ordenado


std::set<std::string> vistas;
vistas.insert("sol");
vistas.insert("mar");
vistas.insert("sol");   // ignorado: ya estaba

std::cout << vistas.size();              // 2
std::cout << vistas.count("sol");        // 1 si está, 0 si no
// construir desde un vector, de golpe:
std::set<std::string> d(palabras.begin(), palabras.end());
  • Guarda claves sin valor asociado. Responde a "¿ya vi esto?" y a "¿cuántos distintos hay?", no a "¿cuántas veces?".
  • map y set son contenedores asociativos ordenados: mantienen sus elementos en un árbol de búsqueda balanceado, que es lo que hace la consulta rápida.
R19 · list

Insertar en medio sin mover nada


std::list<int> l{10, 20, 30};
l.push_front(5);    // 5 10 20 30
l.push_back(40);    // el frente cuesta lo mismo que el final

auto it = l.begin();
++it; ++it;         // hay que avanzar paso a paso: no hay l[2]
l.insert(it, 99);   // inserta antes de it, sin mover elementos
l.erase(it);        // borra ese elemento, sin mover los demás
  • Es una lista doblemente ligada: cada elemento guarda su valor y las direcciones del anterior y el siguiente. No hay bloque contiguo ni acceso por índice.
  • Insertar o borrar con un iterador en la mano cuesta lo mismo sin importar el tamaño. Llegar a ese iterador es lo caro.
Checkpoint

Necesitas guardar un millón de números y consultar muchas veces el que está en la posición 500 000. ¿Qué contenedor conviene?

A. El bloque contiguo del vector permite calcular la dirección del elemento 500 000 con una multiplicación. En list hay que seguir medio millón de enlaces cada vez (B), y set ni siquiera ofrece posiciones: sus elementos se buscan por valor, no por índice (C).
R19 · Criterio de elección

Qué cuesta cada operación

ContenedorAcceso por índiceBuscar un valorInsertarOrden
vector\(O(1)\)\(O(n)\)al final \(O(1)\)*, en medio \(O(n)\)de inserción
listno ofrece\(O(n)\)\(O(1)\) con el iteradorde inserción
mappor clave, \(O(\log n)\)\(O(\log n)\)\(O(\log n)\)por clave
setno ofrece\(O(\log n)\)\(O(\log n)\)por valor

* amortizado, por la duplicación de capacidad de R18.

La complejidad se lee junto con la operación que más vas a repetir. Recorrer un millón de elementos es más rápido en vector que en list aunque las dos digan \(O(n)\), porque el bloque contiguo aprovecha la memoria caché.

R19 · Algoritmos

sort y la comparación a la medida


std::vector<int> v{4, 15, 8, 23};
std::sort(v.begin(), v.end());        // 4 8 15 23, usa operator<

std::vector<Alumno> alu = leerAlumnos();
std::sort(alu.begin(), alu.end(),
          [](const Alumno& a, const Alumno& b) {
              return a.prom > b.prom;   // de mayor a menor
          });
  • Los algoritmos reciben un rango como par de iteradores, no el contenedor. Por eso sort(v.begin()+2, v.end()) ordena solo la cola.
  • Una lambda es una función escrita en el lugar donde se usa: [](parámetros) { cuerpo }. El tercer argumento de sort responde "¿va a antes que b?".
Checkpoint

¿Por qué std::sort(l.begin(), l.end()) no compila cuando l es un std::list<int>?

B. El algoritmo de sort compara elementos lejanos entre sí, lo que exige iteradores de acceso aleatorio; los de list no lo son y el error aparece al instanciar la plantilla. C es falso: sort es genérico y funciona sobre cualquier rango que cumpla el requisito, incluso un arreglo de C. Para ordenar una lista está su propio método, l.sort().
R19 · Algoritmos

Buscar y acumular sobre un rango


auto f = std::find(v.begin(), v.end(), 15);
if (f != v.end())
    std::cout << "posición " << (f - v.begin());   // 2

auto p = std::find_if(v.begin(), v.end(),
                      [](int x) { return x > 20; });
std::cout << *p;                                   // 23
int suma = std::accumulate(v.begin(), v.end(), 0);
double t = std::accumulate(alu.begin(), alu.end(), 0.0,
    [](double acc, const Alumno& a) { return acc + a.prom; });
// el 0.0 fija el tipo del acumulador y el valor inicial

find compara con ==; find_if recibe una lambda que devuelve bool. Los dos devuelven end() cuando no hay coincidencia, así que hay que comparar antes de desreferenciar. accumulate vive en <numeric>; los demás, en <algorithm>.

Checkpoint

Con std::vector<double> v{1.5, 2.5};, ¿qué devuelve std::accumulate(v.begin(), v.end(), 0)?

A. El tipo del acumulador se deduce del tercer argumento, no de los elementos. Con 0 cada suma se trunca a entero y el resultado es 3; con 0.0 es 4.0. Compila sin advertencia con -Wall -Wextra, así que el error solo se nota en el resultado.
R19 · Trampas comunes

Cuatro formas de perder media hora

  • Consultar un map con [] y llenarlo de entradas vacías sin darse cuenta. Para consultar, find o count.
  • Usar el resultado de find sin compararlo antes contra end(). Ese iterador no apunta a ningún elemento.
  • Pasar un valor inicial int a accumulate sobre un rango de double y truncar cada suma.
  • Elegir list "porque insertar es rápido" en un programa que sobre todo recorre. Sin acceso por índice y sin memoria contigua, casi siempre resulta más lento que vector.
R19 · Ejercicio

El mismo problema, tres contenedores

  1. Dada una lista de palabras, cuenta cuántas veces aparece cada una. Resuélvelo con vector, con map y con set.
  2. Mide o estima el costo de cada versión en función del número de palabras.
  3. Argumenta cuál conviene y en qué caso cambiarías de opinión.

// A) vector: por cada palabra recorre las claves ya vistas
//    (el código del slide 3)

// B) map: la clave hace la búsqueda
std::map<std::string, int> conteo;
for (const std::string& w : palabras) conteo[w]++;

// C) set: responde cuántas distintas, no cuántas veces
std::set<std::string> d(palabras.begin(), palabras.end());
std::cout << d.size();

Con \(n\) palabras y \(k\) distintas, A cuesta \(O(nk)\) y B cuesta \(O(n \log k)\). C no resuelve el problema planteado: sirve si la pregunta es cuántas palabras distintas hay. Cambiarías de opinión con \(k\) muy pequeño y fijo (con cinco claves el vector gana por memoria contigua) o si necesitas el resultado en orden de aparición, que el map no conserva.
