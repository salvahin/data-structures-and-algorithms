R4 · Punto de partida

Un carácter invisible cambia el resultado


#include <iostream>
int main() {
    int suma = 0, i = 0;
    for (i = 1; i <= 5; i++);      // suma 1+2+3+4+5
        suma += i;
    std::cout << suma << '\n';
}
      

6

Debía imprimir 15. La sangría dice que suma += i; está dentro del ciclo, pero el punto y coma al final de la línea 4 ya cerró el cuerpo: el ciclo dio cinco vueltas sin hacer nada y suma += i se ejecutó una sola vez, con i valiendo 6.

-Wall lo avisa: this 'for' clause does not guard... [-Wmisleading-indentation].

R4 · Decisiones

if, else y los dos signos iguales


if (cal >= 90)      std::cout << "A\n";
else if (cal >= 80) std::cout << "B\n";
else if (cal >= 70) std::cout << "C\n";
else                std::cout << "Reprobado\n";
  • Se detiene en la primera condición verdadera: cal = 95 imprime solo A.
  • Sin llaves, el if gobierna una sola instrucción. Agregar una segunda línea con la misma sangría la deja fuera de la condición.
  • if (x = 5) asigna y siempre se cumple; -Wall lo señala.
Escribe siempre las llaves, aunque el cuerpo tenga una línea. El arranque de este deck es lo que cuesta omitirlas.
Checkpoint

Con n valiendo 3, ¿qué imprime este fragmento?


if (n > 10);
    std::cout << "grande\n";
A. El punto y coma es una instrucción vacía y se convierte en el cuerpo del if. La línea siguiente queda fuera y se ejecuta siempre, sin importar el valor de n. B describe lo que el autor quería. C no ocurre: la instrucción vacía es sintaxis válida, y de ahí que el error pase inadvertido.
R4 · switch

Sin break la ejecución sigue de largo


int op = 2;
switch (op) {
    case 1: std::cout << "Alta\n";
    case 2: std::cout << "Baja\n";
    case 3: std::cout << "Consulta\n";
    default: std::cout << "Fin\n";
}
      

Baja
Consulta
Fin

Un case es una etiqueta de entrada. El programa salta a case 2 y ejecuta todo lo que sigue hasta un break o hasta el final del bloque.

R4 · switch

Cuando la caída sí se busca


switch (op) {
    case 1:
    case 2:                       // dos casos, un mismo cuerpo
        std::cout << "Modifica el padron\n";
        [[fallthrough]];          // la caída es deliberada
    case 3:
        std::cout << "Escribe en la bitacora\n";
        break;
    default:
        std::cout << "Opcion desconocida\n";
}
  • Dos etiquetas pegadas comparten cuerpo y no necesitan marca.
  • [[fallthrough]]; marca la caída deliberada y calla -Wextra.
  • default atrapa todo lo demás; escríbelo siempre.
Checkpoint

¿Sobre qué puede hacerse switch en C++?

C. El switch se traduce a un salto según un valor entero, así que admite int, char, bool y enumeraciones, y cada case debe ser una constante conocida al compilar. double y std::string no sirven (A) y hay que usar una cadena de if. Cualquier expresión entera vale, venga de una variable o de una llamada (B).
R4 · Ciclos

while pregunta antes, do-while pregunta después


int n = 3;
while (n > 0) {
    std::cout << n << ' ';
    n--;
}
// imprime: 3 2 1
          

int op = 0;
do {
    std::cout << "vuelta\n";
    op++;
} while (op < 1);
// imprime: vuelta
  • while puede dar cero vueltas. do-while siempre da al menos una, porque la condición se evalúa al final.
  • do-while encaja cuando el cuerpo produce el dato que la condición examina.
  • El do-while lleva punto y coma después del while final.
R4 · Ciclos

Las tres partes del for


for (int i = 0; i < 3; i++)
    std::cout << i << ' ';       // imprime: 0 1 2
ParteCuándo se ejecuta
int i = 0Una sola vez, antes de la primera vuelta
i < 3Antes de cada vuelta. Si es falsa, el ciclo termina
i++Al final de cada vuelta, antes de volver a evaluar

Todo for puede escribirse como while y viceversa. Se elige for cuando el número de vueltas se conoce de antemano y while cuando depende de algo que ocurre dentro del cuerpo, como la lectura de R3.

Checkpoint

¿Cuántas veces se ejecuta el cuerpo de for (int i = 10; i > 0; i -= 3)?

B. La secuencia es 10, 7, 4, 1 y después -2, que ya no cumple i > 0. Son cuatro vueltas. La condición compara contra cero, no busca la igualdad, así que el ciclo termina aunque i nunca valga 0 (C). El error de A es olvidar la última vuelta útil; contar los valores de la secuencia a mano evita ese descuido.
R4 · Alcance

Declara el contador dentro del for


for (int i = 0; i < 5; i++) { /* … */ }
// std::cout << i;   error: 'i' no está declarada aquí

int pos = -1;                        // sí sobrevive al ciclo
for (int i = 0; i < n; i++)
    if (dato[i] == buscado) { pos = i; break; }
  • El alcance de i termina con el ciclo. El nombre queda libre para el siguiente for y no se puede leer por accidente después.
  • Si necesitas el valor final, guárdalo en una variable declarada fuera, como pos. Es más claro que reutilizar el contador.
  • Con el contador dentro, el error del arranque no compila: i ya no existe en la línea de suma += i;.
R4 · break y continue

Salir del ciclo o saltar a la siguiente vuelta


int i = 0;
while (i < 5) {
    if (i == 2) { i++; continue; }   // ojo con el incremento
    std::cout << i << ' ';
    i++;
}
// imprime: 0 1 3 4
  • break termina el ciclo. En un switch anidado corta el switch, no el ciclo.
  • continue abandona la vuelta y evalúa la condición otra vez. En un while, si el incremento va después, no se ejecuta y el ciclo se atora.
  • En un for no hay riesgo: el incremento es parte del encabezado.
R4 · Errores de frontera

< frente a <=


const int N = 5;
int datos[N] = {10, 20, 30, 40, 50};   // índices válidos: 0 a 4

for (int i = 0; i <= N; i++)           // llega hasta datos[5]
    std::cout << datos[i] << ' ';
// 10 20 30 40 50 65535
  • Con N elementos, los índices van de 0 a N-1. La condición correcta para recorrer un arreglo es i < N; usar <= produce el clásico error de frontera.
  • datos[5] lee memoria que no pertenece al arreglo. El programa no aborta ni avisa: imprime lo que hubiera ahí, y el valor cambia entre ejecuciones.
  • Cuando el rango es de conteo y no de índices, <= sí es lo correcto: for (int k = 1; k <= 10; k++) suma del 1 al 10.
Checkpoint

Un arreglo tiene 8 elementos y quieres recorrerlo del último al primero. ¿Cuál encabezado es correcto?

A. Los índices válidos son 0 a 7, así que el recorrido inverso arranca en 7 y llega hasta 0 inclusive. B lee datos[8], fuera del arreglo, en la primera vuelta. C hace ocho vueltas pero con los índices 8 a 1: sale del arreglo al principio y nunca toca el elemento 0. Escribe el primer y el último valor del contador antes de elegir el operador.
R4 · Trampas comunes

Cinco errores que el compilador acepta

  • Punto y coma después del for o del if. El cuerpo se vuelve la instrucción vacía y la línea sangrada queda fuera.
  • = en lugar de ==. La condición asigna y evalúa el valor asignado; con cualquier número distinto de cero siempre se cumple.
  • <= al recorrer un arreglo. Toca un elemento que no existe, sin mensaje de error.
  • break olvidado en un case. Se ejecutan los casos siguientes.
  • continue antes del incremento en un while. El contador se congela y el ciclo no termina.
R4 · Ejercicio

Corrige tres ciclos sin ejecutarlos


const int N = 5;
int d[N] = {10, 20, 30, 40, 50};

int suma = 0;                            // A: sumar todo
for (int i = 0; i <= N; i++) suma += d[i];

int cuantos = 0;                         // B: contar > 25
for (int i = 1; i < N; i++)
    if (d[i] > 25) cuantos++;

int k = 0;                               // C: imprimir todo
while (k < N) { std::cout << d[k] << ' '; }

Di primero qué imprime cada uno y por qué. Después compílalos.

R4 · Ejercicio

Los tres rangos corregidos


// A: i <= N lee d[5], fuera del arreglo -> basura en la suma
for (int i = 0; i < N; i++) suma += d[i];

// B: arranca en 1 y nunca examina d[0]
for (int i = 0; i < N; i++)
    if (d[i] > 25) cuantos++;

// C: nunca incrementa k -> imprime 10 para siempre
while (k < N) { std::cout << d[k] << ' '; k++; }

Los tres son el mismo error visto de tres formas: el rango que recorre el ciclo no coincide con el rango de datos válidos. Con estos datos B imprime 3, el mismo resultado que la versión correcta, porque d[0] no cumplía la condición. Un ciclo que da el resultado esperado con un juego de datos no está por eso bien escrito.
