2.1 Definición de recursión

2.1 · Definición de recursión

Anatomía de una función recursiva

Una función recursiva se llama a sí misma sobre una versión más pequeña del problema. Para que termine, necesita tres piezas:

  • Caso base — la entrada que se resuelve directamente, sin llamarse a sí misma.
  • Caso recursivo — la entrada se resuelve combinando el resultado de la misma función sobre un subproblema.
  • Avance hacia el caso base — cada llamada acerca el argumento al caso base. Sin esta pieza, la recursión no termina.
2.1 · Definición de recursión

Las tres piezas en factorial


long long factorial(int n) {
    if (n <= 1) return 1;          // caso base
    return n * factorial(n - 1);   // caso recursivo
}
  • El caso base responde n <= 1 sin ayuda de nadie.
  • El caso recursivo delega el subproblema factorial(n - 1) y combina con una multiplicación.
  • El avance está en el n - 1: cada llamada reduce n, así que el caso base se alcanza en n pasos.
2.1 · Definición de recursión

La hipótesis recursiva

Para escribir el caso recursivo, asume que la llamada interna ya funciona para entradas más pequeñas y concéntrate en combinar su resultado.

  • Al escribir n * factorial(n - 1) no rastreas las llamadas internas: asumes que factorial(n - 1) devuelve (n-1)! y verificas que multiplicar por n produce n!.
  • Es el mismo esquema de la inducción matemática: un caso base demostrado y un paso que usa la hipótesis.
  • Intentar seguir mentalmente todas las llamadas anidadas es el error de novato más común. La traza completa se usa para depurar un caso concreto; para diseñar la función basta la hipótesis.
Checkpoint

Una función tiene caso base y caso recursivo, pero en una de sus ramas el argumento no se acerca al caso base. ¿Qué pasa al ejecutarla?

B. El compilador no verifica la terminación: f(n - 2) con caso base n == 0 compila sin quejas y, llamada con n impar, brinca el caso base para siempre. El programa aborta cuando se queda sin espacio para guardar las llamadas pendientes — el tema del siguiente bloque.

2.1 · Las llamadas pendientes

Una llamada que espera a otra

Cuando una función llama a otra, la primera queda a medias: tiene que retomar en el punto exacto donde se quedó. El programa anota ese punto y lo guarda.

2.1 · Las llamadas pendientes

La pila de llamadas y sus marcos

  • Esa forma de guardar y recuperar —lo último que se guarda es lo primero que se recupera— se llama apilar, y la zona de memoria donde ocurre es la pila de llamadas.
  • Cada llamada activa ocupa ahí un marco: sus parámetros, sus variables locales y el punto al que debe regresar.
  • Si una recursión llega a d llamadas encadenadas, hay d marcos guardados al mismo tiempo. La memoria que consume la recursión es proporcional a esa profundidad.
  • En el Bloque 2 construiremos una Pila como estructura de datos propia. Hoy solo necesitamos saber cómo se comporta.

2.1 · Las llamadas pendientes

Dos llamadas por nivel: fib


long long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // dos subproblemas por llamada
}
  • factorial(5) produce una sola cadena de llamadas. fib(5) produce una ramificación: cada llamada abre dos nuevas, y cada una de esas otras dos.
  • Las dos no ocurren a la vez: primero se resuelve por completo fib(n - 1), con todo lo que abra, y hasta entonces empieza fib(n - 2).

2.1 · Las llamadas pendientes

El desbordamiento de pila


int suma(int n) {              // suma 1 + 2 + ... + n
    if (n == 0) return 0;
    return n + suma(n - 1);
}

suma(10);        // bien: 10 marcos
suma(10000000);  // aborta: diez millones de marcos no caben
  • La pila tiene un tamaño fijo, entre 1 y 8 MB. Cada marco consume decenas de bytes; una cadena de millones de llamadas la agota.
  • suma(n) encadena n llamadas. Un algoritmo que parte el problema a la mitad llega mucho antes al caso base: un millón de elementos toma 20 pasos.
Checkpoint

Al calcular fib(6) con la versión ingenua, ¿cuántas veces se evalúa fib(2)?

C. Nada guarda resultados por ti: cada aparición de fib(2) en el mapa de llamadas se calcula desde cero. El número de apariciones crece siguiendo la propia sucesión de Fibonacci, y por eso la versión ingenua se vuelve impracticable tan rápido. En la sesión 4 eliminaremos ese trabajo repetido guardando los resultados ya calculados.

2.2 Recursión en tres problemas

2.2 · Caso 1: sistema de archivos

Recorrer carpetas dentro de carpetas


void listar(const fs::path& dir, int nivel) {
    for (const auto& e : fs::directory_iterator(dir)) {
        imprimir(e.path(), nivel);
        if (e.is_directory())
            listar(e.path(), nivel + 1);   // el subdirectorio es el subproblema
    }
}
  • Una carpeta contiene archivos y otras carpetas, que contienen archivos y otras carpetas. El dato está definido en términos de sí mismo y la función copia esa forma.
  • Caso base implícito: una carpeta sin subcarpetas no genera más llamadas. La cadena llega tan hondo como el anidamiento, unos pocos niveles en la práctica.
2.2 · Caso 2: expresiones anidadas

Evaluar (2 + (3 * 4)) * 5

Para evaluar la expresión completa hay que evaluar primero lo que está dentro de los paréntesis, y eso de adentro es otra expresión igual de válida, solo que más corta.

2.2 · Caso 2: expresiones anidadas

Una función por cada nivel de paréntesis


int evaluar(const std::string& s, int& i) {
    if (s[i] != '(') return leerNumero(s, i);  // caso base: un número
    ++i;                                       // entrar al paréntesis
    int izq = evaluar(s, i);                   // adentro hay otra expresión
    char op = s[i++];
    int der = evaluar(s, i);                   // y otra más
    ++i;                                       // salir del paréntesis
    return aplicar(op, izq, der);
}
  • Cada par de paréntesis abre una llamada y la cierra al terminar: el anidamiento del texto y el de las llamadas coinciden.
  • Con ciclos habría que llevar a mano qué operación quedó pendiente en cada nivel. La recursión deja ese registro en la pila de llamadas.
2.2 · Caso 3: N-reinas

Backtracking: decidir, explorar, deshacer


void resolver(int fila) {
    if (fila == n) { soluciones++; return; }   // caso base: tablero completo
    for (int col = 0; col < n; ++col) {
        if (!valida(fila, col)) continue;      // poda: esta columna es imposible
        colocar(fila, col);
        resolver(fila + 1);                    // explorar con la reina puesta
        quitar(fila, col);                     // deshacer y probar otra columna
    }
}
  • Cada llamada decide una fila. Las decisiones ya tomadas quedan registradas en la cadena de llamadas pendientes.
  • La poda descarta ramas completas antes de explorarlas: con n = 8 probar todas las asignaciones daría 8⁸ ≈ 16 millones de tableros, y el backtracking visita unos dos mil.

Checkpoint

¿Qué distingue al backtracking de generar todas las combinaciones completas y filtrarlas al final?

C. La poda actúa durante la construcción: una reina mal puesta en la fila 2 descarta de golpe todas las asignaciones de las filas 3 a 8, sin generarlas. La opción B describe guardar resultados ya calculados para no repetirlos, una técnica distinta que veremos en la sesión 4.
Por qué importa hoy

Datos anidados en todas partes


// La respuesta JSON de un LLM viene anidada:
void recorrer(const json& j) {
    if (j.is_object() || j.is_array())
        for (const auto& hijo : j)
            recorrer(hijo);        // cada parte es otro JSON
    else
        procesar(j);               // caso base: valor suelto
}
  • Un LLM devuelve JSON con objetos dentro de objetos y listas dentro de listas. Recorrerlo completo es el Caso 1 con otro nombre.
  • Convertir ese texto en datos usables consiste en entrar y salir de niveles anidados, igual que en el Caso 2.
  • Un agente que planifica en varios pasos prueba una acción, explora a dónde lleva y retrocede cuando no funciona — el esquema del Caso 3.
Cierre STL

Recorridos y permutaciones ya empaquetados


for (const auto& e : fs::recursive_directory_iterator("datos/"))
    if (e.path().extension() == ".json")
        procesar(e.path());

std::sort(v.begin(), v.end());
do {
    procesar(v);                       // cada permutación, en orden
} while (std::next_permutation(v.begin(), v.end()));
  • recursive_directory_iterator hace el recorrido del Caso 1 sin que escribas la recursión. Por dentro suele llevar su propia lista de carpetas pendientes en vez de llamarse a sí mismo.
  • std::next_permutation genera todas las permutaciones con un ciclo, sin llamadas anidadas. Le falta la poda, así que sirve para recorrer todo el espacio pero no sustituye al backtracking de N-reinas.

LC 50 y LC 51

LC 50 · Pow(x, n) — Media

  • Calcula xⁿ con n entero, posiblemente negativo.
  • Multiplicar x por sí mismo n veces excede el límite de tiempo del caso grande.
  • Pista: xⁿ se arma a partir de xn/2, así cada llamada reduce n a la mitad.
  • Casos: (2, 10) → 1024 · (2, −2) → 0.25 · (1.0000000001, 2147483647) → ≈ 1.2397

LC 51 · N-Queens — Alta

  • Devuelve todas las configuraciones válidas de n reinas.
  • Parte del esqueleto de backtracking de hoy; puede quedar abierto y terminarse fuera de clase.
  • Casos: n=1 → 1 solución · n=4 → 2 · n=8 → 92

Material extra · autoestudio

La recursión de cola


long long factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);      // pendiente: multiplicar al regresar
}

long long fact(int n, long long acum) {
    if (n <= 1) return acum;
    return fact(n - 1, n * acum);     // nada pendiente después de la llamada
}
  • En la primera versión el marco tiene que sobrevivir a la llamada interna, porque le queda una multiplicación por hacer con el valor que regrese.
  • En la segunda, el resultado de la llamada interna se devuelve tal cual y el acumulador carga el trabajo ya hecho. El marco actual no guarda nada útil, así que podría reutilizarse.
Material extra · autoestudio

C++ no garantiza esa optimización

  • Un compilador puede convertir la recursión de cola en un ciclo (con -O2, GCC y Clang suelen hacerlo), pero el estándar no lo exige.
  • La corrección de tu programa no puede depender de esa optimización: en -O0, con destructores pendientes o con llamadas indirectas, la conversión no ocurre y la pila crece igual.
  • Regla práctica: si la cadena de llamadas puede crecer con el tamaño de la entrada sin un tope chico, conviértela tú a un ciclo con un acumulador.
  • La recursión se queda donde el número de llamadas encadenadas está acotado por la forma del dato: carpetas, expresiones anidadas, backtracking.
Material extra · checkpoint

¿Cuál de estas llamadas es recursión de cola?

B. La llamada recursiva es la última operación y su valor se devuelve tal cual. En A queda una multiplicación pendiente después de la llamada, y en C quedan otra llamada y una suma. En ambos casos el marco tiene que sobrevivir, así que no son de cola.
Material extra · autoestudio

Lambdas recursivas con std::function


std::function<long long(int)> fact = [&](int n) -> long long {
    return n <= 1 ? 1 : n * fact(n - 1);
};
fact(10);   // 3628800
  • Una lambda es una función anónima escrita en el lugar donde se usa. Al no tener nombre, no puede llamarse a sí misma.
  • std::function le da ese nombre: la variable fact queda capturada por referencia y la lambda la usa para llamarse.
  • Ese nombre tiene precio: cada llamada pasa por una indirección que impide que el compilador incruste el código. Para código que se ejecuta millones de veces conviene una función normal.
