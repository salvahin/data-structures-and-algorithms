R8 · Punto de partida

El arreglo encoge al cruzar la puerta


#include <iostream>

void imprimir(int datos[]) {
    int n = sizeof(datos) / sizeof(datos[0]);
    for (int i = 0; i < n; i++)
        std::cout << datos[i] << ' ';
    std::cout << '\n';
}

int main() {
    int v[6] = {1, 2, 3, 4, 5, 6};
    std::cout << sizeof(v) / sizeof(v[0]) << '\n';   // 6
    imprimir(v);                                      // 1 2
}

La misma cuenta da 6 en main y 2 dentro de imprimir, con el mismo arreglo.

R8 · Arreglos estáticos

Declarar y recorrer


int v[5] = {10, 20, 30, 40, 50};
int n = sizeof(v) / sizeof(v[0]);    // 5
for (int i = 0; i < n; i++)
    std::cout << v[i] << ' ';
int ceros[4] = {};                    // 0 0 0 0
int parcial[5] = {1, 2};              // 1 2 0 0 0
  • El tamaño se fija al compilar; el arreglo vive en la pila.
  • sizeof(v) son los bytes del arreglo completo, 20 aquí, y sizeof(v[0]) los de un elemento.
  • Los índices válidos van de 0 a n - 1. Salirse no produce error: lee o escribe la memoria que esté ahí.
R8 · Direcciones

Toda variable tiene una dirección


int x = 42;
double d = 3.5;
std::cout << x << '\n';                     // 42
std::cout << &x << '\n';                    // 0xffffd597228c
std::cout << sizeof(x) << ' ' << sizeof(d); // 4 8
  • Una variable ocupa un bloque de bytes consecutivos. Su dirección es la del primero de esos bytes.
  • &x se lee “la dirección de x”. El valor cambia en cada ejecución, así que solo importa como identidad, no como número.
  • En un arreglo, los elementos están pegados: si v[0] está en la dirección D, v[1] está en D + sizeof(v[0]).
Checkpoint

Con int v[10]; declarado en main, ¿cuál de estas expresiones da la cantidad de elementos?

C. sizeof(v) devuelve bytes, no elementos: aquí serían 40. Un arreglo estático no tiene métodos, así que v.size() no compila; ese es el std::vector de R18. La división de los bytes totales entre los de un elemento sí da 10, y funciona solo mientras v siga siendo un arreglo.
R8 · Punteros

Una variable que guarda una dirección


int x = 42;
int* p = &x;                 // p guarda la direccion de x
std::cout << *p << '\n';     // 42, desreferencia
*p = 7;
std::cout << x << '\n';      // 7, se modifico x
int* q = nullptr;            // no apunta a nada
if (q != nullptr) std::cout << *q << '\n';
  • int* se lee “puntero a int”. El tipo apuntado le dice al compilador cuántos bytes leer al desreferenciar.
  • *p del lado derecho lee el valor apuntado; del lado izquierdo lo escribe.
  • Desreferenciar un puntero nulo o sin inicializar termina el programa. Por eso todo puntero se inicializa, aunque sea con nullptr.
R8 · Punteros

Cómo se ve en memoria

p es una variable con su propia dirección; lo que guarda dentro es la dirección de x. La flecha existe solo mientras p tenga ese valor.

Checkpoint

Después de int x = 5; int* p = &x; *p = *p + 1;, ¿cuánto vale x?

B. *p designa la variable que está en la dirección guardada en p, que es x. Asignar ahí escribe en x. Para modificar el puntero mismo habría que escribir p = ... sin asterisco (A). La dirección concreta cambia en cada ejecución, pero eso no altera el resultado (C).
R8 · Arreglo y puntero

El arreglo se convierte en puntero


void imprimir(int datos[]) {     // el compilador lee: int* datos
    int n = sizeof(datos) / sizeof(datos[0]);   // 8 / 4 = 2
      

imprimir.cpp:4:20: warning: 'sizeof' on array function parameter
'datos' will return size of 'int*' [-Wsizeof-array-argument]
  • Al pasar un arreglo a una función viaja la dirección de su primer elemento (decaimiento).
  • Dentro de la función datos es un puntero, así que sizeof(datos) son 8 bytes y la división da 2.
  • int datos[], int datos[6] e int* datos producen el mismo código.
R8 · Arreglo y puntero

El tamaño viaja aparte


int suma(const int datos[], int n) {
    int total = 0;
    for (int i = 0; i < n; i++) total += datos[i];
    return total;
}
int main() {
    int v[6] = {1, 2, 3, 4, 5, 6};
    int n = sizeof(v) / sizeof(v[0]);   // aqui v aun es arreglo
    std::cout << suma(v, n) << '\n';    // 21
}
  • El tamaño se calcula donde el arreglo fue declarado y se pasa como parámetro.
  • const int datos[] anuncia que la función solo lee.
  • v[i] y *(v + i) son la misma expresión.
Checkpoint

¿Por qué sizeof(datos)/sizeof(datos[0]) da 2 dentro de void imprimir(int datos[]) en una máquina de 64 bits?

A. El parámetro decayó a int*, y sizeof de un puntero son 8 bytes en 64 bits: 8 entre 4 da 2. No se copia ningún elemento del arreglo (B); solo viaja la dirección del primero. sizeof funciona en cualquier ámbito (C), lo que cambia es el tipo sobre el que se aplica.
R8 · Paso de parámetros

Por valor y por referencia


void porValor(int a) { a = 99; }
void porRef(int& a)  { a = 99; }
int main() {
    int x = 1, y = 1;
    porValor(x);      // x sigue valiendo 1
    porRef(y);        // y ahora vale 99
    std::cout << x << ' ' << y << '\n';   // 1 99
}
  • El paso por valor copia el argumento.
  • Una referencia int& es otro nombre para la misma variable. No se copia nada y toda escritura afecta al original.
  • Una referencia se enlaza al declararse y no se reasigna.
R8 · Paso de parámetros

Referencia constante y criterio para elegir


void mostrar(const std::string& s) { std::cout << s; }
void agregar(std::string& s)       { s += " y Algoritmos"; }
int  doble(int n)                  { return 2 * n; }
SituaciónForma
Tipo pequeño y la función solo leeint n
Objeto grande y la función solo leeconst std::string& s
La función debe modificar el argumentostd::string& s

La referencia constante evita la copia de un objeto grande y deja escrito en la firma que el argumento no se modifica. Para un int la copia cuesta menos que la referencia, así que ahí se pasa por valor.

Checkpoint

Una función recibe un std::string de 4000 caracteres y solo necesita contar sus vocales. ¿Cómo se declara el parámetro?

C. A protege el original pero copia los 4000 caracteres en cada llamada. B evita la copia y deja abierta la puerta a modificar el argumento, lo que obliga a leer el cuerpo de la función para saber si lo hace. La referencia constante junta las dos garantías y es la forma por omisión para objetos grandes de solo lectura.
R8 · Trampas comunes

Cuatro errores de esta sesión

  • Calcular sizeof del arreglo dentro de la función que lo recibe. Ahí ya es un puntero.
  • Declarar int* p, q; creyendo que ambos son punteros. El asterisco se aplica solo a p; q es un int.
  • Devolver la dirección de una variable local. Al terminar la función esa variable deja de existir y el puntero apunta a memoria reutilizable.
  • Recorrer con i <= n. El último índice válido es n - 1, y el compilador no revisa los límites.
R8 · Ejercicio

Tres versiones de intercambiar

Escribe las tres, llámalas desde main con x = 1 y y = 2, e imprime después de cada llamada.


void intercambiar1(int a, int b);      // por valor
void intercambiar2(int* a, int* b);    // por puntero
void intercambiar3(int& a, int& b);    // por referencia
      

void intercambiar1(int a, int b) {
    int t = a; a = b; b = t;           // no cambia nada afuera
}
void intercambiar2(int* a, int* b) {
    int t = *a; *a = *b; *b = t;       // se llama: (&x, &y)
}
void intercambiar3(int& a, int& b) {
    int t = a; a = b; b = t;           // se llama: (x, y)
}

intercambiar1 recibe copias: intercambia los valores de sus dos parámetros locales y los descarta al terminar. Las otras dos reciben la ubicación del original, una escrita con asteriscos y otra sin ellos. Compilar con -Wall -Wextra anticipa el problema: el compilador advierte que los parámetros de la primera versión se asignan y nunca se usan.
