3.1 · Análisis de algoritmos

Por qué medir con reloj no basta

  • El mismo programa tarda distinto según la máquina, el compilador, las banderas de optimización y lo que más corra en ese momento.
  • Una medición con \(n = 10^{3}\) no predice qué pasa con \(n = 10^{7}\): necesitas saber cómo crece el costo con la entrada.
  • El análisis cuenta operaciones como función de n. Es independiente de la máquina y predice el comportamiento antes de ejecutar.
  • Medir sigue siendo útil — al final de la sesión veremos cómo hacerlo bien con <chrono> — pero la medición confirma el análisis, y sin análisis no sabes qué esperar de la medición.

3.1.1 Preliminares matemáticos

3.1.1 · Preliminares matemáticos

Cómo se lee el símbolo de sumatoria

Una sumatoria es un ciclo escrito en matemáticas: el índice \(i\) es el contador, los límites son la cabecera del for y el término general es el cuerpo.

3.1.1 · Preliminares matemáticos

Sumatorias: el costo de un ciclo es una suma

  • Analizar un ciclo es evaluar una sumatoria: si el cuerpo cuesta \(c(i)\) en la vuelta \(i\), el ciclo cuesta \(\sum_{i=1}^{n} c(i)\).
  • Constante (el cuerpo no depende de \(i\)): \(\sum_{i=1}^{n} c = c\,n\).
  • Aritmética: aparece cada vez que un ciclo interno depende del externo.
    \[ \sum_{i=1}^{n} i \;=\; \frac{n(n+1)}{2} \]
  • Al desarrollarla, \(\frac{n(n+1)}{2} = \frac{n^{2}}{2} + \frac{n}{2}\), el segundo término pesa cada vez menos: con \(n = 1000\) aporta el 0.1 %. Al primero lo llamamos término dominante, y es el que da la forma del crecimiento: \(n^{2}\).
3.1.1 · Preliminares matemáticos

Logaritmos: contar cuántas veces se puede dividir

  • \(\log_2 n\) responde una pregunta concreta: ¿cuántas veces divido \(n\) entre 2 hasta llegar a 1? Por eso aparece en todo algoritmo que descarta la mitad.
  • Crece muy despacio. Mil veces más datos, diez pasos más:
    \[ \log_2 10^{3} \approx 10 \qquad \log_2 10^{6} \approx 20 \qquad \log_2 10^{9} \approx 30 \]
  • Cambiar de base multiplica por una constante, así que en notación asintótica la base no importa:
    \[ \log_2 n \;=\; \frac{\log_{10} n}{\log_{10} 2} \]
3.1.1 · Preliminares matemáticos

Series geométricas e inducción

  • Geométrica creciente: la suma completa vale menos que el doble del último término — el último nivel domina.
    \[ 1 + 2 + 4 + \cdots + 2^{k} \;=\; \sum_{i=0}^{k} 2^{i} \;=\; 2^{k+1} - 1 \]
  • Geométrica decreciente (razón \(r < 1\)): un costo que se reduce a la mitad en cada paso suma, en total, una constante por el primer término.
    \[ \sum_{i=0}^{\infty} r^{i} \;=\; \frac{1}{1-r} \]
  • Inducción: la herramienta para demostrar que una fórmula vale para toda \(n\), no solo para los casos que probaste a mano — caso base más paso inductivo. Es el mismo esquema de la hipótesis recursiva de la sesión pasada, y la usaremos en la sesión 4 para verificar soluciones de recurrencias.
Checkpoint

Un ciclo divide \(n\) entre 2 en cada vuelta hasta llegar a 1. Con \(n = 1\,048\,576 = 2^{20}\), ¿cuántas vueltas da?

A. El número de vueltas es \(\log_2 n = 20\). La opción B es \(n/2\) (dividir una vez), y C es \(\sqrt{n}\) — dos confusiones frecuentes. Dividir repetidamente entre 2 llega a 1 en pasos logarítmicos, y esa es la razón de que \(\log n\) aparezca en búsqueda binaria, árboles y heaps.

3.1.2 Contar operaciones

3.1.2 · Contar operaciones

El modelo de costo uniforme

  • Convención: cada operación elemental — asignación, comparación, suma, acceso v[i] — cuesta 1 paso.
  • Es una simplificación deliberada: en el hardware real una suma y un acceso a memoria no cuestan lo mismo, pero difieren en una constante, y la notación asintótica va a absorber las constantes.
  • Con el modelo fijo, el costo de un algoritmo es una función \(T(n)\): número de pasos para una entrada de tamaño \(n\).
3.1.2 · Contar operaciones

Ciclo simple: contar línea por línea


int total = 0;                     // 1
for (int i = 0; i < n; ++i)        // 1 + (n+1) + n
    total += v[i];                 // 2n  (acceso + suma-asignación)
return total;                      // 1
// T(n) = 4n + 4
  • La comparación i < n se evalúa \(n+1\) veces (la última falla); el incremento, \(n\) veces.
  • El conteo exacto depende de qué contamos como "una operación"; la forma lineal no depende de esa convención.
    \[ T(n) \;=\; 1 + \bigl(1 + (n{+}1) + n\bigr) + 2n + 1 \;=\; 4n + 4 \]
3.1.2 · Contar operaciones

Ciclos anidados: multiplicar y sumar


// Anidado completo: el cuerpo corre n · n veces
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j)
        cuenta += m[i][j];               // n² ejecuciones

// Anidado triangular: j arranca en i+1
for (int i = 0; i < n; ++i)
    for (int j = i + 1; j < n; ++j)
        comparar(v[i], v[j]);            // n(n-1)/2 ejecuciones
  • En el triangular, el cuerpo corre la sumatoria aritmética del bloque anterior:
    \[ \sum_{i=0}^{n-1} (n-1-i) \;=\; (n-1) + (n-2) + \cdots + 1 \;=\; \frac{n(n-1)}{2} \]
  • \(\dfrac{n(n-1)}{2} \approx \dfrac{n^{2}}{2}\): la mitad del anidado completo, pero crece igual — como \(n^{2}\).
3.1.2 · Contar operaciones

El ciclo triangular, dibujado

3.1.2 · Contar operaciones

Paso variable: cuando i no avanza de uno en uno


// i se duplica: 1, 2, 4, 8, ..., n  →  log₂ n vueltas
for (int i = 1; i < n; i *= 2)
    procesar(i);

// combinación: ciclo externo log n, interno n
for (int paso = n; paso > 0; paso /= 2)
    for (int i = 0; i < n; ++i)
        comparar(i, i + paso);           // n · log₂ n ejecuciones
  • Multiplicar o dividir el índice produce ciclos logarítmicos; la pregunta correcta es "¿cuántas vueltas hasta salir?", no "¿de cuánto en cuánto va?".
    \[ i = 2^{k} < n \;\Longrightarrow\; k < \log_2 n \]
  • El patrón \(n \log n\) del segundo fragmento reaparecerá en merge sort y en std::sort.
Checkpoint

En el ciclo triangular (j arranca en i+1), ¿cuántas veces corre el cuerpo y cómo crece?

B. El cuerpo corre \((n-1) + (n-2) + \cdots + 1 = n(n-1)/2\) veces. Dividir entre 2 cambia la constante, no la forma: sigue siendo cuadrático. "Empezar más adelante" recorta términos de la suma pero el promedio del ciclo interno sigue siendo \(\sim n/2\) — de ahí el error de las opciones A y C.

3.1.3 · Notación asintótica

La definición formal de O grande

\[ f(n) = O\bigl(g(n)\bigr) \iff \exists\, c > 0,\; n_0 \;:\; f(n) \le c \cdot g(n) \quad \forall\, n \ge n_0 \]
  • En palabras: a partir de cierto tamaño, \(f\) queda por debajo de un múltiplo fijo de \(g\). Es una cota superior sobre el crecimiento: un techo que el costo ya no rebasa.
  • Ejemplo, con \(c = 6\) y \(n_0 = 2\):
    \[ 4n + 4 \le 6n \quad \forall\, n \ge 2 \;\Longrightarrow\; 4n + 4 = O(n) \]
  • La \(c\) absorbe constantes y la \(n_0\) descarta tamaños chicos: ambas hacen que la etiqueta hable solo del crecimiento.
3.1.3 · Notación asintótica

La misma definición, dibujada

Con \(c = 5\) y \(n_0 = 20\): \(3n + 40 \le 5n\) para toda \(n \ge 20\), es decir \(3n + 40 = O(n)\). Antes de \(n_0\) la curva de \(f\) va por arriba de \(c\,g\), y la definición lo permite: solo exige que a partir de algún punto deje de hacerlo.

3.1.3 · Notación asintótica

Para qué te sirve encontrar \(c\) y \(n_0\)

En el día a día escribes solo la etiqueta; la pareja es lo que la sostiene.

  • Es la prueba. Decir "esto es \(O(n)\)" sin exhibir una pareja es una conjetura; con ella, queda demostrado.
  • \(c\) marca qué es negociable. Compilador, caché y costo por operación mueven \(c\) y dejan igual la forma del crecimiento: ahí está la frontera entre optimizar y cambiar de algoritmo.
  • \(n_0\) es la letra chica. Por debajo de ese tamaño la notación calla, y por eso std::sort cambia a inserción en tramos cortos.
  • Lo usas la próxima sesión: verificar una recurrencia por sustitución es proponer una cota y demostrarla con una \(c\) concreta.
3.1.3 · Ejemplo resuelto

Cómo se elige \(c\) y \(n_0\) en la práctica

Una vez, para justificar la etiqueta: el ciclo simple de hace rato es \(O(n)\).

  • 1. Escribe la desigualdad. Con \(T(n) = 4n + 4\), buscas \(c\) y \(n_0\) tales que \(4n + 4 \le c\,n\) desde \(n_0\).
  • 2. Prueba una \(c\) mayor que el coeficiente y despeja \(n\). Con \(c = 6\):
    \[ 4n + 4 \le 6n \iff 4 \le 2n \iff n \ge 2 \]
  • 3. El umbral es lo que quedó: \(n_0 = 2\). En el límite: \(T(2) = 12 = 6 \cdot 2\).

La pareja no es única: con \(c = 5\) vale desde \(n_0 = 4\); con \(c = 8\), desde \(n_0 = 1\). Mientras más justa la \(c\), más tarde arranca el umbral.

3.1.3 · Notación asintótica

Dos casos que la intuición no resuelve

Con \(4n + 4\) nadie necesita la definición. Con estos dos, sí — y se parecen entre sí.

  • ¿Es \(2^{\,n+1} = O(2^{n})\)? Sí. \(2^{\,n+1} = 2 \cdot 2^{n}\), así que \(c = 2\) sirve desde \(n_0 = 1\): la constante absorbe el factor.
  • ¿Es \(2^{\,2n} = O(2^{n})\)? No. \(2^{\,2n} = (2^{n})^{2}\), y el cociente entre ambas es \(2^{n}\), que crece sin límite. Ninguna \(c\) fija alcanza.
    \[ \frac{2^{\,2n}}{2^{n}} = 2^{n} \longrightarrow \infty \]
  • Se ven casi igual y la respuesta es opuesta. Cuando el caso no es evidente, la definición es lo único que decide.
3.1.3 · Notación asintótica

Ω acota por abajo, Θ ajusta

NotaciónDefiniciónSe lee
\(f = O(g)\)\(f(n) \le c\,g(n)\) desde \(n_0\)\(f\) no crece más rápido que \(g\)
\(f = \Omega(g)\)\(f(n) \ge c\,g(n)\) desde \(n_0\)\(f\) no crece más despacio que \(g\)
\(f = \Theta(g)\)\(O(g)\) y \(\Omega(g)\) a la vez\(f\) crece exactamente como \(g\)
\[ c_1 n^{2} \;\le\; 3n^{2} + 50n \;\le\; c_2 n^{2} \quad \forall\, n \ge n_0 \;\Longrightarrow\; 3n^{2} + 50n = \Theta(n^{2}) \]
  • \(\Theta\) es la afirmación más fuerte: acota por arriba y por abajo. Si puedes decir \(\Theta\), decir solo \(O\) informa menos.
  • Todo esto habla de crecimiento, no de segundos: \(\Theta(n^{2})\) dice que al duplicar \(n\) el costo se cuadruplica.
3.1.3 · Notación asintótica

Tres errores frecuentes

  • "O significa peor caso." Son cosas independientes: el peor caso es qué entrada analizas; \(O\), \(\Omega\) y \(\Theta\) son cotas sobre la función resultante. Se puede dar la \(\Theta\) del mejor caso y la \(O\) del promedio.
  • "Es \(O(2n)\)". La constante ya está absorbida por la \(c\) de la definición; escribirla sugiere que la notación distingue algo que no distingue.
    \[ O(2n) = O(n) \qquad O(n^{2} + n) = O(n^{2}) \]
  • "Las constantes no importan". No aparecen en la notación, pero en la práctica deciden: para las \(n\) de tu problema, una \(O(n^{2})\) con constante chica puede ganarle a una \(O(n \log n)\) con constante grande. La gráfica siguiente lo muestra.
3.1.3 · Notación asintótica

Cómo crecen las curvas

3.1.3 · Notación asintótica

Constante y exponente son palancas distintas

  • Mejorar la constante (mejor caché, menos trabajo por iteración, paralelismo) desplaza la curva hacia abajo y mueve el punto de cruce.
  • Mejorar el exponente (otro algoritmo) cambia la forma de la curva: a partir de algún n, gana contra cualquier constante.
  • Truco de lectura: en escala log-log toda potencia \(n^{k}\) es una recta de pendiente \(k\). Dos implementaciones del mismo algoritmo son rectas paralelas; dos algoritmos distintos tienen pendientes distintas.
    \[ T(n) = c\,n^{k} \;\Longrightarrow\; \log T = k \log n + \log c \]
Checkpoint

Un algoritmo es \(O(n^{2})\). ¿Cuál afirmación es necesariamente cierta?

B. Eso es exactamente la definición: \(O\) da una cota superior con constante y umbral. No dice "exactamente \(n^{2}\)" (podría incluso ser \(O(n)\): la cota no tiene que ser ajustada), y no ordena algoritmos para entradas concretas — con \(n\) chico o constantes favorables, el \(O(n^{2})\) puede ganar, como vimos en la gráfica.
Ejemplo resuelto

Del código a la Θ, paso a paso


for (int i = 0; i < n; ++i)          // bloque 1
    v[i] = i;

for (int i = 0; i < n; ++i)          // bloque 2
    for (int j = 0; j < n; ++j)
        m[i][j] = v[i] * v[j];
  • 1. Cuenta cada bloque por separado. El primero da \(n\) vueltas; el segundo, \(n \cdot n\).
  • 2. Suma los bloques (van uno después del otro, no anidados): \(T(n) = a\,n + b\,n^{2}\).
  • 3. Quédate con el término dominante y concluye. Para \(n\) grande \(b\,n^{2}\) supera a \(a\,n\) valgan lo que valgan \(a\) y \(b\), así que \(T(n) = \Theta(n^{2})\): el bloque 1 no cambia nada.
Ejercicio en clase

Cinco fragmentos: den la Θ y justifiquen


// A                                  // B
for (i = 0; i < n; i += 2) f();      for (i = 1; i < n; i *= 3) f();

// C                                  // D
for (i = 0; i < n; ++i)              for (i = 0; i < n; ++i)
  for (j = 0; j < 100; ++j) f();       for (j = n; j > 1; j /= 2) f();

// E
for (i = 0; i < n; ++i)
  for (j = 0; j < i * i; ++j) f();

Misma receta que el ejemplo anterior: cuenta las vueltas, escríbelas como sumatoria, quédate con el término dominante y concluye con \(\Theta\). La justificación vale más que la letra griega.

Por qué importa hoy

La atención de un Transformer es \(O(n^{2})\)

  • En el bloque de atención, cada token del contexto se compara con todos los demás: \(n\) tokens \(\to n^{2}\) comparaciones. Es el ciclo anidado completo de hoy, en tamaño industrial.
  • Esa sola cota explica por qué las ventanas de contexto crecieron tan lento: duplicar el contexto cuadruplica el costo del bloque de atención.
    \[ T(2n) = c\,(2n)^{2} = 4\,c\,n^{2} = 4\,T(n) \]
  • El costo total del modelo crece menos que eso, porque tiene términos lineales en \(n\) que dominan hasta que \(n\) es grande — el mismo juego de término dominante que hicimos con \(n(n+1)/2\).
Por qué importa hoy

FlashAttention mejora la constante

  • FlashAttention hace la atención varias veces más rápida sin cambiar la \(O(n^{2})\) de cómputo: reorganiza los accesos para reducir el tráfico con la memoria de la GPU y baja la memoria extra de \(O(n^{2})\) a \(O(n)\).
  • La atención dispersa y la atención lineal sí atacan el exponente: cambian el algoritmo para no comparar todo contra todo.
  • Leer correctamente un paper de eficiencia exige la distinción de hoy: ¿mejoró la constante o mejoró el exponente? La respuesta decide si la mejora aguanta cuando n se multiplica por 100.
Checkpoint

FlashAttention acelera la atención en la práctica. En términos de hoy, ¿qué mejoró?

C. El cómputo sigue siendo \(\Theta(n^{2})\); lo que cambió es cuánto cuesta cada unidad de ese cómputo (menos idas a memoria lenta). La opción B comete el error inverso al de "\(O(2n)\)": la notación ignora constantes, pero el reloj no — una constante 5 veces menor son GPUs 5 veces más baratas.

El estándar especifica complejidad, no implementación

OperaciónGarantía del estándar

Cierre STL

Medir bien con <chrono>


auto t0 = std::chrono::steady_clock::now();
ordenar(v);
auto t1 = std::chrono::steady_clock::now();

auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(t1 - t0);
  • steady_clock es monotónico: sirve para medir intervalos. system_clock puede saltar (ajustes de hora) y no sirve para esto.
  • Compila con -O2. Medir un binario -O0 no dice nada útil: el optimizador cambia las constantes por completo, y a veces elimina el código que creías medir.
  • Repite la medición con varios n y compara la forma del crecimiento contra tu análisis, no un solo número.
