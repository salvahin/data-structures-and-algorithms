6.1 Administración de memoria

6.1 · Administración de memoria

Dos regiones con reglas distintas

Stack

  • Variables locales; se libera sola al salir del scope.
  • Tamaño conocido en compilación.
  • Rápida: mover un puntero de tope.

Heap

  • Se pide con new; vive hasta que alguien la libere con delete.
  • Tamaño decidido en ejecución.
  • La responsabilidad de liberarla es del programador.

Toda estructura enlazada de este bloque vive en el heap: los nodos se crean y destruyen uno por uno, en tiempo de ejecución.

6.1 · Administración de memoria

new y delete: el par que debe cerrarse


int* p = new int(42);     // reserva un int en el heap
delete p;                 // lo libera; p queda apuntando a basura

int* arr = new int[n];    // reserva un arreglo de n ints
delete[] arr;             // forma correcta para arreglos

Nodo* nodo = new Nodo{7, nullptr};   // objeto con inicializador
delete nodo;              // llama al destructor y libera
  • Cada new tiene exactamente un delete; cada new[], un delete[].
  • Mezclar los pares (new[] con delete) es comportamiento indefinido.

Los tres errores clásicos

  • Fuga — perder el último puntero a un bloque sin haberlo liberado. El bloque queda ocupado hasta que el proceso muere.
  • Puntero colgante — usar un puntero después de liberar el bloque al que apunta (use-after-free).
  • Doble liberación — hacer delete dos veces sobre el mismo bloque; corrompe las estructuras internas del asignador.

Ninguno de los tres falla de inmediato: son comportamiento indefinido. El programa puede correr bien hoy y fallar mañana con otros datos, otro compilador u otra carga.

Checkpoint

Después de ejecutar delete p;, ¿qué contiene p?

B. delete libera el bloque pero no toca la variable puntero: queda colgante. Ni el compilador ni el runtime detectan el uso posterior (opciones A y C describen lenguajes con recolector o verificación, no C++). Por eso conviene asignar p = nullptr; tras liberar cuando el puntero sobrevive.

6.2 Apuntadores y referencias

6.2 · Apuntadores y referencias

El puntero: una dirección con tipo


int x = 10;
int* p = &x;      // p guarda la direccion de x
*p = 20;          // desreferencia: modifica x a traves de p

int arr[4] = {3, 1, 4, 1};
int* q = arr;     // el nombre del arreglo decae a puntero

q + 1;            // avanza sizeof(int) bytes, no 1 byte
arr[i];           // equivale a *(arr + i)
  • La aritmética de punteros trabaja en unidades del tipo apuntado; el compilador multiplica por sizeof(T).
  • Un puntero puede valer nullptr, reasignarse, o apuntar a basura si no se inicializa.
6.2 · Apuntadores y referencias

Referencias y punteros a punteros


int x = 10;
int& r = x;       // alias: r ES x, no una copia
r = 20;           // modifica x; r no puede re-ligarse a otra variable

void pushFront(Nodo*& head, int v) {   // referencia a puntero
    head = new Nodo{v, head};          // el caller ve el cambio
}
// alternativa equivalente en C: Nodo** head
// y dentro: *head = new Nodo{v, *head};
  • Una referencia siempre está ligada a algo válido: sin nullptr, sin reasignación.
  • Para que una función modifique el puntero mismo (p. ej. head, el puntero al primer nodo de una lista), recibe Nodo*& o Nodo**.

Checkpoint

Esta función no funciona: void pushFront(Nodo* head, int v) { head = new Nodo{v, head}; }. ¿Por qué?

C. Un puntero se copia como cualquier otro valor: la función modifica su copia y el head original queda igual (el nodo nuevo además se fuga). La firma correcta es Nodo*& head. La opción A liberaría un nodo que sigue en uso; la B es falsa — new siempre reserva en el heap.

STL

Punteros inteligentes: liberar sin acordarse


auto p = std::make_unique<Nodo>(7);   // dueño unico
// no hay delete: se libera solo al salir del scope,
// incluso si una excepcion interrumpe la funcion

auto q = std::make_shared<Nodo>(9);   // dueños multiples
// se libera cuando el ultimo shared_ptr muere (contador)
  • El patrón se llama RAII: el recurso se libera en el destructor del objeto que lo posee, y el compilador garantiza que ese destructor corre.
  • Regla moderna: new y delete explícitos casi no aparecen en código nuevo. Hoy los escribimos para entender qué hace el puntero inteligente por nosotros.
