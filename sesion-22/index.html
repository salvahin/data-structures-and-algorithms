8.2.3.1 DFS: búsqueda en profundidad

8.2.3.1 · DFS

La regla de DFS

  • Desde el vértice actual, avanza hacia un vecino no visitado; solo cuando ya no hay vecinos nuevos, retrocede.
  • Los pendientes viven en una pila (LIFO): en la versión recursiva, la pila de llamadas del programa; en la iterativa, un std::stack explícito.
  • Marcar visitados es obligatorio: sin la marca, cualquier ciclo hace que el recorrido dé vueltas para siempre.
  • Con lista de adyacencias cuesta \(O(V + E)\): cada vértice se visita una vez y cada arista se revisa un número constante de veces.
8.2.3.1 · DFS

DFS recursivo, línea por línea

8.2.3.1 · DFS

DFS recursivo


void dfs(int u) {
    visitado[u] = true;
    visita(u);
    for (int v : ady[u]) {
        if (!visitado[v]) {
            dfs(v);
        }
    }
}

ady es la lista de adyacencias y visitado un std::vector<bool> de tamaño n que empieza en false. visita es lo que haga el algoritmo con cada vértice.

La recursión se encarga del retroceso: cuando termina el for de un vértice, el control regresa a la llamada que lo invocó.

En grafos muy profundos la pila de llamadas puede desbordarse; para eso existe la versión iterativa.

8.2.3.1 · DFS

DFS iterativo con std::stack

8.2.3.1 · DFS

DFS iterativo


void dfsIter(int inicio) {
    std::stack<int> pila;
    pila.push(inicio);
    while (!pila.empty()) {
        int u = pila.top();
        pila.pop();
        if (!visitado[u]) {
            visitado[u] = true;
            visita(u);
            for (int v : ady[u]) {
                if (!visitado[v]) {
                    pila.push(v);
                }
            }
        }
    }
}

Un vértice puede entrar a la pila dos veces, desde dos vecinos distintos, antes de procesarse. Por eso la marca se revisa al sacarlo, en if (!visitado[u]).

Sin ese if, el vértice repetido se visitaría dos veces.

El orden sale distinto al de la versión recursiva porque el último vecino apilado es el primero en salir. Los dos órdenes son recorridos en profundidad.

8.2.3.1 · DFS

Qué se resuelve con DFS

  • Componentes conexos: lanzar DFS desde cada vértice sin visitar; cada lanzamiento pinta un componente completo.
  • Detección de ciclos: en un grafo no dirigido, una arista hacia un vértice visitado que no es el padre delata un ciclo (en la simulación pasó con la arista 0–2). En dirigidos, el ciclo aparece como una arista hacia un vértice que sigue en la pila de llamadas.
  • Laberintos, backtracking y orden topológico por DFS: todo lo que se formula como «explora hasta el fondo y regresa».
8.2.3.1 · DFS

Componentes conexos: un DFS por cada vértice sin visitar


int componentes() {
    int c = 0;
    for (int u = 0; u < n; u++) {
        if (!visitado[u]) {
            dfs(u);
            c = c + 1;
        }
    }
    return c;
}

El for prueba los vértices en orden. El 1 y el 2 ya quedaron visitados por dfs(0), así que el siguiente que lanza un recorrido es el 3.

Checkpoint

En tu DFS olvidaste marcar los vértices como visitados. El grafo tiene un ciclo. ¿Qué pasa?

B. La marca de visitado es lo único que impide volver a entrar a un vértice ya explorado. Con un ciclo A→B→C→A y sin marcas, el DFS recorre ese ciclo sin fin (en la versión recursiva, hasta desbordar la pila de llamadas). Es un error clásico porque el algoritmo se ve completo, compila y funciona bien en grafos sin ciclos.

8.2.3.2 BFS: búsqueda en anchura

8.2.3.2 · BFS

La regla de BFS

  • Visita primero todos los vértices a distancia 1 del origen, luego los de distancia 2, y así por niveles.
  • Los pendientes viven en una fila (FIFO): los vértices se procesan en el orden en que fueron descubiertos.
  • El arreglo de distancias sirve además como registro de visitados: dist[v] == -1 significa «no descubierto».
  • Cuesta \(O(V + E)\), igual que DFS: cambia el orden de visita, no el costo.
8.2.3.2 · BFS

BFS con distancias, línea por línea

8.2.3.2 · BFS

BFS con distancias


std::vector<int> bfs(int inicio) {
    std::vector<int> dist(n, -1);
    std::queue<int> fila;
    dist[inicio] = 0;
    fila.push(inicio);
    while (!fila.empty()) {
        int u = fila.front();
        fila.pop();
        for (int v : ady[u]) {
            if (dist[v] == -1) {
                dist[v] = dist[u] + 1;
                fila.push(v);
            }
        }
    }
    return dist;
}

BFS marca al descubrir: dist[v] cambia antes de encolar, así que cada vértice entra a la fila una sola vez.

Un vértice que no se alcanza desde el origen termina con dist == -1.

¿Por qué aquí se marca al meter y en el DFS iterativo al sacar? En BFS, la primera vez que se descubre un vértice ya se conoce su distancia mínima, así que marcarlo ahí es correcto y evita que entre dos veces a la fila. En el DFS iterativo, marcar al meter deja al vértice con quien lo vio primero, y el orden deja de ser en profundidad.

8.2.3.2 · BFS vs DFS

El contenedor decide el recorrido

8.2.3.2 · BFS

Por qué BFS da el camino más corto

  • La fila procesa los vértices en orden de distancia: primero todos los de distancia d, después los de d + 1. Nunca se mezclan.
  • Cuando un vértice se descubre, se descubre desde el nivel más cercano posible. Cualquier otro camino hasta él llegaría igual de lejos o más tarde.
  • DFS no tiene esa propiedad. En la simulación llegó al 2 por el camino 0, 1, 4, 5, 2, de cuatro aristas, aunque el 2 es vecino directo del 0.

La garantía vale para grafos no ponderados. Con pesos distintos por arista se usa Dijkstra, que cambia la fila por una fila de prioridad: el heap del bloque de árboles.

Checkpoint

Tomas el código de BFS y cambias std::queue por std::stack, sin tocar nada más. ¿Qué obtienes?

B. Toda la diferencia entre BFS y DFS está en qué contenedor guarda la frontera: FIFO procesa por niveles, LIFO se hunde por el último descubierto. Con pila, un vértice puede descubrirse por un camino largo antes que por el corto, y el valor que quede en dist ya no es mínimo. Es el error conceptual más común del bloque de grafos.

8.2.3.3 Ordenamiento topológico

8.2.3.3 · Orden topológico

Ordenar respetando dependencias

  • Un orden topológico de un grafo dirigido es una lista de sus vértices donde toda arista (u, v) tiene a u antes que a v.
  • Existe si y solo si el grafo es un DAG: con un ciclo, alguien tendría que ir antes que sí mismo.
  • Un DAG puede admitir muchos órdenes válidos; el algoritmo produce uno.
  • Ejemplos: materias y prerrequisitos, tareas de un build, dependencias entre paquetes.
8.2.3.3 · Orden topológico

Primero, contar las flechas que llegan


std::vector<int> gradosEntrada() {
    std::vector<int> ge(n, 0);
    for (int u = 0; u < n; u++) {
        for (int v : ady[u]) {
            ge[v] = ge[v] + 1;
        }
    }
    return ge;
}

El grado de entrada ge[v] cuenta cuántos vértices tienen que ir antes que v. Un vértice con ge[v] == 0 puede ir ya.

Recorre todas las listas una vez: \(O(V + E)\).

8.2.3.3 · Orden topológico

Algoritmo de Kahn, paso a paso

8.2.3.3 · Orden topológico

Kahn en C++


std::vector<int> kahn() {
    std::vector<int> ge = gradosEntrada();
    std::queue<int> listos;
    for (int u = 0; u < n; u++) {
        if (ge[u] == 0) {
            listos.push(u);
        }
    }
    std::vector<int> orden;
    while (!listos.empty()) {
        int u = listos.front();
        listos.pop();
        orden.push_back(u);
        for (int v : ady[u]) {
            ge[v] = ge[v] - 1;
            if (ge[v] == 0) {
                listos.push(v);
            }
        }
    }
    return orden;
}

La fila de listos guarda los vértices que ya no esperan a nadie. Cada vez que uno sale, sus flechas de salida se cumplen y los grados bajan.

Cada vértice entra una vez a la fila y cada flecha se descuenta una vez: \(O(V + E)\).

Si orden.size() es menor que n, el grafo tiene un ciclo.

8.2.3.3 · Orden topológico

El mismo grafo con una flecha más: 2→1

8.2.3.3 · Orden topológico

La variante por DFS

  • Se corre DFS y cada vértice se anota al terminar su llamada. La lista invertida es un orden topológico.
  • Funciona porque un vértice solo termina cuando ya terminaron todos los que tienen que ir después de él.
  • Para detectar ciclos, cada vértice lleva uno de tres estados: NUEVO, ABIERTO (su llamada sigue en la pila) o CERRADO. Una flecha hacia un vértice ABIERTO cierra un ciclo.

8.2.3.3 · Orden topológico

Orden topológico por DFS en C++


const int NUEVO = 0;
const int ABIERTO = 1;
const int CERRADO = 2;

std::vector<int> ordenTopoDfs() {
    estado.assign(n, NUEVO);
    terminados.clear();
    hayCiclo = false;
    for (int u = 0; u < n; u++) {
        if (estado[u] == NUEVO) {
            dfsTopo(u);
        }
    }
    std::reverse(terminados.begin(), terminados.end());
    return terminados;
}

estado y terminados son std::vector<int> y hayCiclo un bool, visibles para las dos funciones. dfsTopo es la de la simulación.

El for lanza un DFS desde cada vértice que siga NUEVO, igual que al contar componentes. Así se cubren los vértices que ningún recorrido anterior alcanzó.

Los dos algoritmos detectan el ciclo sin trabajo extra: en Kahn, porque orden.size() queda menor que n; aquí, porque hayCiclo termina en true. Los dos cuestan \(O(V + E)\).

Checkpoint

Corres Kahn sobre un grafo dirigido de 8 vértices y el orden resultante tiene 5. ¿Qué concluyes?

B. Un vértice solo entra al orden cuando su grado de entrada llega a 0. Los que participan en un ciclo se esperan mutuamente y ninguno lo alcanza jamás. La opción A no aplica: los vértices aislados tienen grado de entrada 0 y entran a la fila desde el inicio. La C tampoco: el conjunto de vértices procesados no depende del orden en que se saquen, solo la secuencia.

Por qué importa hoy

El backward de PyTorch es Kahn

  • La retropropagación recorre el grafo de cómputo en orden topológico inverso: ningún nodo puede procesar su gradiente antes que quienes dependen de él.
  • En modo eager, PyTorch no ordena nada hacia adelante — ejecuta tu código tal cual y construye el grafo como subproducto. El motor de autograd resuelve el backward con conteo de dependencias sobre una cola de listos: Kahn, distribuido.
  • En los compiladores de grafo (torch.compile, XLA) el orden topológico es explícito también hacia adelante, para programar y fusionar operaciones.
  • Y el BFS multi-salto es como GraphRAG expande contexto: desde la entidad mencionada, traer vecinos a distancia 1 y 2.
