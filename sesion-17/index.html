Repaso · Altura

Altura: la recursión modelo


int altura(Nodo* n) {
    if (n == nullptr) return -1;
    int hIzq = altura(n->izq);
    int hDer = altura(n->der);
    if (hIzq > hDer) return hIzq + 1;
    return hDer + 1;
}
  • Visita cada nodo una vez: O(n). No hay forma de conocer la altura sin mirar todas las ramas.
  • El patrón — resolver en los hijos, combinar en el padre — es la plantilla de casi todo lo demás de hoy.

Repaso · Validación

El check correcto: cotas que se heredan


bool esBST(Nodo* n, Nodo* piso, Nodo* techo) {
    if (n == nullptr) return true;
    int x = n->dato;
    if (piso != nullptr && x <= piso->dato)
        return false;
    if (techo != nullptr && x >= techo->dato)
        return false;
    if (!esBST(n->izq, piso, n)) return false;
    return esBST(n->der, n, techo);
}

El hijo izquierdo hereda techo = n y el derecho hereda piso = n. Llamada inicial: esBST(raiz, nullptr, nullptr). Cada nodo se revisa una vez: O(n).

Checkpoint

¿Por qué falla el check que compara cada nodo solo con sus dos hijos?

C. En el contraejemplo, 50 cumple con su padre (50 > 20) pero rompe la cota que le impone 40 desde dos niveles arriba. El check local es O(n) igual que el correcto (la opción A no es el problema); lo que le falta es propagar el intervalo válido hacia abajo.

Repaso · K-ésimo menor

K-ésimo menor en código


Nodo* kesimo(Nodo* n, int k, int& vistos) {
    if (n == nullptr) return nullptr;
    Nodo* izq = kesimo(n->izq, k, vistos);
    if (izq != nullptr) return izq;
    vistos = vistos + 1;
    if (vistos == k) return n;
    return kesimo(n->der, k, vistos);
}

Llamada inicial: int vistos = 0; y kesimo(raiz, k, vistos). Costo O(h + k): bajar hasta el mínimo y contar k nodos.

Repaso · Ancestro común más bajo

LCA: donde los caminos se separan


Nodo* lca(Nodo* n, int a, int b) {
    while (n != nullptr) {
        int x = n->dato;
        if (a < x && b < x)
            n = n->izq;
        else if (a > x && b > x)
            n = n->der;
        else
            return n;
    }
    return nullptr;
}

Un solo camino desde la raíz: O(h). Supone que las dos claves están en el árbol.

Repaso · Consulta por rango

Rango en código: dos podas y una visita


void rango(Nodo* n, int a, int b,
           std::vector<int>& salida) {
    if (n == nullptr) return;
    if (a < n->dato)
        rango(n->izq, a, b, salida);
    if (a <= n->dato && n->dato <= b)
        salida.push_back(n->dato);
    if (n->dato < b)
        rango(n->der, a, b, salida);
}

Costo O(k + h): k nodos reportados más los nodos frontera donde el camino entra y sale del rango. Ese análisis va documentado en tu entrega.

Checkpoint

Un BST balanceado tiene un millón de claves y la consulta rango(a, b) devuelve 12 elementos. ¿Cuántos nodos visita, aproximadamente?

B. La poda descarta subárboles completos fuera del rango, así que el costo depende de lo que sí se reporta (k) más la frontera (O(h) ≈ 20 aquí). La opción C ignora que reportar k elementos obliga a visitarlos: si el rango cubriera medio árbol, la consulta costaría medio millón de visitas aunque h siga siendo 20.

Por qué importa hoy

Consultas por rango en búsqueda vectorial

  • Una búsqueda semántica devuelve los documentos cuyos embeddings quedan más cerca de la consulta. Casi siempre lleva además un filtro sobre metadatos: "solo los publicados desde 2024".
  • Ese filtro es una consulta por rango sobre un campo ordenado y se resuelve con un índice de árbol, sin tocar los embeddings. En PostgreSQL con la extensión pgvector, la fecha se indexa con un B-tree.
  • Si el filtro se aplica después de la búsqueda de vecinos, puede dejar menos de k resultados. Por eso los motores deciden si filtran antes o después según cuántos documentos pasan el filtro.
STL

Rangos sobre std::map


std::map<int, std::string> m = /* ... */;
auto ini = m.lower_bound(35);     // primera clave >= 35
auto fin = m.upper_bound(65);     // primera clave >  65
for (auto it = ini; it != fin; ++it)
    procesar(*it);                // [35, 65] en orden: O(k + log n)

std::distance(ini, fin);          // ¡O(n)! iteradores bidireccionales:
                                  // contar exige caminar uno a uno
  • lower_bound / upper_bound son la versión de biblioteca de tu consulta por rango.
  • std::distance sobre un map recorre elemento por elemento: el árbol no guarda tamaños de subárbol, así que contar un rango cuesta O(n) y no O(1).
