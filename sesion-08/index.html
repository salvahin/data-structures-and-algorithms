5.3 Insertion Sort

5.3 · Insertion Sort

La idea: insertar en una zona ya ordenada

  • Es la forma en que ordenas cartas en la mano: tomas la siguiente y la deslizas hacia la izquierda hasta su lugar. (Usaremos esa imagen en el pizarrón.)
  • Invariante: al inicio de la pasada i, el prefijo a[0..i−1] está ordenado.
  • La pasada i toma a[i] y lo inserta en su posición dentro del prefijo, desplazando a la derecha los elementos mayores.
5.3 · Insertion Sort

Sobre datos casi ordenados: el mejor caso en acción

5.3 · Insertion Sort

Codificación: desplazar, no intercambiar


void insertionSort(std::vector<int>& a) {
    for (int i = 1; i < (int)a.size(); ++i) {
        int x = a[i];          // el elemento a insertar
        int j = i - 1;
        while (j >= 0 && a[j] > x) {
            a[j + 1] = a[j];   // desplaza una posición a la derecha
            --j;               // el hueco se corrió: ahora está en j+1
        }
        a[j + 1] = x;          // por eso x cae justo en j+1
    }
}
  • Desplazar en vez de swap: una asignación, no tres.
  • Sobre --j y j--: aquí son idénticos.
  • Comparación estricta: no mueve los iguales, así que es estable.
5.3 · Insertion Sort

Análisis: el costo son las inversiones

CasoCostoPor qué
Mejor (ya ordenado)O(n)el while nunca entra: una comparación por elemento
Peor (inverso)O(n²)cada elemento cruza todo el prefijo
GeneralO(n + d)d = número de inversiones de la entrada
  • Con pocas inversiones — datos casi ordenados — el costo es casi lineal. Por eso es el algoritmo elemental que sobrevive en la práctica: std::sort lo usa para rangos pequeños y Timsort (Python) lo usa para tramos.
  • Constantes pequeñas, acceso secuencial a memoria, estable y en sitio.
Checkpoint

Un arreglo de n elementos está casi ordenado: cada elemento está a lo más a 2 posiciones de su lugar final. ¿Cuánto cuesta Insertion Sort?

B. El costo real es O(n + d) con d inversiones; si nadie está a más de 2 posiciones de su lugar, d ≤ 2n y el total es O(n). La opción A confunde el peor caso del algoritmo con el costo de esta entrada. La C malinterpreta la cota Ω(n log n): aplica al peor caso sobre todas las entradas, no prohíbe entradas fáciles baratas.
5.3 · Insertion Sort

Los tres elementales, lado a lado

MejorPeorMovimientosEstable

Insertion combina lo mejor de los otros dos: sensible al orden como Bubble, con movimientos baratos. La barrera que ninguno de los tres cruza es el O(n²) del peor caso.

5.4 Merge Sort

5.4 · Merge Sort

Divide y vencerás aplicado a ordenar

  • Dividir: partir el arreglo en dos mitades. Costo O(1): solo calcular el punto medio.
  • Vencer: ordenar cada mitad recursivamente. Caso base: 0 o 1 elementos ya están ordenados.
  • Combinar: fusionar dos mitades ordenadas en una sola secuencia ordenada. Costo Θ(n) — aquí vive todo el trabajo.

Es el mismo esquema que analizamos en la sesión 4; hoy lo codificamos completo y verificamos la recurrencia.

5.4 · Merge Sort

Dos actos: dividir hacia abajo, fusionar hacia arriba

5.4 · Merge Sort

La fusión, elemento por elemento

Cada elemento se copia una sola vez: fusionar cuesta Θ(n). En los empates gana la izquierda, y eso lo mantiene estable.

5.4 · Merge Sort

merge: el diagrama anterior, en código


void merge(int a[], int aux[], int lo, int mid, int hi) {
    for (int p = lo; p <= hi; ++p) aux[p] = a[p];   // copia el tramo a trabajar

    int i = lo;          // siguiente sin usar de la mitad izquierda
    int j = mid + 1;     // siguiente sin usar de la mitad derecha
    for (int k = lo; k <= hi; ++k) {                // llena a[lo..hi] en orden
        if      (i > mid)            { a[k] = aux[j]; ++j; }   // izquierda vacía
        else if (j > hi)             { a[k] = aux[i]; ++i; }   // derecha vacía
        else if (aux[i] <= aux[j])   { a[k] = aux[i]; ++i; }
        else                         { a[k] = aux[j]; ++j; }
    }
}
  • En aux las dos mitades quedan una junto a la otra: lo..mid y mid+1..hi.
5.4 · Merge Sort

El algoritmo completo


void mergeSort(int a[], int aux[], int lo, int hi) {
    if (lo >= hi) return;              // 0 o 1 elementos: ya está ordenado
    int mid = lo + (hi - lo) / 2;      // el punto medio seguro de la sesión 6
    mergeSort(a, aux, lo, mid);        // ordena la mitad izquierda
    mergeSort(a, aux, mid + 1, hi);    // ordena la mitad derecha
    merge(a, aux, lo, mid, hi);        // fusiona las dos
}

int datos[6] = {38, 27, 43, 3, 9, 82};
int aux[6];                            // el auxiliar se crea una sola vez
mergeSort(datos, aux, 0, 5);

El auxiliar se reserva una vez y todas las llamadas lo reutilizan, así que la memoria extra es O(n) en total, no por llamada.

5.4 · Merge Sort

La versión corta, con la biblioteca estándar


void mergeSort(std::vector<int>& a, int lo, int hi) {
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, lo, mid);
    mergeSort(a, mid + 1, hi);
    std::inplace_merge(a.begin() + lo, a.begin() + mid + 1, a.begin() + hi + 1);
}
  • std::inplace_merge recibe inicio, punto medio y fin, y hace la fusión que acabas de escribir a mano.
  • Mismo trabajo: Θ(n) por nivel y Θ(n log n) en total. En producción se usa esta; la anterior enseña qué hay debajo.
5.4 · Merge Sort

La recurrencia, resuelta

T(n) = 2·T(n/2) + Θ(n)

  • Árbol de recursión: cada nivel suma Θ(n) (las fusiones de ese nivel cubren el arreglo completo) y hay log₂n + 1 niveles → Θ(n log n).
  • Teorema Maestro: a = 2, b = 2, f(n) = Θ(n) = Θ(n^log₂2) → caso 2 → Θ(n log n).
  • En todos los casos: la división no mira los datos, así que entrada ordenada, inversa o aleatoria cuestan lo mismo. Contrasta con Insertion.
  • El precio: O(n) de memoria auxiliar para el merge. Merge Sort clásico no ordena en sitio.
Checkpoint

Merge Sort recibe un arreglo ya ordenado. ¿Cuánto cuesta?

C. Merge Sort no inspecciona los datos antes de dividir: hace las mismas llamadas y las mismas fusiones siempre (cada merge hará menos comparaciones, pero copia los n elementos igual). Esa regularidad es su virtud — peor caso garantizado — y su costo: no aprovecha entradas fáciles, que es exactamente lo que Insertion sí hace.
La cota inferior

Ω(n log n): hasta aquí se puede llegar

Argumento del árbol de decisión:

  • Cada ejecución es un camino en un árbol binario: cada nodo es una comparación y cada hoja una permutación de la entrada.
  • El árbol necesita al menos n! hojas — cualquier permutación puede ser la entrada y cada una exige una secuencia distinta de movimientos.
  • Un árbol binario con n! hojas tiene altura ≥ log₂(n!) = Θ(n log n) (por la aproximación de Stirling).
  • La altura es el peor caso en comparaciones: ningún algoritmo por comparación baja de Ω(n log n). Merge Sort es asintóticamente óptimo.
Checkpoint

Radix Sort ordena enteros en O(n·k). ¿Contradice la cota Ω(n log n) que acabamos de demostrar?

B. La demostración cuenta hojas de un árbol de comparaciones; un algoritmo que extrae información de otra forma (dígitos, cubetas) no vive en ese árbol y la cota no lo restringe. La opción C no es cierta en general (con k constante, O(n·k) = O(n)). La lección: toda cota inferior tiene un modelo de cómputo en letra chica, y hay que leerla.

Por qué importa hoy

merge corre en producción millones de veces al día

  • Una base vectorial grande reparte sus datos en fragmentos, cada uno con su propio índice.
  • Ante una consulta, cada fragmento devuelve sus mejores k candidatos ya ordenados por puntaje.
  • Alguien tiene que combinar esas listas ordenadas en una sola respuesta: eso es exactamente merge — los mismos dos punteros eligiendo el mejor, generalizados a k listas.
  • Cada consulta de un sistema RAG sobre un índice distribuido ejecuta esta fusión. El paso "combinar" de hoy es la operación central de la recuperación a escala.
