R5 · Punto de partida

Una función que devuelve un número inventado


int clasificar(int cal) {
    if (cal >= 90) return 4;
    else if (cal >= 80) return 3;
    else if (cal >= 70) return 2;
    // si cal es menor que 70 no hay return
}
int main() { std::cout << clasificar(55) << '\n'; }
      

$ ./clasificar
55

Imprimió 55, el argumento que se le pasó: leyó lo que quedaba donde esperaba el resultado. Con -O2 el número sería otro.

R5 · Declaración y definición

Prometer que existe, y entregarla


double area(double base, double altura);   // declaración

int main() {
    std::cout << area(3.0, 4.0) << '\n';   // 6
}

double area(double base, double altura) {  // definición
    return base * altura / 2.0;
}
  • La declaración da el nombre, los tipos de los parámetros y el tipo de retorno. Con eso el compilador ya puede verificar cada llamada.
  • La definición agrega el cuerpo; puede estar en otro archivo, como en R0.
  • Sin la declaración previa, el compilador no conoce ese nombre y falla ahí.
R5 · Parámetros

El parámetro es una copia


void duplicar(int n) { n = n * 2; }
int main() {
    int x = 5;
    duplicar(x);
    std::cout << x << '\n';      // 5, no 10
}
  • Al llamar, el valor de x se copia en el parámetro n. Son dos variables distintas y n deja de existir al terminar la función.
  • Los nombres del argumento y del parámetro no tienen relación: llamar n a los dos no los conecta.
  • Para modificar el original hay que pasar por referencia o puntero (R8).
Checkpoint

Declaras int suma(int a, int b); arriba del main y nunca escribes su cuerpo, pero sí la llamas. ¿Qué ocurre?

C. El compilador solo verifica que la llamada coincida con la declaración, y coincide. El cuerpo lo busca el enlazador entre todos los .o, y al no encontrarlo emite undefined reference, el error de R0. No hay error en la llamada (A) ni un cuerpo por omisión (B): declarar es prometer, definir es entregar.
R5 · Valor de retorno

Qué devuelve y qué hace return

  • return expr; termina la función de inmediato y entrega el valor al punto de llamada. Lo que venga después no se ejecuta.
  • El valor se convierte al tipo declarado. Una función int que hace return 2.7; devuelve 2, en silencio.
  • Una función void no devuelve nada. Admite return; a secas para salir antes de tiempo.

void avisar(int n) {
    if (n < 0) return;                 // salida temprana
    std::cout << "valor: " << n << '\n';
}
R5 · Valor de retorno

Todos los caminos tienen que retornar


$ g++ -std=c++17 -Wall -Wextra clasificar.cpp -o clasificar
clasificar.cpp:8:1: warning: control reaches end of
non-void function [-Wreturn-type]
  • Salir de una función con retorno declarado sin ejecutar un return es comportamiento indefinido: sigue con lo que haya en el registro de retorno.
  • Es una advertencia: sin -Wall no aparece nada.
  • Se corrige cambiando el último else if por un else, o con un return 1; al final.
Si -Wall dice control reaches end of non-void function, hay una entrada para la que tu función devuelve basura.
Checkpoint

¿Cuál de estas funciones dispara -Wreturn-type?

A. Cuando n es impar la función llega al final sin retornar, y eso es comportamiento indefinido: el compilador deja de garantizar qué hace el programa completo. Sin optimización suele devolver un valor cualquiera; con -O2 el programa puede colgarse o saltarse el código que sigue. B es void: no debe devolver nada y return; es una salida temprana válida. C es la excepción del lenguaje que ya vimos en R2: main puede omitir el return y el compilador supone return 0;.
R5 · Alcance

Cada función tiene sus propias variables


int contador = 0;              // global
void registrar() {
    int contador = 100;        // oculta a la global
    contador++;
    std::cout << "local: " << contador << '\n';   // 101
}
int main() {
    registrar();
    std::cout << "global: " << contador << '\n';  // 0
}
  • Una local nace al entrar a la función y muere al salir; nadie más la ve.
  • Un nombre declarado dentro oculta al de fuera, y el compilador no lo señala.
  • Las globales dejan que cualquier función modifique el estado sin que se note en la firma. Mejor pasa el dato como parámetro.
Checkpoint

Dentro de una función escribes int total = 0; y dentro de un for de esa misma función, int total = 5;. ¿Qué pasa?

B. Cada bloque { } abre un alcance nuevo y una declaración en el interior oculta a la exterior mientras dure ese bloque. Al cerrar el for, total vuelve a ser la de afuera con su valor intacto. No hay conflicto (A) porque están en alcances distintos, y no comparten almacenamiento (C). Es la fuente de errores más difícil de ver al leer código ajeno.
R5 · Sobrecarga

Un nombre, varias listas de parámetros


int mayor(int a, int b) { return a > b ? a : b; }
double mayor(double a, double b) { return a > b ? a : b; }
std::string mayor(const std::string& a,
                  const std::string& b) {
    return a.size() >= b.size() ? a : b;
}
mayor(3, 9);        // la de int    -> 9
mayor(2.5, 1.5);    // la de double -> 2.5
  • La sobrecarga permite reutilizar un nombre cuando la operación es conceptualmente la misma sobre tipos distintos.
  • El compilador elige al compilar, según los tipos de los argumentos. En el ejecutable son tres funciones separadas, con nombres internos distintos.

Qué distingue a dos sobrecargas

Diferencia¿Sirve para distinguirlas?

Tipo de retornoNo

int f(int a);
double f(int a);   // error: ambiguating new declaration

La firma no incluye el retorno: en f(1); nada diría cuál llamar. Si dos candidatas empatan, el error es call of overloaded … is ambiguous.

Checkpoint

Existen void f(int); y void f(double);. Llamas f('a');. ¿Cuál se ejecuta?

B. Sin coincidencia exacta, el compilador ordena las conversiones posibles por preferencia. La promoción de char a int tiene mayor prioridad que la conversión de char a double, así que gana f(int) sin ambigüedad. No hace falta una sobrecarga por cada tipo (A), y las dos candidatas no están empatadas (C).
R5 · Argumentos por omisión

Valores que el llamador puede no escribir


void saludar(const std::string& n, int veces = 1,
             char sep = '\n') {
    for (int i = 0; i < veces; i++)
        std::cout << "Hola " << n << sep;
}
saludar("Ana");             // 1 vez, salto de línea
saludar("Luis", 3);         // 3 veces
saludar("Sam", 2, ' ');     // 2 veces, separadas por espacio
  • Van al final: tras uno con valor por omisión, todos deben tenerlo.
  • Se escriben en la declaración; con .h y .cpp (R11), en la cabecera.
  • Con void f(int, int = 0); y void f(int);, f(5) es ambigua.
R5 · Trampas comunes

Cuatro descuidos que el binario no perdona

  • No retornar en todos los caminos. Solo -Wall lo dice, y el valor devuelto cambia entre compiladores y niveles de optimización.
  • Esperar que el parámetro modifique al argumento. El paso por valor copia; hace falta una referencia (R8).
  • Repetir el valor por omisión en la declaración y en la definición. El compilador lo rechaza como redefinición.
  • Intentar sobrecargar cambiando solo el tipo de retorno. El error habla de ambiguating new declaration y no menciona la palabra sobrecarga.

Sobrecargar es dar varios significados a un nombre según los tipos. En R14 esa idea se aplica a los operadores, y en R16 se contrasta con la sobreescritura, que es otra cosa.

R5 · Ejercicio

Parte este main en funciones


int main() {
    double notas[3], suma = 0;
    for (int i = 0; i < 3; i++) {
        std::cout << "Nota " << i + 1 << ": ";
        std::cin >> notas[i];
        suma += notas[i];
    }
    double prom = suma / 3;
    std::cout << "Promedio: " << prom << '\n';
    if (prom >= 70) std::cout << "Aprobado\n";
    else            std::cout << "Reprobado\n";
}

Extrae tres funciones: pedir las notas, calcular el promedio y decidir si aprueba.

R5 · Ejercicio

Las tres funciones que salen del main


void pedirNotas(double n[], int cuantas) {
    for (int i = 0; i < cuantas; i++) {
        std::cout << "Nota " << i + 1 << ": ";
        std::cin >> n[i];
    }
}
double promedio(const double n[], int cuantas) {
    double s = 0;
    for (int i = 0; i < cuantas; i++) s += n[i];
    return s / cuantas;
}
bool aprobado(double prom) { return prom >= 70.0; }

promedio y aprobado no imprimen nada, así que pueden probarse con valores fijos sin teclear. El parámetro cuantas viaja aparte porque el arreglo pierde su tamaño al pasarse a una función, lo que se explica en R8.
